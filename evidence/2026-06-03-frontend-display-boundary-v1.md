## 已确认的核心显示边界

- 左侧一级入口：项目、智能体、画布、记忆、知识库、设置。
- `模型与 Agent` 不作为当前一级入口；相关状态放在智能体、设置或管理详情里。
- 右侧固定入口：秘书、通知、待办、运行中、管理。
- 审计和日志放入管理，不作为右侧散开的顶级入口。
- 秘书是独立半身悬浮标，不是工作台底部常驻聊天框；打开后主体显示最近聊天内容。
- 记忆是能看懂的记忆中心，不是治理后台。
- 知识库是资料和笔记空间，偏 Obsidian / vault / 文档管理，不直接等同于记忆层。
- 项目页按工作流 / 智能体 / 文档 / 记忆 / 设置切换，各 tab 只显示自己该显示的内容。
- 智能体页是会话中心，命名为智能体；中间版本最终必须支持发消息继续会话。
- 一级画布默认打开可编辑无限画布，可以切到画布库和工作流总览；项目画布和一级画布复用同一画布模块，但上下文、数据归属和执行权限不同。
- 权限、错误、证据和开发者模式都必须用人话分层显示，普通 UI 不直接铺 schema、raw event、traceback、adapter 细节、日志或 evidence 路径。

## 风险和边界

- 本文档范围超过中间版本，不能把全部内容解释为当前开发任务。
- 后续 UI 任务必须先拆成最终产品边界、中间版本必须落地、后端和数据依赖、后置能力。
- 需要后端读模型支撑的内容不能靠前端假数据冒充。
- 秘书、画布、记忆中心和知识库都不能绕过控制核心、权限、审计和正式记忆状态机。
