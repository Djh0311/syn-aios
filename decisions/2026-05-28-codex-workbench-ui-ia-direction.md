# Codex 工作台 UI 与信息架构方向决策

## 结论

当前产品不是索引浏览器，目标应调整为 Codex 工作台。

第一屏必须是首页总览，只放四个主入口：

- Agent
- 项目
- Skill 管理
- Harness 管理

每个入口下方显示最近打开或最近使用，不显示数量。

项目打开后进入项目级可视化工作流。工作流要以可视化、生动的流转为主，不以普通列表或静态看板为主。

当前只编排 Codex。其他 agent 入口可以空白显示，但不做假接入。

## 依据

- 用户明确指出当前 UI 没有做到看板功能，仍然混乱。
- 用户明确要求当前只编排 Codex，先把 Codex 做好做完善。
- 用户确认第一屏必须是首页总览，且第一屏只有入口。
- 用户确认入口暂定为 Agent、项目、Skill 管理、Harness 管理。
- 用户确认入口下方显示最近打开或最近使用，不显示数量。
- 用户确认项目打开后是编排工作流，左侧有窄功能列表快捷切换。
- 用户确认希望项目工作流是可视化、生动的工作流。
- 用户确认没接入、没做的 agent 空白显示。
- 用户确认 Skill 的删除、编辑、选择 agent 加载可以后置。
- 用户确认 Harness 后续要支持多个仓库和多个版本来源。

## 先说薄弱点

- 当前产品化桌面壳一期仍是索引浏览壳，不是最终信息架构。它可作为技术底座，不能作为 UI 方向继续小修。
- 旧的权限弹窗离线交互测试价值下降。它可以验证旧 UI 的一个局部，但不能解决首页入口和项目级工作流混乱的问题。
- “Agent”入口未来会承载 Codex、OpenClaw、VS Code、OpenCode、Claude Code 等，但当前不能假装这些都已接入。
- Skill 删除、编辑、选择 agent 加载属于写入和配置能力，当前阶段不应直接做真实写入。
- Harness 多仓库、多版本来源需要数据模型，当前先预留，不直接实现完整仓库管理。

## 首页方向

首页只做入口，不做复杂信息流。

四个入口：

- Agent：进入 agent 接入与状态页。
- 项目：进入项目列表和项目工作流。
- Skill 管理：进入 skill 分类、适配关系和使用状态。
- Harness 管理：进入 harness 框架、版本、场景和项目使用关系。

入口下方显示最近打开或最近使用，例如：

- Agent：最近使用 Codex。
- 项目：最近打开的项目。
- Skill 管理：最近查看或使用的 skill。
- Harness 管理：最近查看或使用的 harness。

首页不显示数量。

## Agent 页方向

当前只做 Codex。

未接入或未实现的 agent 空白显示，不显示假能力。

未来可能出现的 agent：

- Codex
- OpenClaw
- VS Code
- OpenCode
- Claude Code

这些 agent 是否可编排，必须依赖稳定 CLI、SDK、headless 入口或官方支撑。不能靠操控第三方 IDE 扩展 UI 作为主方案。

## 项目页方向

项目页是当前阶段的主战场。

项目列表进入某个项目后，默认展示项目级可视化编排工作流。

项目内左侧窄功能列表建议包含：

- 工作流
- 会话
- 任务包
- Evidence / Handoff
- Skills
- Harness
- 设置

工作流视图应表达：

- Director 如何拆解任务。
- 任务包派给哪个 Codex 会话。
- Specialist 会话当前状态。
- Handoff / evidence 回到哪里。
- 总指导是否接受、退回、暂停或需要用户输入。

工作流不是普通索引列表。列表只能作为辅助视图。

## Skill 页方向

Skill 页需要清晰看板，不是简单目录树。

需要展示：

- Skill 分类。
- 当前被哪个 agent 使用。
- 可以被哪个 agent 使用。
- 当前哪些项目使用。
- 哪些项目可推荐。
- 是否已加载。
- 风险或缺失说明。

删除、编辑、选择 agent 加载后置。当前阶段可先做展示、分类和关系建模。

## Harness 页方向

Harness 页需要清晰看板。

需要展示：

- Harness 框架。
- 版本。
- 来源。
- 使用场景。
- 功能说明。
- 适用项目。
- 关联命令或验证入口。
- 最近验证状态。
- 风险或缺失配置。

未来要支持多个仓库和多个版本来源。当前先预留模型和 UI 位置，不直接实现完整仓库管理。

## 看板与画布关系

项目内工作流应以画布优先。

原因：

- 多会话编排需要表达关系、流向和依赖。
- Director、任务包、specialist 会话、handoff、review 之间不是单纯状态列。
- 用户明确需要可视化、生动的工作流。

看板仍有价值，但作为辅助视图：

- 用来按状态筛选任务。
- 用来批量查看待派发、执行中、待回收、已接受、需修改、暂停。

建议项目内默认布局：

- 左侧窄功能列表。
- 中间可视化工作流画布。
- 右侧详情面板，显示节点详情、任务包、handoff、evidence、回收意见。

## 当前阶段边界

当前只做 Codex。

当前不做：

- 多 agent 接入。
- OpenClaw / VS Code / OpenCode / Claude Code 编排。
- 个人知识库正文入库。
- 向量搜索。
- 模型辅助调度。
- 复杂跨 agent 画布。
- 真实删除或改写 skills。
- 完整 harness 多仓库管理。
- 写 Codex 内部状态库。

## 对现有产物的处理

`product-line/prototypes/productized-desktop-shell/` 保留为 Tauri 技术底座。

现有首页、项目页、会话页、Skills / Plugins 页、任务线页、诊断页不能作为最终 UI 方向继续扩展。

下一步应由信息架构线重做：

- 首页四入口。
- Agent 页空白与 Codex 可用状态。
- 项目列表与项目详情。
- 项目内可视化工作流。
- Skill 管理看板。
- Harness 管理看板。

桌面应用线等信息架构回收后再实现。
