# 决策：记忆自发捕获、每日整理与 Skill 治理修订 v1

日期：2026-08-01<br>
状态：**用户已拍板；记忆产品方向修订。**<br>
性质：覆盖旧正本中“普通聊天一律不捕获、所有正式记忆逐条人工确认、自动技能化一律 deferred”的默认口径；保留来源、作用域、敏感性、版本、冲突、外发和审计治理。

## 1. 一句话

**秘书和记忆层可以像长期个人助理一样自发观察、捕获和整理，但任何进入长期行为上下文的内容都必须经过记忆治理；系统推断、敏感信息、权限和外部行动永远不能靠自动学习悄悄升级。**

## 2. 新的记忆链

```text
对话 / 项目结果 / 用户纠正 / 外部数据摘要 / 日常事件
  → CaptureEvent
  → Observation
  → MemoryCandidate
  → 策略治理与冲突检查
  → FormalMemoryVersion（符合自动策略）
     或 NeedsUserDecision（需要用户确认）
     或 Rejected / Quarantined
```

- 捕获、Observation 和 Candidate 可以由秘书 / 记忆机制自发创建，不要求用户先说“记住”。
- 不是每条聊天都捕获；捕获器必须判断是否稳定、是否会影响未来协作、是否已有来源、是否重复、是否过期、是否敏感。
- 普通低风险记忆在满足明确策略时，可以自动创建或更新正式版本；“自动”是治理规则的结果，不是 LLM 直接写表。
- 需要用户决定的内容进入聚合待决策，不因用户暂未处理而冒充正式事实。

## 3. 必须保留的治理维度

每条 Observation、Candidate 和 FormalMemory 至少保留：

- source ref 与捕获时间；
- personal / global / project 等作用域；
- 用户明确事实、系统观察、系统推断的类型区分；
- confidence、有效期 / 新鲜度和冲突关系；
- sensitive level 与 model export policy；
- 版本、状态历史、创建 / 修改原因和审计；
- 哪些角色、项目、模型和外部系统可以读取。

修改正式记忆必须创建新版本，不能静默覆盖。用户能查看、纠正、冻结、废弃、合并、拆分和删除可删除的数据；依法或为审计必须保留的事件按对应制度处理。

## 4. 自动与必须确认的边界

### 4.1 可以在策略允许时自动沉淀

- 用户反复明确表达且无冲突的低风险偏好；
- 用户对助手解释方式、工作习惯和协作方式的纠正；
- 有直接来源、低敏感、可撤销的个人协作事实；
- 已经由项目真源确认、只作为受限摘要引用的项目结果；
- 经过重复证据验证的内部方法模式。

### 4.2 只能作为候选或请求用户决定

- LLM 推断出的身份、关系、因果、偏好或意图；
- 与现有记忆冲突、来源不明、置信度低或已过期的内容；
- 会改变项目目标、优先级、验收或外部承诺的内容；
- 可能影响多个项目或长期全局制度的高影响规则；
- 用户明确要求不要保存、只在当前对话使用或稍后再决定的内容。

### 4.3 永远不能因自动学习获得或改变

- 密钥、token、OAuth、密码、恢复码和完整敏感原文；
- 系统权限、工具 allowlist、沙箱、写根、自动批准和外部操作授权；
- 用户身份权威、法律 / 财务 / 医疗等高影响结论；
- 向外部发送、发布、购买、交易或改变状态的许可；
- 项目正式事实和审计历史的真源。

## 5. 每日定时整理

每日定时事件可以整理：

- 当日角色会话和用户纠正；
- 项目交付、失败、决策和未闭环摘要；
- 个人范围内的承诺、变化和重复模式；
- 新建 / 修改 / 冲突 / 失效的记忆；
- 可能沉淀为稳定方法的重复做法。

整理结果分开结算：

- 日报：给用户看的当日事实与延续摘要；
- MemoryCandidate / FormalMemoryVersion：会影响未来协作的长期内容；
- SkillCandidate / SkillDraft：可复用方法；
- AuditEvent：发生过什么以及为何自动处理；
- DecisionRequest：需要用户确认的冲突或高影响内容。

`daily loop` 不是“把所有聊天总结一遍”，也不能把日报自动当正式记忆。

## 6. Skill 治理

- 日常整理可以自动生成 `SkillCandidate` / `SkillDraft`。
- 只有输入、输出、适用范围、反例、版本、依赖、权限和验证都明确后，候选才可以登记为正式 skill。
- 普通内部、无外部副作用的方法可以在满足重复证据和验证门后按策略启用；具体门槛在实施合同中冻结。
- 涉及外部操作、敏感数据、凭据、写入、发布、购买、交易、权限扩张或安全闸的 skill，永远不能因为重复成功自动取得新权限；它每次运行仍受原权限和确认合同约束。
- skill 更新必须可回滚；旧版本和采用理由保留审计。

## 7. 与旧正本和当前实现的关系

- 覆盖 `docs/memory-layer-consolidated-canon-v1.md` §3、§6.1、§7 中“普通聊天不自动捕获”“用户确认门不可裁”“auto-skillification 全部 deferred”的产品默认。
- 覆盖 `docs/memory-layer-design-v1.md` 中与上述三点冲突的产品结论；其七层模型、来源、版本、作用域、敏感性、冲突、权威 / 索引分离和生命周期设计继续有效。
- 不改变“子智能体不能直接写正式记忆”“知识库命中不是记忆”“向量 / 图索引不是权威事实”“正式记忆不可静默覆盖”。
- **当前代码仍主要实现 Candidate 经用户确认后转 FormalMemory，且普通聊天尚未接入这条链。** 本决策定义目标，不把现有实现写成已经具备自动治理能力。

## 8. 实施前必须冻结

- 自动沉淀策略矩阵和风险等级；
- 冲突、过期、撤回和用户纠正的状态机；
- 每日整理的输入范围、预算、幂等键、失败恢复和保留期限；
- SkillCandidate 的重复证据、验证、启用、权限和回滚门；
- 敏感内容检测、脱敏、禁止落盘和模型外发策略；
- 用户查看、纠正、关闭自动学习和批量撤销的产品入口。

未冻结这些合同前，不得用一个“自动总结并写记忆”的 prompt 代替治理实现。
