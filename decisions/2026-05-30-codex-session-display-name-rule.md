# 决策：Codex 会话展示名规则

## 结论

Codex 原本会话名保留为基础展示名。

在工作流或项目团队工作区里，不直接用原会话名替代角色和状态，而是叠加显示：

- 角色 / 工作线
- 原 Codex 会话名
- 当前状态
- 必要时补充时间、项目路径、最近消息摘要

## 展示规则

### 全局会话列表

主标题：

- Codex 原本会话名。

辅助信息：

- 项目归属。
- 最近更新时间。
- 是否已绑定项目 / 工作流节点。
- 可读状态。

### 项目工作区 / 工作流节点

主标题：

- 角色或工作线，例如：总指导、开发线、验证线、回收线。

副标题：

- Codex 原本会话名。

状态信息：

- 空闲、运行中、待权限、失败、待回收、已回收等工作流状态。

示例：

- `开发线 · 原 Codex 会话名`
- `验证线 · 原 Codex 会话名`
- `总指导 · 原 Codex 会话名`

### 原会话名不足时

如果原会话名为空、重复、太泛或无法辨认，可以显示补充信息：

- 创建或更新时间。
- 项目路径。
- 最近一条用户消息摘要。
- 绑定来源：用户绑定、工作流绑定、索引推断。

这些补充信息只用于展示，不反写 Codex 原始会话。

## 依据

- 用户确认“原 Codex 会话名保留做基础展示名，工作流里叠加角色和状态”这一规则可行。
- `decisions/2026-05-29-codex-agent-session-center-project-binding-v1.md` 已要求全局 Agent 页面、项目 Agent 会话入口、工作流节点复用同一套 Codex 会话服务。
- `evidence/2026-05-29-reference-workflow-session-node-research-v1.md` 的 AionUi 研究结论是：会话可以作为可见工作单元，但工作流状态要作为底层账本。

## 不做

- 不直接改 Codex 原始会话名。
- 不把角色名写回 Codex 内部状态库。
- 不用聊天标题替代工作流状态。
- 不只靠会话名判断任务进度、权限、失败或回收状态。

## 风险

- 只显示原会话名会看不出工作流职责。
- 只显示角色名会丢失 Codex 原始上下文。
- 自动摘要可能不准，所以只能作为辅助展示，不能当用户确认事实。
