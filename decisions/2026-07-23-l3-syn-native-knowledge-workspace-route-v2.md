## 1. 决策

L3 第二片继续由 Syn 自己实现和维护，不嵌入、控制或迁移 Obsidian。2026-07-25 起，知识库界面目标改为：

> 在 Syn 原生技术与安全边界内，高保真复刻 Obsidian 核心桌面工作区的信息架构、空间比例、面板组织、标签页模型和高频交互；同时保留 Syn 自有品牌、开放文件真相源、确认式写入与主管只读能力。

“高保真复刻”在本决策中指：

- 核心桌面壳的结构、层级、密度、比例和工作方式按冻结参考逐项对齐；
- 左侧活动栏/文件与搜索侧栏、中间标签页工作区、右侧上下文侧栏、底部状态区形成一个固定高度工作台；
- 编辑、预览、Graph、Canvas 在中间工作区切换，不得作为多个全宽容器纵向堆叠；
- 快速打开、命令面板、折叠/展开、拖拽分栏、焦点和键盘路径按核心日用合同对齐；
- 颜色、字体、产品名、图标和确认式 AI 动作使用 Syn 自有设计系统，不复制 Obsidian 商标、品牌图形或受限资产。

知识工作区发生规范冲突时，冻结的 Obsidian 参考决定空间结构、比例和工作方式；Syn 设计简报决定颜色、字体、品牌、语义状态和其他页面的一致性。

## 2. 产品目标

用户在 Syn 内可以完成一条不依赖 Obsidian 的日用闭环：

1. 浏览、搜索和组织知识文件；
2. 创建、编辑、预览 Markdown；
3. 使用 `[[双链]]`、反向链接、标签和属性组织知识；
4. 通过快速打开和命令面板定位与执行高频动作；
5. 查看局部/全局关系图；
6. 创建和编辑兼容 JSON Canvas 1.0 的画布；
7. 管理受限附件；
8. 在标签页、分栏和侧栏之间切换并恢复工作区；
9. 让主管通过统一 capability plane 只读搜索、读取、打开和引用；
10. AI 写入继续经过提议、用户确认、固定 vault、冲突检查和 Batch 2 audit。

## 3. 界面合同

### 3.1 设计意图

- 使用者：长时间整理、检索、编辑和关联知识的桌面用户。
- 核心动作：在文件、笔记、链接关系和画布之间快速切换，持续写作而不离开上下文。
- 体验：安静、紧凑、连续、工具化；内容工作区是唯一视觉焦点。
- Syn 签名：确认式 AI 写入、审计状态和主管引用进入既有上下文区或临时浮层，不另建第二套知识仪表盘。

### 3.2 单壳结构

主知识库视图必须只有一个工作台根：

1. 最左活动栏：知识功能入口及必要的 Syn 动作；
2. 左侧栏：文件、搜索、标签等互斥视图；
3. 中间工作区：标签页、Markdown 编辑/预览、Graph、Canvas；
4. 右侧栏：属性、反链、标签、大纲和当前上下文；
5. 底部状态区：当前文件、模式、保存/冲突等低层级状态。

应用壳固定在可用窗口高度内。页面本身不得因知识模块纵向堆叠而滚动；文件树、编辑区和侧栏各自内部滚动。

### 3.3 必须退场的旧结构

- 新原生工作台下面继续渲染旧统计条、旧三栏知识面板或 `KnowledgeVaultNotesPanel`；
- Graph、Canvas、维护面板分别作为全宽大容器追加在编辑工作台下方；
- 同屏出现两个或更多彼此竞争的知识主容器；
- 用卡片仪表盘替代连续桌面工作区；
- 为复刻外观引入无键盘语义的自制控件或破坏现有可访问性。

旧能力若仍需保留，必须迁入左/右侧栏、命令面板、设置页或按需抽屉；不得继续占据第二主层级。

### 3.4 参考冻结

实施前先冻结一套可复核参考：

- Obsidian 桌面版本、默认主题与明暗模式；
- 主窗口尺寸与系统缩放；
- 文件树、编辑、预览、搜索、反链、Graph、Canvas 的基准截图；
- 关键尺寸、栏宽、密度、分隔、标签页与状态区对照表；
- Syn 品牌替换清单和不复制资产清单。

参考未冻结前，只能做现状审计和结构拆解，不能宣称“1:1”或“高保真完成”。

## 4. 数据与兼容边界

### 保留

- Syn 自管 vault 是唯一知识文件根。
- Markdown 文件继续是笔记真相源。
- Frontmatter 使用普通 YAML 文本表达，只解析已声明的安全字段。
- Canvas 采用开放的 JSON Canvas 1.0 `.canvas` 文件。
- 附件使用 vault 内受限目录和允许类型，不创建第二套资源数据库。
- 官方 Obsidian CLI/URI bridge 仅作可选互操作层；未安装 Obsidian时 Syn 核心功能仍可用。

### 不承诺

- Obsidian 社区插件或主题兼容；
- Obsidian 私有 API、命令 ID、内部缓存和工作区文件兼容；
- Obsidian 商标、品牌图形、原始图标包或受限资产复制；
- Sync、Publish、移动端和插件市场；
- 任意第三方 vault 无损导入。

## 5. 从既有实现保留与改造的资产

### 直接保留

- `knowledge_vault.rs` 的固定根、路径锁、创建/读取/写入、冲突拒绝和 Batch 2 audit；
- 已有 Markdown、目录、搜索、wikilink、backlink、Graph、Canvas、附件和恢复能力；
- `knowledge_search/read/open/cite` 及现有 registry、role allowlist、可信 binding 双闸；
- typed Obsidian bridge 的安全测试、固定 argv、超时、输出上限和错误收口。

### 改造

- `KnowledgeBaseView` 收敛为唯一单壳入口；
- Graph 和 Canvas 进入中间标签页/工作模式；
- 属性、反链、标签和大纲进入右侧上下文栏；
- 搜索、文件和标签进入左侧栏；
- 旧统计、记忆捕获、维护与兼容状态降级为按需区域；
- `knowledge_open` 默认打开 Syn 原生标签页，仅在用户显式选择时交给官方 Obsidian。

### 继续停止

- 强制安装 Obsidian、CLI 注册和以 Obsidian 为前置的阶段门；
- Accessibility 受管伴随窗口、窗口贴合和截图流；
- “用 Obsidian 反向承载 Syn”；
- Electron 迁移、`app.asar`、私有 API、伪嵌入、解包、改签或逆向。

## 6. 架构与安全约束

- 前端不得直接访问任意文件路径；文件、Canvas、附件和搜索均走 typed host command。
- 所有相对路径必须规范化并拒绝绝对路径、父级穿越、符号链接和大小写漂移。
- Markdown、Canvas 与附件写入必须有 stale revision/mtime/hash 冲突检测。
- 搜索索引和链接图是可重建投影，不是第二真相源。
- MCP 只读能力不得获得知识写、Canvas 写或附件写。
- 不因界面复刻放宽主管 `read-only + 空写根`、conversation binding、服务端 allowlist、sandbox 或 runtime profile。
- 不在本阶段改变 M5 schema、DB-primary bridge、CAS 或正式记忆模型。

## 7. 验收口径

### 7.1 界面门

必须先证明：

1. 知识库只有一个固定高度工作台；
2. 旧统计条、旧三栏和旧 Vault Notes 不再形成第二主容器；
3. Graph、Canvas、编辑与预览在同一中间工作区切换；
4. 左、中、右区域只有内部滚动，主页面无堆叠式纵向滚动；
5. 基准窗口下的结构、比例、密度、标签页和侧栏行为与冻结参考逐项对照；
6. 键盘焦点、折叠、空态、加载、错误和冲突态有明确表现；
7. Syn 品牌替换和不复制资产清单均满足。

### 7.2 功能门

界面门通过后，仍须由真实 Syn App 在不安装 Obsidian的情况下完成“创建→编辑→链接→反链→搜索→图谱→Canvas→附件→重启恢复→冲突拒绝→主管只读引用”的代表性闭环，才能宣布本阶段完成。

官方 Obsidian 能打开同一 Markdown/Canvas 文件只属于兼容加分项。
