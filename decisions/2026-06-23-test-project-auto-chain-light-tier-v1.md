## 为什么
- 测试项目是专用开发靶子 (git 仓、可回滚、非真实/生产仓)，随便读写无真实不可逆损害。
- 2026-06-22 已下放「单节点真跑」为轻档；自动连环 = 把单节点真跑重复 N 次，目标仍锁死测试项目、沙箱不外溢——单次的损害边界没变 (都在可回滚的靶子里)。
- 真正多出来的风险只有一个：无人值守地连跑可能「跑飞」(超出预期的节点数/迭代)。→ 用下面四条硬护栏兜住，而非靠逐步审批。

## 精确边界 (轻档成立前提，必须硬；任一松 → 立刻回高危#4)
1. **path-lock 不动**：链每节点的真跑目标仍锁死该固定测试项目。
2. **沙箱不外溢**：codex 仍关在测试目录 (workspace-write + add-dir 限定)。
3. **【链式特有·删了逐步闸后仅剩的安全，四条必须全在】**
   - ① **runaway 上限**：单链最多派发节点数 = min(图节点数, 硬顶 50)；拓扑序、每节点最多跑一次 (P1 无环/无 loop)；失败即停、不自动重试；沿用现有 codex 单跑超时。跑满强制停。
   - ② **可中断**：用户随时停链。
   - ③ **审计**：每节点派发记审计事件 (链起/每节点 start·done·fail/链停)。
   - ④ **可回滚**：依赖测试项目 git + 写前备份。
4. 链每节点真派发，必须走现有 gated `execute_project_workflow_node` (双闸+沙箱+临时 work_item)，不旁路、不新开闸、`codex_local_runner` / 安全闸 / codex审批 / `manual_relay` 字节不动 (高危#3 不动)。

## 没松的
- 自动连环进任何「非测试真实项目」(用户实际仓/生产) = 仍高危#1+#4、仍锁。
- **多项目接力** = 仍锁 (高危#4 的另一半)。
- auto-approve「乙」全量 (生产档护栏 + 放开非测试项目) = 仍是终局/④c；本决策只下放『圈在测试项目的自动连环』，不等于已开乙全量。

## 实现含义
- 新增件：链驱动 controller + per-node 链状态进 workflow-state + 四条硬护栏；不碰安全闸/沙箱/codex审批/manual_relay。
- 失败处理 = 链停 + 用户定 (不自动重试/跳过，防在老失败节点上打转)。
- 中断恢复 = 断点续：已完成节点跳过、被中断的半截节点重跑、从它往下接。
