## 为什么
- 用户痛点：现角色循环手点 7 步太繁琐；**用户要的是自动化**。
- **自动化某种程度上就是更好的「可用」**（7 步 → 2~3 步），所以"跳过 S2 手动打磨、直接上自动"有产品道理。
- 计划本就允许「阶段是路线、非死序，用户可随时调整顺序与取舍」（master-roadmap §4）。
- 自动化的是「造计划 + 执行」的体力；**方案授权那道人闸不动**——不是放开审批，是省手动劳动。

## 精确边界（轻档成立前提，任一松 → 立刻回高危）
1. **方案授权这道人闸不省**（principles §4「LM 不得绕过权限确认执行」+ 中间版 §0.3「方案授权制·用户确认方案=确认一段自动执行范围」）。auto-advance 的**前提 = active 授权已存在**；它只在授权**之后、范围内**自动推进，**不碰授权本身**。
2. **圈固定测试项目**（高危#1 轻档·path-lock 锁死 `/Users/yoyi/codex-workflow-mario-test`）；**非测试真实项目仍锁死**。
3. **四护栏在**（auto-chain 决策 `2026-06-23-test-project-auto-chain-light-tier-v1.md`）：runaway 上限 / 可中断 / 审计 / 可回滚。
4. **超授权范围 → 必停下确认**；任一步失败 → 停 + 可见 + 等用户定（中间版 §156/§161/§3）。
5. **0-diff**：S1 闸 `decide_real_execution_command` / `command_plan_for` 沙箱 / `execute_project_workflow_node_at` / `prepare` / `run_director_task_chain` 本体**不改逻辑**——只新增「编排串起来」命令 + 接咨询命令（复用现成）。
6. **全局主管复核（方案边界 / 最终结果）先由用户演**（角色）；做成 agent 自动 = 后续，不在本决策。

## 偏离了什么（计划点名的）
- **偏离中间版 §1.3**「❌ 不内置 LLM / 结构化 JSON / 手动派发 / 临时方案」：agent 层用 LM（**经外部 codex·不内置 LLM**）自动编排，替代手动结构化派发。
- **但仍守的**：仍依赖外部 Codex（不内置 LLM，§1.3 那条本质不破）；仍守方案授权（§0.3）；仍经状态机+权限（§4）；仍圈测试项目。
- 即：偏离的是「手动派发」，**不是**「绕权限 / 内置 LLM / 放开非测试」。

## 没松的
- **乙·自动连环**（放开非测试真实项目 + 生产档重护栏 + 真·NL 主对话）= 仍锁、仍终局。本决策只下放「圈测试项目 + 守方案授权」的半自动编排。
- **auto-approve 把「方案授权」也自动** = **永不做**（直接违 §0.3 + §4）。
- **真·NL 主对话「按计划开干」启动**（北极星）= 仍后置。
- **多项目接力 / 非测试真实项目真跑** = 仍高危、仍锁。
