# 决策：停止修补交办模块，按边界旁路重建 v1

日期：2026-08-01<br>
状态：**已停止作为当前路线；只保留来源事实。**<br>
2026-08-01 用户随后明确：前端整体暂时保留，项目主管常驻项目内部；重构重点是提取整个工作台后端模块能力并重新设计协作主干，而不是先旁路重建一个独立项目助手面。因此本文“停止继续修补”仍有效，“按项目助手 / 工作流三个边界立即旁路重建”不再产生当前计划或任务授权。

## 决定

1. **停止继续给现有 `ProjectJiaobanPanel` 叠加行为补丁。** 当前未提交代码原样保留，不 reset、不回滚，也不再拿它当下一阶段的直接施工底座。
2. **按三个边界重建，不做一次性全量重写：**
   - 项目助手：普通项目聊天；首次新建，后续按返回的 `conversation_id/thread_id` 续接。
   - 工作流控制：方案、审批、运行、交货及主管 MCP，只在明确的工作流入口内出现。
   - 旧交办适配层：暂时承接固定测试项目和历史工作流展示；新面通过验收后再逐项退役。
3. **项目分类和权限必须由宿主端掌握。** 前端隐藏输入框不是权限闸。站 3b 不得进入 `workspace-write`；普通项目聊天也不得自动建立 supervisor binding、写 workflow 投影或触发方案/审批/运行。
4. **采用旁路替换。** 新项目助手面不复用旧五态页面状态机；共享的只应是经过冻结的 transport、消息事件和视觉基础件。旧页面作为 legacy adapter 保留到替代验收通过。
5. **验收分层结算。** typecheck、离线测试和 build 只证明离线实现；真实桌面 App 至少要证明首句 `new`、第二句 `existing` 续同一会话、站 3b 不能发送、workflow/DB/JSON 无意外写入，才能称为端到端通过。

## 保留的产品原则

- 对话是自然交流；方案、审批、运行和交货是独立结构化实物。
- 用户点方案卡才构成执行授权。
- transport、工具动作、读模型投影和审计镜像分层结算，任何一层失败不得改写其他层的事实。
- 当前真实 direct adapter 只有 Codex；不宣称其他 agent 已接入。

## 被本决策取代的实现结论

- `ProjectJiaobanPanel` 继续同时承担聊天、五态、方案、工作流、历史、站 3b 和主管试点的做法。
- 把普通项目聊天绑定到 supervisor/workflow 上下文的做法。
- 把 resident/private-home 或 R7 Gate 0 修复线继续当作普通项目聊天的当前路线。
- `docs/plans/2026-07-16-master-execution-plan-conversation-first-v1.md` 作为当前“唯一计划入口”的地位。

旧决策、任务包和 evidence 仍是历史事实，不删除、不回写成“从未发生”。
