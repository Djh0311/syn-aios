# 技术栈与扩展架构决策

## 结论先说

当前产品线仍以治理 Codex 为主。技术栈按“本地 agent 管理工作台”倒推，不按当前原型进度倒推。

阶段 2 / 第一版推荐技术栈：

- 桌面壳：Tauri 2
- 本地核心：Rust
- 前端：React + TypeScript + Vite
- 画布与关系视图：React Flow
- 本地事实库：SQLite
- 本地搜索：SQLite FTS
- 向量库：后置评估，不进入当前阶段

这不是把当前 Tauri 探针包装成最终定案。Tauri 探针只证明了部分可行性：CLI 可用、最小工程可编译、后端可读真实索引、窗口能创建。UI 正文和按钮点击还没有稳定验证。

## 先说薄弱点

- 当前仍没有完整桌面应用验收。依据：`product-line/archive/handoffs/2026-05-27-tauri-min-prototype-after-cli-review.md`。
- React Flow、SQLite FTS、个人知识库还没有原型验证。当前只是架构方向，不是已完成能力。
- “超级工作台”范围很大，不能进入当前阶段。当前阶段仍只治理 Codex。
- Tauri 依赖和构建产物体积大，后续要控制安装、缓存和打包成本。

## 为什么当前阶段仍只做 Codex

依据：

- 用户明确要求阶段目标仍以治理 Codex 为主，其他后面慢慢做。
- 当前已有数据盘点、索引内核、静态壳、Tauri 探针都围绕 Codex。
- 多 agent 接入、个人知识库、模型调度都还没有数据模型和验收标准。

当前阶段目标：

- 把 Codex 本地会话、项目、skills、任务线、handoff、evidence 管起来。
- 做只读治理和低风险本机动作。
- 不写 Codex 状态库。
- 不展示密钥和正文类敏感内容。

## 技术栈分层

### 桌面壳：Tauri 2

职责：

- 本地窗口。
- 受控系统动作。
- 权限边界。
- 前端和 Rust 后端通信。

选择原因：

- 本产品需要打开项目目录、定位日志、复制路径、后续可能管理本地 agent 进程。
- 这些能力不能靠纯网页稳定完成。
- Electron 权限面更大，不作为第一优先路线。

### 本地核心：Rust

职责：

- 扫描本机数据源。
- 维护路径白名单。
- 读取索引和日志元数据。
- 执行本机低风险动作。
- 后续管理本地 agent 进程。

边界：

- 前端不能直接拿任意路径执行系统动作。
- 所有危险能力都必须通过 Rust 命令层。
- 所有写入必须有阶段授权、预览和备份。

### 前端：React + TypeScript + Vite

职责：

- 工作台布局。
- 项目、会话、skills、任务线、验证状态展示。
- 搜索、过滤、详情抽屉、状态面板。
- 后续接画布视图。

选择原因：

- 当前目标不是简单表格页，而是复杂本地工作台。
- TypeScript 有助于约束索引协议和 UI 状态。

### 画布：React Flow

职责：

- 项目关系图。
- agent 状态图。
- 任务流和证据流。
- 后续知识引用图。

边界：

- 画布不是全部界面。
- 日常治理仍需要列表、搜索、详情页、时间线。
- 不把所有功能硬塞进无限画布。

### 数据层：SQLite + FTS

职责：

- 存项目、会话、任务、agent、证据、handoff、事件、索引快照。
- FTS 做本地全文搜索。

边界：

- 当前阶段可以继续用 JSON 索引文件。
- SQLite 是下一步稳定化方向，不要求立刻替换现有索引原型。
- 不在当前阶段做大规模知识库或向量检索。

### 知识库层：后置

后续可以扩展：

- 本地个人知识库。
- 文档解析。
- 全文搜索。
- 引用溯源。
- 摘要和标签。
- 语义搜索和向量索引。

当前不做：

- 不做个人知识库正文入库。
- 不做向量库选型落地。
- 不默认把文档或对话正文送云端。

## 长期扩展方向

长期可以演进为本地超级工作台，但必须分阶段。

长期对象模型建议：

- `source`：数据来源，例如 Codex、项目目录、知识库、其他 agent。
- `entity`：统一对象，例如项目、会话、文件、任务、agent、知识条目。
- `relation`：对象关系，例如属于、引用、派生、阻塞、验证过。
- `event`：状态变化，例如扫描、运行、失败、回收、确认。
- `capability`：可执行能力，例如打开目录、复制路径、启动 agent、生成任务包。
- `permission`：能力的权限边界和用户确认记录。

这个模型先作为架构约束，不要求当前阶段全部实现。

## 阶段边界

当前阶段只做：

- Codex 治理。
- 本地只读索引。
- 桌面壳。
- 低风险路径动作。
- 任务线和证据入口。

后续再做：

- 个人知识库。
- 多 agent 接入。
- 模型辅助调度。
- 复杂画布编排。
- 本地向量搜索。
- 可控写入。

## 当前未决问题

- React Flow 是否作为第一版主视图，还是先作为项目关系/任务关系辅助视图。
- SQLite 何时替换 JSON 索引文件。
- 个人知识库先支持哪些文件类型。
- 是否需要本地模型参与摘要和标签。
- 是否需要跨设备同步。

这些都不进入当前阶段验收。
