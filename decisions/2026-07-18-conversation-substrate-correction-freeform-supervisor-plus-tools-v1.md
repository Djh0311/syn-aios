## 拍板摘要

1. **聊天=聊天**:与主管的对话永远开着,自由多轮,无状态锁、无回合格式强制。
2. **实物走工具**:方案/派发/终标等结构化产物,只经主管调 Syn 的 MCP 工具产生并落右区卡;聊天里永不产生实物。
3. **闸不变**:方案卡上点批准才跑(所批即所跑、带图+lint 前移=P2-A 原样);审计一笔不少。
4. **工人归主管**:worker 由主管管理,管不了的拿到对话里问你;你永远只面对主管(蓝图五根柱原样)。
5. **信息自然流转**:用户不在 Syn 与 Codex/其他 agent 之间搬话；MCP 结果回发起它的原 thread，主管继续用自然语言解释；工具失败不抹掉已经完成的对话。

即:与 Claude Code/Codex 同构——对话是介质、工具调用是受治理的动作、批准是闸。

## 自然信息流转合同（07-19 补充）

| 层 | 责任 |
|---|---|
| 自然语言对话 | 理解、追问、协商、解释；用户只和主管说话 |
| MCP | 方案、任务、状态、证据、终标等结构化动作与结果回传 |
| Syn 控制核心 | 路由、角色能力、参数校验、幂等、审计、权威事实 |
| 卡片 / 索引 | 对权威结构化事实做实物投影，不另造聊天通道 |
| 用户批准卡 | 唯一执行授权；主管落 Pending 卡不等于批准执行 |

因此必须分开记录四个结果：**用户消息是否入账、主管是否完成答复、工具是否成功、卡片是否物化**。任一层失败只报告本层真相，不得用一句“没送到主管”把其余成功事实一起吞掉。

“自然流转”不批准全局自动工具调用：能力仍按 role / server / tool 精确给；Syn 仍做 schema、权限、审计与 fail-closed。现有 Syn 控制核心承担这一职责，**不由此重启已搁置的 Syn 自有 agent 层**。
