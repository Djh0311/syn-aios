## 2. P1 问题与调整要求

### P1-1 R4-6 没有停止线，已出现零产出任务包

现象（git 实测）：

- R4 共 49 个执行包，其中约 39 个为测试夹具抽离。
- 巨石下降在 A44 后停滞：A45–A49 五个包在约 65 分钟内连续收口（06-12 07:02–08:07），巨石累计 +2 行（3,402 → 3,404），零下降。
- 这五个包的产出全部是拆"本身已低于 2,000 行新文件上限"的 helper 文件：A48 把 521 行拆成 239+308，A49 把 370 行拆成 15+374——不改善任何棘轮指标，但每包仍消耗全套治理成本（任务包 + evidence + 复核 + 3 个 commit + 6 份权威文档各写一段 checkpoint）。

根因：官方计划 R4-6"离线测试主文件按领域拆分"没有定义完成判据，"继续拆"成了自我延续指令（CURRENT.md 当前"下一步 R4-A50：继续中等粒度离线交互测试按域拆分"即证）。这不是执行线偷懒，是计划缺口。

调整要求：

1. 补定 R4-6 完成判据：**主文件 ≤ 2,000 行（对齐 TS/TSX 新文件上限），或剩余内容已属单一域不可再拆，以先到者为准**；达成即声明 R4-6 收口，不再续拆。
2. 立即生效的立项规则：**后续任何 R4-6 包必须在任务包里写明"预计使哪个棘轮指标下降多少行"；不降低任何棘轮指标的拆分包不得立项。**已低于 2,000 行上限的 helper 文件不再作为拆分对象（确需的准备工作并入产生下降的那个包，不单独立项）。
3. 已排队的 R4-A50 按上述规则重新定 scope 或取消。

### P1-2 R4 硬目标未动，R2 后段挂起理由可能已过期

现象：

- 官方计划 R4 清单里的硬目标基本未动：ProjectsView 按目标布局区块拆分（仅 -172 行）、AgentView（-247 行）、types.ts 分域（-151 行）、`WorkbenchSnapshot` 改按页查询（仅有 R4-A2 的只读 skeleton command，业务数据未迁移，`returns_business_data=false`）。
- lib.rs 自 R2-B10（06-11 03:52，13,949 行）后停滞，现 13,965 行；通往 ≤3,000 的主体——inline tests 巨石（约 1,703–13,949 区段、213 个 `#[test]`）——一行未迁。
- R2-closing 复核（`DONE_WITH_CONCERNS`）当时挂起 inline tests 迁移的前置条件是"共享 fixture/stub runner 底座未拆 + 跨 store 事务语义等 R3 transaction / test support 设计"。**R3-A13 事务采纳 Level A 现已完成，该前置条件至少部分满足，挂起理由需要重新评估。**

调整要求：

1. R4-6 按 P1-1 收口后，火力转向 R4 硬目标。立项顺序由主管线提案，建议：types.ts 分域 / snapshot 按页查询先行（为解冻后布局重做铺路），ProjectsView / AgentView 按目标布局区块拆随后（拆分基准维持官方计划：按 Xuanji §16 目标布局区块切，不按现状外观切）。
2. 重开"R2 后段评估"：以 R3-A13 完成为输入，重新判定 lib.rs inline tests 迁移是否解锁。结论必须写成显式决定——继续挂起也要给出新的挂起理由和复评触发点，**不允许无限期默认挂起**。

### P1-3 棘轮水位线存在无声回涨缺口

现象（shape gate 实测）：

- lib.rs 水位线钉死在初始 25,925，当前 13,965 仍报 `status: decreased`。
- 但 lib.rs 已从 R2-B10 的 13,949 回涨 +16 行（R3/R4 的 mod 声明，内容本身经任务包批准、合理）。gate 对这 16 行无感知——**lib.rs 现有 11,960 行的无声回涨空间**；同理适用于所有已下降的棘轮文件。这正是 R0"无静默豁免"原则想防住的形态。

调整要求（治理任务包，R0 类型）：

1. 棘轮语义从"不超过初始基线"改为"**不超过历史最低收口值**"；回涨必须在任务包里显式裁决并留痕，gate 对未裁决回涨报 error 而非沉默。
2. 本次处理：lib.rs 水位线重置为 13,965（已有的 +16 行以本文裁决为既往任务包批准的模块声明，不要求倒拆——倒拆是无意义返工）；此后按新语义执行。
3. 实现方式由主管线设计（gate 写回历史最低值 / 内置基线表均可），验收 = 人为给任一棘轮文件加 1 行，gate 必须 fail。
