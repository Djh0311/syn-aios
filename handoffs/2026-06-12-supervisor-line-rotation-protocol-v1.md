## 1. 班制

- **主管线职位唯一**，档案 = 既有权威文档链。夜班脑 = Codex（额度便宜、目标模式通宵），白班脑 = Claude（额度贵、按需出场）。
- 换班不写新 handoff；当班脑在每包 checkpoint 与任务包头部留痕（`Supervisor：<model-id>，当班`），CURRENT.md 即班次记录。
- 复核线**不轮班**：固定 Opus 4.8 独立会话——对 Codex 与 Claude 皆为跨模型复核，且是唯一连续旁观两个班次的眼睛，跨班不一致优先由它发现。

## 2. 接班三步（每次换班的固定动作）

1. **`git status`**：工作区脏 → 对照当前开口任务包二选一：补完收口，或回滚到上个 commit；选择与理由写入当班第一个 checkpoint。（防"额度在包中间断掉"）
2. **重读磁盘**：CURRENT.md「当前结论」+ 当前车道的停止线；不信任何开机快照或上一班转述。（两个班次均实测过权威档案中途变更）
3. **核对停止线**：确认当前车道仍有有效的数字停止线；没有 → 不开工，先把停止线立给用户拍板。

## 3. 复检节奏（信任阶梯，参数待用户定）

- 头 **N=3** 次换班：接班脑对前一班全部任务包做全量复检（= 换脑抽查实操，2026-06-12 首轮已跑一次方向）。
- 连续 N 次无 P 级发现后：降为**抽检 1/3**；但凡触及禁迁清单、危险区边界或权威结构的包**必检**。
- 任一次复检出 P0/P1：节奏回退到全量，重新积累。
- 复检结论一律写 handoff 留痕；抽检免掉的包在结论里列明"免检+理由"。

## 4. 夜班放行双前提（缺一不放）

夜班（无人值守目标模式）开跑前必须同时满足——

1. 当前车道有**数字停止线**（到线即停，不自寻新活）；
2. **任务包队列已备好**（夜班只执行已立项的包，不在无人时立新方向）。

依据：R4 夹具车道空转 26 包，正是发生在无人看管的通宵跑。车道吃完而队列已空 → 夜班写当班清单后停下，剩余额度不烧。

## 5. 白班工作面（成本闸）

- 白班 Claude **默认只做判断与备料类**：复核协调与放行准备、窗口计划与提案起草、为夜班立任务包队列、评估包。
- **执行类（代码搬运/迁移/重构）需用户当次点头**才做——贵脑不默认干便宜活。
- 白班结束前的固定动作：检查夜班双前提是否就绪（§4），不就绪则补齐或明确告知用户缺什么。

## 6. 与既有机制的关系

- 本制度是愿景文档 §4"换脑非换人、额度继承"的运行化：班次轮换不清零任何职位信任；§3 复检即"换脑抽查"机制的常态化（其转正与否仍属愿景文档 §10 待表态项，本制度先以草案口径运行积累数据）。
- 未来工作台的调度器政策即本文的自动化版本（制度即数据：先文件跑通，后引擎执行）。
