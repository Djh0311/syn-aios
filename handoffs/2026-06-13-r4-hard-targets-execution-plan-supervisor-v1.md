## 2. 分批与停止线（核心设计）

按风险把 R4 硬目标剩余部分切成两批，中间设强制停止线：

```
批一：snapshot 按页查询（中风险，可自主连续跑）
  → 【停止线】批一全部收口后停下，等主管+用户定 View 拆分设计
    → 批二：ProjectsView / AgentView 按目标布局区块拆（高风险，停止线后另行授权）
```

**为什么在这里设停止线**：批二要"按解冻后目标布局区块"拆（Xuanji §16：四周窄栏/中央主界面/右侧详情面板/底部状态栏/悬浮入口）。这个"区块→组件边界"的映射是判断活，牵涉解冻后 UI 重做基准——让执行线凭现状外观猜着拆，会重演夹具车道空转的教训。判断密集的活前停下、先备料再跑，是既定原则。

## 3. 批一：snapshot 按页查询（本规划授权自主跑）

**目标**：把整包 `WorkbenchSnapshot` 读模型拆成按页查询（项目页 / 智能体页 / 运行中页 / 记忆页 / 知识库页 / 设置页），前端按页取数，不再一次性拉整包。

**建议子步（执行线按需拆任务包，每步一包、独立复核、独立 commit）**：
- H2-1：定义六个页各自的读模型 schema（每页需要哪些字段），落 `page_read_model.rs`，对照现有 `WorkbenchSnapshot` 字段做覆盖核对（不漏字段）。
- H2-2：后端按页 query 实现，复用 R4-A1 骨架；注意 shape gate 约束——新 query 命令不进 `lib.rs`、command 总数变化要在任务包里声明并更新基线。
- H2-3：前端消费方从整包 snapshot 切到按页取；保持现有界面行为与视觉**完全不变**（这是读模型重构，不是 UI 改动）。
- H2-4（按需）：`types.rs` 中 `WorkbenchSnapshot` 相关结构随之瘦身，降低 `types.rs` 棘轮。

**批一边界（硬约束）**：
- 行为与视觉零变更——只改"数据怎么取"，不改"页面长什么样"。
- 不拆 ProjectsView / AgentView 组件（那是批二）。
- 不碰 UI 布局、CSS、水墨风格。
- 每包必须声明预计降低哪个棘轮指标多少行；不降棘轮的准备工作并入产生下降的包，不单独立项。
- 不执行真实 codex、不读写 `~/.codex`、不碰 R3 Level B、不解冻 backlog。

**批一完成判据**：六个页读模型独立可查、前端全部切到按页取、整包 snapshot 不再被前端直接消费、相关离线测试全绿。达成即声明批一收口并**停在停止线**。

## 4. 停止线后：批二预告（本规划不授权执行）

停止线后由主管线（Claude）产出"ProjectsView/AgentView 布局区块→组件边界映射"设计稿，经用户过目确认后，才另行授权批二执行。批二同样按区块逐块拆、每块独立复核。**执行线不得在批一收口后自行进入批二。**

## 5. 通用约束（两批都适用）

- 每包：任务包 → 实现 → 离线验证（typecheck / 相关测试 / shape gate / git diff --check）→ 独立复核线 `CLEAR` → commit → checkpoint。
- 复核线独立（claude-opus-4-8 或 Codex 额度恢复后的 Codex 复核线），**不得由执行线自复核**。
- 轮班制度 `handoffs/2026-06-12-supervisor-line-rotation-protocol-v1.md` 适用：换班三步、夜班双前提（停止线 + 任务队列已备）。
- 棘轮"历史最低水位"语义照旧；不降棘轮不立项。
