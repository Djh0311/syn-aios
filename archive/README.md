# 产品线历史档案

状态：**纯历史目录，不是当前产品正本、当前状态、候选方案、任务入口或执行授权。**

## 这个目录保存什么

- `tasks/`：已经完成、停止、被取代或不再排期的旧任务包；
- `evidence/`：旧版本、旧场景和旧证据等级下形成的实施与验收记录；
- `handoffs/`：旧阶段的交接、复核和接手说明；
- `decisions/`：已经被吸收、取代或只保留历史来源的旧决定；
- 其他按日期或旧治理体系保存的快照。

归档表示“保留来源和审计价值”，不表示内容错误，也不表示其中描述的能力今天仍然成立。

## 不从这里推导什么

归档正文里的“当前”“唯一”“下一步”“必须执行”“已授权”“已冻结”“最终”都只在该文件记录的时间、版本和范围内成立。它们现在不用于：

- 定义 Syn 是什么；
- 改写当前产品需求或架构；
- 判断当前源码已经具备什么能力；
- 恢复旧阶段、旧任务或旧授权；
- 决定今天的开发顺序。

需要了解当前项目时：

- 产品与开发导航从仓库根 `README.md` 进入；
- 当前实现与验收边界看 `docs/current-state.md`，并结合当前版本库（Git）、源码和直接验证；
- 当前开发规则和授权边界看 `AGENTS.md`；
- 产品决定只采用仍被当前产品正本收录、且没有被后续决定取代的部分。

## 从历史记录中发现重要内容时

如果历史交接、证据或旧决定里存在今天仍需要的用户拍板、产品要求或架构原则，应先把该内容连同来源提取到当前产品正本或正式决定中，再让原文件继续留在历史档案。不得因为某句话只存在于归档里，就直接把它恢复成当前要求。

历史证据可以被知识系统检索和引用，但检索命中不会提高其权威等级，也不能绕过来源、敏感性和当前事实复核。

## 整理与迁移约束

本目录和仓库中的旧证据、交接存在大量相互引用。后续如需继续移动，应保留旧路径到新路径的映射，逐批更新引用，并校验文件数量、内容哈希和 Markdown（文本标记格式）链接；不要只凭文件名删除、合并或判断内容已经失效。
