# 桌面容器路线决策

## 结论先说

薄弱点：

- 静态网页壳已经能看数据，但不能兑现阶段 2 里的“打开文件夹、定位日志”等桌面动作。依据：`product-line/handoffs/2026-05-27-desktop-app-static-shell-validation-review.md`。
- 直接上 Electron / Tauri 都会引入新的依赖、构建和权限边界，不应在没有路线确认时开实现。依据：`product-line/tasks/2026-05-27-desktop-container-route-decision.md` 禁止安装依赖，并要求先做路线决策。
- 当前没有证据说明必须马上做完整桌面容器。依据：静态壳已通过 smoke，可继续作为只读入口。

决策：

- 当前保留静态网页壳，作为阶段 2 只读入口。
- 第一版如果要实现打开文件夹、定位日志、复制路径等本机动作，推荐优先走 Tauri 能力验证。
- 不推荐直接进入完整 Electron 实现。
- 不推荐继续把纯网页包装成“最终桌面应用”。

## 依据

- `product-line/STAGE_PLAN.md`：阶段 2 目标包括本地桌面应用、打开文件夹、复制路径、定位日志。
- `product-line/handoffs/2026-05-27-desktop-app-static-index-shell-review.md`：静态壳被接受为原型，但不是最终桌面应用。
- `product-line/handoffs/2026-05-27-desktop-app-static-shell-validation-review.md`：静态壳 smoke 通过，但真桌面能力需要路线决策和权限边界。
- `product-line/README.md`：第一版只读治理 Codex，不写 Codex 状态库，不展示密钥。

## 路线比较

### 继续纯网页

优点：

- 当前已验证可用。
- 不需要新增桌面依赖。
- 风险最低，最不容易误写本机状态。
- 适合继续展示项目、会话、skills、harness 候选和 warning。

缺点：

- 不能可靠打开文件夹。
- 不能可靠定位 rollout 日志。
- 不能做受控本机文件动作。
- 直接双击 `index.html` 可能受浏览器本地文件读取限制，仍建议本地 server。

判断：

- 适合作为当前只读入口继续保留。
- 不适合作为最终桌面能力方案。

### Electron

优点：

- 对网页前端迁移成本低。
- Node 生态做文件夹打开、路径复制、系统动作比较直接。
- 如果后续要做更复杂桌面交互，开发速度可能快。

风险：

- 权限面更大，容易把 Node 能力暴露给 UI。
- 依赖更重，安装和打包成本更高。
- 对本产品线来说，最大风险是误把“只读治理”扩成“可随意访问本机文件系统”。

判断：

- 不推荐作为第一优先路线。
- 只有在后续明确需要大量 Node 生态能力时再评估。

### Tauri

优点：

- 更适合把本机动作收敛成少量显式命令。
- 权限边界可以按能力设计，例如只允许打开项目目录、复制路径、定位已索引日志。
- 与当前“只读治理、少量低风险动作”的目标更匹配。

风险：

- 需要引入新的工具链和构建流程。
- 如果本机 Rust / Tauri 环境不齐，需要额外安装和验证。
- macOS 打包、签名、权限提示后续要单独处理。

判断：

- 推荐作为真桌面能力的优先路线。
- 下一步不应直接全量迁移，而应先做最小能力验证。

## 推荐路线

推荐分两步：

1. 保留当前静态网页壳作为只读入口。
2. 用户确认后，派桌面应用线做 Tauri 最小能力验证。

Tauri 最小能力验证只验证这些事：

- 能加载现有静态 UI。
- 能读取同一个静态 `codex-index.json`。
- 能通过显式命令打开项目文件夹。
- 能通过显式命令定位 rollout 日志所在文件。
- 不写 `/Users/yoyi/.codex`。
- 不读取或展示 `.env`、密钥、授权文件。

## 不推荐路线

- 不推荐直接做完整 Electron 应用。理由是权限面和依赖面更大，当前证据不足。
- 不推荐继续把纯网页叫桌面应用。理由是它缺少阶段 2 的本机动作能力。
- 不推荐在静态壳里伪造“打开文件夹”“定位日志”按钮。理由是这会让用户误以为能力已经存在。

## 仍然未知

- 本机是否已经有 Tauri 所需工具链。
- macOS 打包和权限提示要做到什么程度。
- 第一版是否必须打包成可双击 app，还是本机开发模式即可。
- 打开文件夹和定位日志是否只允许索引内已有路径，还是允许用户输入路径。

## 下一步建议

建议先让用户确认是否接受“Tauri 最小能力验证”路线。

如果确认，下一包再派给桌面应用线，范围只做能力验证，不做完整产品化打包。
