## 2. 建什么

1. **点允许立刻有脸 + 状态防丢**:
   - `authorizeAndStart` 一进来就 `setManualPhase("running")`(运行脸文案:"正在确认方案并自动推进…可能要几分钟");不是等 await 回来才切。
   - reset effect 改条件:**`runningRef.current === true` 时不清;`latestProposal` 变 null 时不清**;只在"出现一份**新的** pending proposal id"时清(那才是"新方案到了、回批面"的本意)。
   - `outcome`/`startError` 在模块级缓存一份(按 project_root 键),面板重挂载时恢复——换 tab 回来结果还在。
2. **旧方案不冒充当前**:批面显示方案生成时间 + 目标原文;若方案创建时间**不是今天**,批面顶部黄条「这是 X 天前的旧方案」,主按钮换成「重新说目标出新方案」,[允许并开始]降为次按钮。防再批库存。
3. **重新出方案带上下文**:`backToSay` 时**预填 goal = 原 user_goal**;"说"面顶部若有上次停因,显示一行摘要(如「上次停在:写范围为空——重新出的方案会带上写范围」)。不再落空白首屏。
4. **会话收纳**:平铺 radio → 一行「用哪个对话干:接现有 · <最近一条标题> ▾」,点开才展开选择(最近 5 条 + 其余折叠/可搜);「开个新的」置灰 + "下一阶段支持"(用户已拍方案 a 下阶段)。默认选中最近一条现有会话;项目无可用会话时给人话提示(去智能体页开一条)。
5. **接缝换合流命令**:`runJiaobanAuthorizeAndStart` 的三步兜底 → 换成调后端 `confirm_and_start_authorized_run`(传 existing 的 thread_id;返回同形 outcome,组件不动——原注释就是这么设计的)。合流命令对已确认旧方案会干净拒("方案不是待用户确认状态")→ 把这个拒显示成人话 + 引导「重新说目标」。`lib/tauri.ts` 补前端封装(纯 invoke,不带逻辑)。
6. **顺手**:面板顶部若检测到 stage=blocked 的 outcome,「去工作流看看」按钮保留;别的不加。
