## 0. 接手须知

- 本包只建**工具面**:把现成工作台命令包装成可供"主管 codex 会话"调用的受控 MCP 工具。**不建主管契约、不开试点开关**(那是站2 的包)。
- 教训在案:memories 一夜自开(07-07)→ **绝不写 `~/.codex/config.toml` 全局配置**;工具挂载必须 per-会话/per-调用。
- 两分法约束进墙:工具内壁只做**确定性**检查(授权/绑定/path-lock/allowed_write/配额);终标工具产出**意见**,写账本亮黄牌,**无权停链**。

## 1.0 勘察先行(硬闸 · 单独回交 ≤1 页)

1. **MCP 宿主方案**:工作台侧怎么起 MCP server(Tauri 进程内 / sidecar 二进制;stdio / SSE)?生命周期跟 app 还是跟单?给一个推荐+理由。
2. **主管会话挂载方式**:codex 有没有 per-invocation / per-会话的 MCP 配置口(不落全局 config)?勘实并给命令样例;**若只支持全局配置 → 停,回报,方案重议**。
3. **七工具 → 现成命令映射清单**:派工人/读口供/追问工人/等待/读关键文件/终标收单/报告用户,各自映射到哪个现成入口(函数/命令名+文件行),各自的闸点是什么。
4. **配额计数落点**:并发/追问/时长计数存哪(store 侧 sidecar,不碰 `~/.codex`)。

## 1.1 实现(核复后)

- 七工具逐个包装:内壁=确定性闸(授权检查/绑定/path-lock/allowed_write/配额递增)→ 调现成命令 → **调用即审计事件**(actor=supervisor_orchestrator·工具名·参数摘要·结果摘要);
- 终标工具:产出 `{verdict, reason}` 写账本+黄牌位,**不改链态、不触发重做循环**(两分法);
- 错误人话复用 `run_error_translation.rs`,不新建翻译器。

## 2. 死线

人闸([允许并开始])0-diff;经典管线行为 0-diff(工具面是旁路能力,不改老路);不写 `~/.codex` 任何文件;runner argv/沙箱构造区 0-diff(工具只调现成入口,不开新执行路径);新增 Tauri 命令/MCP 端点报数;进程收割是收割器职责,工具面不杀进程。

## 3. 变更辐射面(模板必填)

MCP 宿主进程生命周期(app 启动/退出/崩溃时 server 与在跑单的关系);审计事件量级(主管一单可能几十次调用,账本增速);配额 sidecar 的锁与并发。

## 4. 验收

- 勘察核复原文引用在最终回交里(硬闸);
- 每工具单测 ≥1 条越权拒 + ≥1 条落账断言(共 ≥14);终标工具"无权停链"负测试(意见=needs_rework 时链态不变);
