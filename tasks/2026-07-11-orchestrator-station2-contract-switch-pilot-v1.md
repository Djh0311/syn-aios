## 0. 接手须知

- 站1 已收:`supervisor_orchestrator` MCP role + 七工具 + 配额 sidecar 全在库(`mcp/supervisor_orchestrator.rs`)。本包把它接到"能起一个真主管会话"为止,**试点开关默认关、首次真跑不在本包内**。
- 主管会话本身也是 `codex exec` 子进程 → **必须登记进 ①.75 的 `exec_process_registry`**(spawn 登记/收尾注销),别造第二套进程管理。

## 1. 建什么

### 1.1 主管会话发射器(后端)
- 输入 = 一个已批准的授权段(active authorization);组装**开场白 = 契约正文 + 本单上下文**(用户目标/已批方案摘要/授权范围/任务包现状);
- 契约文本进代码作模板常量,顶部注明:**正本 = contract draft 文档路径,改正本必须同步此常量**(防两份漂移);
- 调用形状(勘察已验证):`codex exec --ignore-user-config -C <固定测试项目> -c 'mcp_servers.supervisor_orchestrator.command=…' -c '…args=["__mcp_server","--role","supervisor_orchestrator","--run-id","<run>"]'`;模型/effort **显式传参**(`--ignore-user-config` 后无用户默认可依赖);
- argv 硬约束:沙箱 **read-only**(主管自己不写文件,一切写经 MCP 工具→现成命令)、复用既有 `codex_approval_bypass_arg` 拒绝清单(禁 `--full-auto`/绕审批旗)、path-lock 圈固定测试项目;
- spawn 后登记收割器、收尾注销;run-id 贯通(发射器→MCP server→配额 sidecar→审计)。

### 1.2 按单开关(前端小改)
- 交办面加模式选择:「经典状态机(默认)/ 主管编排(试点)」;**仅 只读单 + 固定测试项目 时可选**,其余灰显带一句原因;
- 选了试点的单,批准后走发射器而非经典链;单内 UI 至少能看:主管进行中 + 账本事件流(复用现成审计读模型,不新造面)。

### 1.3 试点验收数字落档(机制侧)
- 计划预写的四数(越权 0 / 卡住率 ≤ 经典 / 追问在预算内 / 每单账本可回放)所需字段核对:sidecar 审计 + workflow 账本足以回答四数——缺字段就补进 sidecar 记录,**不写链态**。
