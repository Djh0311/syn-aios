# 任务包:好用 UI 原型(现有功能 + 权威愿景 → 可点 HTML)· 用户委托 → 主导线执行 v1

日期:2026-07-08　性质:**轻档·纯原型**(零产线代码;执行者 = 主导线——用户原话「agent 层的设计……要靠你」+ 本单「写个任务包让你……做一份 ui 原型」)。

## 0. 需求原文(2026-07-08 用户)

1. 交办页面左侧需要有**工作历史**——中断的、没做的可以直观看到;
2. 根据**现有功能 + 权威文档的未来愿景**做一份 UI 原型,需求就是**好用**:用起来非常简单方便,**管理项目、开发项目非常简单清晰**;
3. 秘书放右侧栏**感觉有点小**,未来内容多了会非常挤;
4. 「我还有些想法但说不上来」——原型的第二职责:**钓出说不上来的想法**(用户对具体屏反应 → 迭代)。

## 1. 输入(设计依据·全在库)

- 现有功能实况:`CURRENT.md` ①②(交办五态/所批即所跑/全局主管两道意见/秘书待拍板面/记忆环);
- 交办定稿 `decisions/2026-07-02-...`(**尊重不推翻**:五态/授权卡/永不冻;用户当年否掉「工作桌首页/导航收编」——原型不复活它,除非用户看完新屏主动重议);
- 未来愿景:路线图 Phase C(NL 一句话入口)/D(模版·多工作流·记忆完整)/E(多项目生产);愿景 v1(像小公司);架构 §7(秘书=核心协作层·可出现在多处);中间版 §0.6 十步流程;
- 风格约束(用户 2026-06-10 拍过):**只动布局,不动风格——水墨古风保留**。

## 2. 判据(每个设计决定过一遍)

**好用五柱**:少动手/看得懂/等得安心/卡了有路/交货有交代;**一票判**:它让用户**少等、少点、少懵**了吗?三个都不占 → 不进原型。

## 3. 交付

- `prototypes/ui-vision-mockup/index.html`——自包含可点 HTML(假数据用真跑过的单:删怪/计分板/纯建议);
- 必答三题:① 工作历史左栏长什么样(状态一眼分:跑着/卡住/交货/纯建议/待批·中断单行内给[接着跑])② 秘书怎么长大(收展宽面板 + 秘书全页两级)③ 现状与未来同屏怎么标(「现在就有」/「Phase C」/「构想·待拍」徽标,防把愿景误当现状);
- **迭代式**:v1 → 用户看+反应(含钓出来的想法)→ 改 → 拍板;拍板后按定稿出**实现包**(工作历史后端读模型 + 前端;秘书扩容),原型本身不进产线。

## 4. 边界

纯 HTML 原型,不碰 `prototypes/productized-desktop-shell/**` 任何产线文件;不复活用户否过的方案(可作「构想·待拍」灰列,不当默认);原型里的未来功能必须带阶段徽标,不许画成现状。
