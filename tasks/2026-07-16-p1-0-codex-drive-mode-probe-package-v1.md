# 任务包:P1-0 codex 驱动方式选型勘察(只读探针)v1

日期:2026-07-16 · 档位:**轻档·只读探针**(仓库零改动;固定测试项目/temp 内实验) · 执行者:执行线 · 上位:总执行计划 §一 阶段一(`docs/plans/2026-07-16-master-execution-plan-conversation-first-v1.md`,防跑偏总则先读)。

## 背景(一句)

阶段一要把主管做成"常驻会话+MCP 内线电话";Syn 驱动 codex 有三条路(shell `resume` / `codex mcp-server` / `codex app-server`),选哪条要实测数据,不要印象。

## A·探什么(逐项实测,每项记原始输出)

1. **A1 基线·shell resume**:新会话后连续 ≤12 轮 `codex resume` 注入短消息。量:每轮墙钟延迟(冷启/热续分开记)、失败率与失败形态;同一会话并发发两个 resume 的行为(锁?竞态?报错原文)。
2. **A2 mcp-server 模式**:`codex mcp-server`(stdio)起实例,手写最小 JSON-RPC client(node 原生,零新依赖):initialize → tools/list(**暴露的工具与参数形态整段记录**)→ 发起对话 → 续轮 ≤12 轮。量:每轮延迟、回合结束语义、进程生命周期(常驻/每会话一进程)、2-3 并发实例的内存与稳定性。
3. **A3 app-server 浅探**(≤30 分钟封顶):启动形态+协议初判,结论只需"值不值得深入",别陷进去(标注 experimental)。
4. **A4 工具调用挂起上限(关键)**:自写慢 MCP 工具(node,收到调用后 sleep N 秒再返回;N=60/300/900 各 1 次)挂进一个测试会话,让模型调用它。量:codex 等不等得起、超时阈值与报错**整段原文**、超时后该回合如何收场。→ 这是"问你一句"选实现(挂起等答 vs 转交+唤醒)的定量依据。
5. **A5 转交+唤醒模式直证**:工具立即返回「已转交用户,等答复」→ 回合自然结束 → 稍后 `codex resume` 注入「用户答复:…」。验证:会话能否衔接上下文续跑(发条模式可行性)。
6. **A6 只读挂项目**:read-only 沙箱起会话,cwd=固定测试项目,多轮让它自己翻文件答问。验证"咨询期只读挂项目、能自主读不靠注入"的形态与限制。

## B·红线(违者停手报回)

- **仓库零改动**:开工/收工各跑 `git status --short` 留证一致;探针脚本与日志放 `evidence/raw/2026-07-16-p1-0-drive-mode-probe/`(不 commit)或 /tmp。
- cwd 只许固定测试项目 `/Users/yoyi/codex-workflow-mario-test` 或 temp;**禁任何真实项目**。
- **禁读 `~/.codex` 凭据**(auth/token/secret);需要隔离用临时 `CODEX_HOME`;**全局 codex 配置零改**;不新装全局包(npm -g 禁)。
- 每实验回合数按 A 项封顶;单项卡死不硬泡,记录现象跳下一项;总墙钟目标半天内。
- **报回不自拍**:探到意料外能力(如 mcp-server 暴露强工具)只记录上报,不顺手启用;引用运行时输出**整段原文**,截断处显式标「[截断]」且不得作为结论依据。
