## 薄弱点

- “完全按照源稿”与“右侧保留现有图标窄栏”天然冲突，所以本任务包必须把右侧栏列为用户批准的差异，不能在回收时当成失败。
- 源稿是静态 HTML，真实工作台是 React/Tauri 应用；照抄 HTML 会破坏状态、确认弹层和现有工作流入口。

- 如果没有源稿截图基准，不能宣称“对齐源稿”。

## 目标

把真实工作台 UI 调整为以 `inkwash-full.html` 为主的水墨工作台界面，同时保留当前工作台必须有的真实能力。

具体目标：

1. 顶部栏、左侧导航、中央舞台、底部 dock 尽量按源稿还原。
2. 首页恢复源稿星图式工作台，而不是当前失败提示/普通面板式首页。
3. 项目页和工作流页按源稿视觉语言重做，但必须保留真实项目、会话、工作流、确认弹层入口。
4. 右侧栏保留窄图标入口，点击或选中后展开详情。
5. 通知、待办、审计从左侧导航移到右侧栏。
6. 刷新入口保留在顶部栏，视觉上融入源稿顶部栏。

## UI 对齐规则

### 1. 总体骨架

以源稿骨架为主：

- 顶部栏：源稿 `topbar`。
- 左侧栏：源稿 `rail-left`，但移除通知、待办、审计。
- 中央区域：源稿 `stage`。
- 底部栏：源稿 `dock`。
- 右侧栏：保留当前图标窄栏，选中后展开详情。

桌面默认尺寸建议：

- 左侧栏接近源稿 `72px`。
- 顶部栏接近源稿 `56px`。
- 底部栏接近源稿 `64px`。
- 右侧图标栏可保持当前窄栏宽度，但展开详情时不得遮挡关键操作；可用抽屉、滑出面板或展开宽度实现。

### 2. 顶部栏

顶部栏按源稿执行：

- 品牌区域用源稿的印章 + `本地 AI 工作台`。
- 项目切换区域按源稿放在品牌后。
- 搜索区域按源稿样式，文案优先使用 `跨项目 · 跨记忆 · 跨审计`。
- 右侧保留模型 / key / 待审 / 新建 / 头像等源稿结构。
- 加入当前应用“刷 / 重新读取”入口。

刷新入口要求：

- 不能破坏源稿顶部栏层级。
- 可以放在源稿右侧操作区。
- 必须有 `aria-label` 或等价可访问名称。
- 点击仍调用当前 `reload()` 逻辑。

不应出现：

- `Codex 工作台` 作为顶部品牌。
- 单独的“状态 可用/需处理”顶栏文案，除非以源稿右侧状态信息样式融入。
- 说明性文案挤占主界面。

### 3. 左侧导航

左侧导航按源稿保留这些入口：

- 首页
- 项目
- 想法箱
- 建议方案
- 工作流
- 智能体
- 知识库
- 记忆
- 技能
- harness
- 工具
- 模型 / 凭据
- 设置

左侧不要放：

- 通知
- 待办
- 审计

左侧导航要求：

- 图标窄栏。
- 默认只显示图标。
- 悬停或聚焦显示提示。
- 当前选中态按源稿朱砂侧边标记。
- 图标可以沿用源稿字符图标，若改用图标库，必须整体风格一致。

### 4. 右侧栏

右侧栏不完全照源稿，按用户本轮确认执行：

- 保留当前图标窄栏。
- 图标入口至少包含：通知、待办、审计。
- 若当前已有运行中工作流入口，也保留在右侧。
- 选中某个图标后展开详情。

展开详情要求：

- 通知详情显示通知中心内容。
- 待办详情显示待办中心内容。
- 审计详情显示审计 / 权限 / 风险记录摘要。
- 运行中详情显示运行中工作流。
- 展开面板视觉使用源稿右侧 `pane / feed / run` 的水墨语言。
- 收起后回到图标窄栏。
- 不把右侧详情常驻成源稿 320px 宽栏，除非用户后续改口。

### 5. 首页

首页必须恢复源稿默认首页方向：

- 顶部问候和标题区域。
- 星图式五个核心节点：
  - 项目
  - 智能体
  - 当前工作流
  - 技能
  - harness
- 节点内挂近期信息。
- 视觉上保持宣纸底、淡墨晕染、朱砂强调、虚线分隔。

真实数据挂接：

- 项目数来自 `snapshot.projects`。
- 会话数来自 `snapshot.sessions`。
- 工作流数来自 `workflowState`。
- 技能 / harness 优先接现有数据；缺真实数据时显示只读占位，但必须明显是未接真实数据。

### 6. 项目页

项目页按源稿视觉语言执行，但要尊重当前用户已确认的工作方式：

- 项目入口仍应能看到项目列表。
- 选中项目后进入该项目的工作台。
- 工作流页只显示工作流画布；其他内容不要塞到工作流画布外面的杂乱面板。
- 会话、任务包、交接、技能、验证、设置等内容各在自己的界面。

允许的实现方式：

- 项目页可以保留“项目列表 + 当前项目内容”的结构。
- 当前项目内容的视觉要按源稿纸面、虚线、淡墨、宋体标题改造。
- 项目内 tab 可以存在，但不要做成厚重卡片。
- 工作流 tab 中只显示工作流画布和画布内必要的节点详情/抽屉。

### 7. 工作流画布

工作流画布按源稿 `canvas` 方向执行：

- 使用水墨纸面背景，不使用硬网格白板感。
- 节点、连线、状态条使用源稿的淡墨、朱砂、虚线、纸面卡片语言。
- 节点详情可以放右侧抽屉或画布内展开。
- 不新增通用插件节点生态。
- 不做 ComfyUI 式复杂节点编辑器，除非后续有专门画布研究任务。

### 8. 其他视图

这些入口要按源稿结构至少有可进入界面：

- 想法箱
- 建议方案
- 智能体
- 知识库
- 记忆
- 技能
- harness
- 工具
- 模型 / 凭据
- 设置

真实能力不足时：

- 可以使用源稿式只读占位。
- 必须标明未接真实数据或仅展示原型态。
- 不能用假数据冒充真实完成。
