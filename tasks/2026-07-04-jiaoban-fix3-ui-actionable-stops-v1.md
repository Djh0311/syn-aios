## 2. 建什么

### 2.1 [接着跑,不用重批](核心按钮)
- 出现条件:方案 status==user_confirmed 且(卡住脸/startError/合流被拒"方案不是待用户确认");
- 点击 → 立刻上"正在干"脸(同 fix2 防冻套路:先切相位再 await、runningRef 防重入)→ 调 `autoAdvanceAuthorizedRoleLoop({project_root, workflow_id, actor_id:"user"})` → 返回走现有 outcome 呈现(ran/blocked/needs_binding 各归各脸);
- 文案:「接着跑(方案已批过,不用重批)」;合流"已确认"拒绝的报错**拦截翻译**:「这份方案已经批过了——不用重批,点下面接着跑」+ 本按钮(别把原始错误裸给用户)。

### 2.2 停因→动作 死配对表(卡住脸统一走它)
| 停因特征 | 主按钮 | 备注 |
|---|---|---|
| needs_binding / 会话类 | 选一条会话(现有入口) | 选完自动回到[接着跑] |
| blocked·写范围/方案内容类(message 含"方案缺/写范围/重新让 AI 出方案") | 重新说目标出新方案(现有) | 带原目标+停因摘要(fix2 已做) |
| blocked·其它(含"角色"类·fix3 后端钳位后应基本消失) | [接着跑,不用重批] | 次按钮:重新说目标 |
| startError / 拆任务失败 / 超时 / flaky | [接着跑,不用重批] | 文案注明「上一步失败了,接着跑会从拆任务重来」 |
| 兜底(识别不了) | [接着跑] + [重新说目标] 双给 | **绝不允许出现零按钮的终态** |
- 后端 fix3 会带来新 warnings(「角色已按 codex-dev 执行」「已接续上次中断的运行」)→ 在干/交货脸下用小字列出,不挡主路径。

### 2.3 "正在干"文案细分(小)
- 链事件还没出现的阶段,progress 首行:「主管正在拆任务…(最长可能十几分钟,偶尔自动重试)」;链事件出现后切现有逐步呈现。
