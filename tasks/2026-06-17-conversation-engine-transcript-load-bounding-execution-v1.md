## 1. 拍板摘要

- **要做的事**：把对话的**数据加载**也界定住——点开只先取**最近 N 条**（秒开），更早的**往上滚再按需加载**，根治「点开大对话卡 1–5 秒」。
- **代价**：一刀后端 + 前端的加载分页改造，坐在已建好的虚拟化渲染上。

## 2. 根因（上一轮真机抓出，侦查其实早已指出）

- 侦查当时就写明：`codex_transcript.rs` 的 `read_jsonl_events` **一次性全量读 + 解析整个 rollout JSONL**；前端 `useAgentTranscriptLoader` **等整条全部事件**才显示。
- 上一轮重做虚拟化了**渲染**（画哪几条便宜了），但**加载没动**——点开仍要先把整条读出来 + 解析 + 传过来，**大对话就卡在渲染之前这一段**。
- **本刀专修这一段。**（`codex_transcript.rs` 上一轮未改动，正是漏点。）

## 3. 架构与做法

- **后端**（`codex_transcript.rs` / `commands.rs`）：
  - `read_jsonl_events`（或新增 paged 版）支持**只取最后 N 条事件 + 返回游标**（还剩多少更早 / 行偏移）；新增或改 Tauri 命令按游标取**更早一页**。
  - 推荐先实现「读全部行但只解析 + 返回最后 N + 游标」（砍掉大头：解析 / 构建 / IPC 千条事件）；**若真机大文件 IO 仍是瓶颈，后端从文件尾部反向读最后 N 行、避免全量读盘**。
  - 仍走既有 transcript viewer 的遮挡边界——**读的是同样的 rollout 正文、只是界定数量，不新增 `.codex` 访问面**。
- **前端**（`useAgentTranscriptLoader` / `conversationEngine` / `TranscriptViews`）：
  - 点开：先载**尾部 N** → 立刻渲染 + 黏底（秒开）；
  - 用户**上滚到顶** → 按游标加载**更早一页** → 前插 + **保持滚动位（不跳）**；
  - 复用已建好的**虚拟化渲染** + pending decision-only 发送追加。

## 4. 内部里程碑 + 自检（一次做完、分步推进）

- **M1 后端分页加载**：tail-N + 游标命令；fixtures 测（尾部正确、游标取更早、超大文件不全解析返回）。自检：命令只返回 N 条 + 游标，不再返回全部事件。
- **M2 前端尾部优先 + 上滚加载更早**：点开先显最近、上滚加载更早、**前插不跳滚动位**。自检：点开不等全量；加载更早前插不跳。
- **M3 接合虚拟化 + 黏底 + 发送**：与已建虚拟化 / 黏底 / pending 发送接好。自检：大对话点开秒显、上滚顺、发送冒泡不变。
