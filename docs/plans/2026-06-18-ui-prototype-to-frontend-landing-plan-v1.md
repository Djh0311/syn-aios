## 拍板摘要（先读这段）

- **这是什么**：把水墨原型上敲定的 UI 改动，逐条映射到**真前端 React 代码**的"现状 + 落点(文件:行) + 改动量 + 风险"清单。给咨询线据此拆任务包。
- **代价**：一份对照方案；不含代码改动。
- **关键事实**：原型是**理想稿**，真前端与它**有明显参差**——有些原型页在真前端是**占位**或**右栏抽屉**，有些原型"要删的东西"真前端**本就没有**，还有真前端**强于原型**的真实能力（智能体会话）绝不能被覆盖。所以"照原型落地"≠"照搬"，是**有取舍的融合**。
- **不批准**：本方案不授权任何代码实现、不动任何安全闸、不解锁真实执行。第 5 节的几个"形态分歧"需要**用户先拍板产品方向**，咨询线才好拆包。

## 一句话判据

判一条原型改动现在能不能直接落码——问：**「它是改现有结构(文本/视觉/复用现成机制) 还是 要新建/要数据源没有/要决定产品形态？前者→可直接拆包；后者→先停，回第 5 节让用户拍方向。」**

## 5. ★ 形态分歧：要用户先拍板的（不是码工，是产品方向）

这几条原型和真前端**不只是缺代码，是产品形态选择**。咨询线拆包前，建议先让用户拍：

1. **通知 / 待办 / 审计：右栏抽屉 还是 升格为独立左栏页？**
   真前端它们是 `RightDetailPanel` 的抽屉 panel（不是 view）；原型把它们画成了独立整页。两条路：① 保持右栏抽屉（轻、与现状一致，原型的独立页设计当"抽屉展开后的内容版式"用）；② 升格为左栏独立页（重，要新建 3 个 view + 路由）。**建议 ①**——省事且符合"右栏是常驻余光"的既定分工。
2. **想法箱 / 建议方案 / 工具 / 模型凭据：四个占位页怎么办？**
   真前端是 `SourceStylePlaceholder` 占位（拿现成快照字段凑列表，非真功能）。原型给了它们完整版式。落地 = 把占位换成真页，工作量各不等（想法箱/建议方案有原型设计可抄；工具/模型涉及真实数据接入，属后置）。要排优先级。
3. **智能体页：原型静态表 vs 真前端真实会话能力 —— 必须融合，不能覆盖（硬约束）。**
   真前端 `AgentView` + 整个 `views/agent/*` 是**活功能**：真实会话列表→按 threadId 拉真实 transcript（`lib/tauri.ts:208/213` 真 invoke）→分页游标/缓存/虚拟滚动→可被项目页 `focusedAgentThreadId`(App 699-703) 跨视图聚焦跳入。**后端正重点优化这层、前端也已配套改了不少。** 原型的智能体页只是静态表格。**落地铁律：原型只接管"列表/卡片的视觉与信息架构"，真实会话读取/分页/跳转/渲染整条链路原样保住、挂进新外壳。**
4. **首页"变更"列：无数据源。** 先占位，还是立项做 change-feed（要新增"上次访问时间"基线 + 读模型）？建议先占位。
5. **项目页 3 格状态条：是新建。** 确认就要这 3 个字段（阶段/harness/启用技能）、且接受从画布侧栏上提派生。
