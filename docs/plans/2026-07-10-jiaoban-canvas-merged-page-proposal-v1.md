# 提案:交办·画布合一页(绑定前置+阶段自适应)v1

日期:2026-07-10 · 性质:**提案(方向用户已认「可以」·分片颗粒度未拍·未拆包)**。来源:用户 07-10 真机走完绑定面板后的构想原话——「把交办页和工作流页面合并:上方交办、左侧交办历史默认折叠、下方对应方案的工作流;后面选对话就在节点里操作」+ 担心「UI 会挤」;总指导补齐形态并经用户认可。

## 0. 一句话

**交办与工作流合成一页:图只画一次(画布预演节点),会话在节点上选,绑定在点[允许并开始]之前就绪(停点面板退成 fallback),交办区与画布按阶段轮流当主角——批时卡为主、干时图为主。**

## 1. 为什么(三个真痛·全是 07-10 真机撞的)

1. **绑定时机不对**:包3 的「批准→拆完→停面板」让[允许并开始]不像开始(点了又被拦一道)——用户原话「应该在点开始前就做好绑定」;
2. **同一张图画两次**:授权卡里的工序图(纵向步骤流)和画布任务节点(跑起来才出现)是同一份「所批即所跑」的图,两处画、两处维护;
3. **交办页和工作流页来回切**:干活时看逐格亮要在交办页、看节点依赖要切画布,一单活两个页面。

## 2. 形态(方向已认)

### 2.1 布局(三区)
- **左**:交办历史,默认折叠成窄图标条(点开=现左栏);
- **上**:交办区(说/批/干/交货/卡住 五态照旧·授权卡瘦身=文字要点+按钮·工序图不再卡内画);
- **下**:工作流画布(现有画布组件·方案出来即长出**任务预演节点**)。

### 2.2 阶段自适应主区(解「挤」的核心)
同一时刻只有一个主角:**说/批** = 交办区高、画布矮条(预演节点一排);**干** = 交办缩成状态条(进度+[停下]),画布放大;**交货/卡住** = 交办回主位。历史折叠 + 画布保留现有全屏 HUD(要细看一键放大)。

### 2.3 绑定前置(替包3 停点)
- 方案生成 → 画布同步长出预演节点(方案步骤级·「批的就是这份图」标注挪到画布);
- 每节点默认「新会话」(canon 默认·一眼可见);想接旧对话 → **点节点**弹现成会话选择器;
- [允许并开始] = 绑定映射随批准一起提交 → 直接跑**零停点**;
- 主管拆出任务按步骤继承映射;对不上/重拆的任务默认新会话不继承(已拍规则);**包3 后端资产全保留**(映射命令/校验/不回落/existing 逐任务绑),变的只是采集时机;停点面板降级为 fallback(任务与预演对不上时才弹)。

### 2.4 死线(设计红线)
- **人闸庄重感**:[允许并开始]常驻交办区、始终是页面最清楚的动作,不淹进画布;批前画布节点**只能改会话,不能改任务内容**(否则「所批即所跑」语义散);
- 五态词表/黄牌哲学/永不冻死配对全保留;人闸/冻结核/审计 0-diff 思维照旧;
- 只读单(`tasks/2026-07-10-advice-only-to-readonly-run-v1.md`·独立包)与本提案正交:只读单也走预演节点+绑定。

## 3. 分片建议(每片独立真机验·顺序待拍)

- **M1·预演节点+绑定前置**(后端小·前端中):画布在方案阶段渲染预演节点(带会话标);节点选会话;批准提交映射(复用包3 确认命令);停点降 fallback。——**不动布局**,先把「点开始前绑好」兑现。
- **M2·布局合并**(前端为主):交办区+画布进同一页,阶段自适应主区;历史折叠条;工作流 tab 保留只读入口过渡。
- **M3·工序图退役+授权卡瘦身**:卡内步骤流删除(图归画布)、授权卡剩文字要点+按钮;词表巡检。

M1 先行的理由:它独立兑现用户最痛的「绑定时机」,不赌布局改版;M2/M3 依赖 M1 的预演节点。
