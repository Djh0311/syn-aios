## 拍板摘要（先读这段）

- **批的是什么**：把 Xuanji 提炼的 UI 功能候选（原 backlog「全部待议」）按「**什么时候能加**」分三批——挂在已定阶梯：甲·中转 → 乙·工作流连环 → 多软件接入；并给每条标「**前后端怎么分工**」（三类）。
- **代价**：一份排期表；以后开对话照它派活，不用每次重想。
- **边界（关键）**：**本表只定 UI 归属 + 分工节奏**。每批背后的「真实能力（后端机制）开发」**另行排期**，不在本表拍板。所以「第一批」≠「马上做」，而是「甲 relay 跑通后这批才有附着点」。
- **不批**：不解锁真实执行、不改任何安全闸、不动 relay 实现包死线。

## 一句话判据

判一条 UI 功能现在该不该动手——问：**「它在哪一批（甲/乙/多软件）？承接它的真实能力到位了吗？它属于【后端做 / 前端开 / 先定接口】哪类？」** 三问齐了才开工；缺真实能力或缺接口约定 → 登记排期、不抢跑。

## 1. 边界：这表定什么、不定什么

- **定**：每条 UI 功能的【批次】+【前后端分工类型】。
- **不定**：真实能力（后端机制）的开发排期——那是另一条线，按甲/乙阶段推进时单独排。
- **原则**：UI 体验默认往丰富站（见记忆 `feedback-engineering-vs-product-instinct`：聊体验别用性能直觉砍）；但**没有真实能力承接的 UI 不抢跑**，免得做出空壳。

## 2. 分工三类（怎么分活，不踩「劈两半」坑）

- **【后端做】**：后端一条线做完，前端只贴现成壳显示一下——不必专门开前端对话。
- **【前端开】**：前端单独开个对话即可，后端没活（或已有）。
- **【先定接口】**：前后端都重、契约复杂，硬拆会被劈成两半（两个对话互相看不见、约定漂移、用户被迫当唯一人肉同步线）。**必须先写一张「接口约定」文件**（数据字段 / 回传格式），或一个对话从头做到尾。

> 为什么不是简单两类（前端/后端）：按前后端竖切会把一条功能从腰上劈两半，扔进两个互相看不见的对话，契约漂移，用户成传话员。这正是 Syn（任务包 / outbox / 统一记忆层 / 主管角色）要自动化解决的事——dogfood 的活证据。

## 3. 第一批 · 跟着甲·中转（relay）跑起来

〔附着前提：甲让用户能真把消息发给 Codex、它真跑。「干活过程中的人机互动」才有地方挂；之前没真执行，这些都是空的。〕

| # | 功能 | 分工 | 说明 / 卡点 |
|---|---|---|---|
| 1 | 计划审查门 | **先定接口** | 后端让 Codex 先吐计划、停下等裁决；前端弹窗 + 批准/驳回/**补充意见**。卡：甲 relay 能否中途暂停双向交互；契约（计划结构 + 裁决回传）等 relay 跑通再定。 |
| 2 | Ask-User 反问 | **先定接口** | agent 卡住发问 → 用户答 → 塞回继续。与 1 一对，一起定接口。同卡 relay 双向交互。 |
| 3 | 插话分诊 | **后端做** | 判「打断/补充/排队」+ 控制在跑任务，主要在后端（正则秒判兜底 LLM）；前端只加个小提示。 |
| 4 | 对话回滚（快照） | **前端开** | 纯前端做**对话层**快照/列表/退回某步。注：只退对话，不退「已让 Codex 改过的真实文件」（那种危险，relay 包本就保守处理，不在此条）。 |
| 5 | 底部状态栏 | **后端做** | 任务数/异常/待确认/token·成本 = 后端状态，聚合成一个接口；前端贴一条常驻栏。 |

**第一批现在能立刻分头开干的 3 条**：
- 后端线 → **3 插话分诊**、**5 状态栏**
- 前端单开 → **4 对话回滚**
- 2 条卡住（**1 计划审查**、**2 Ask-User**）：等甲 relay 跑通 + 咨询线与用户定一张「接口约定」文件再开工——这俩最容易劈两半，别抢跑。

## 4. 第二批 · 跟着乙·工作流连环 + 记忆层有料

现在**别细排前后端**（能力没影、契约没定，细排是空中楼阁）。到乙启动前再排。

- 偏纯前端、可「先搭空壳玩」（读现有数据先显示，有料等后端）：**记忆图谱、token 占用条、@ 寻址、路由解释条**。
- 其余全【先定接口】且等乙：**编排策略选择、节点状态可视（含日志时间线）、权限页、System Prompt 面板、调度页（Cron）**。
- 背后机制（9 状态 / 消息排队 / worktree / 异步任务存储）跟着乙一起，不单拍 UI。

## 5. 第三批 · 多软件接入之后

现在 Syn 只编排 Codex 一个；这批都是「管多个外部软件/会话」的，得先真接入别的才有意义。**不排。**

- 渠道 / 远端会话（IM：微信/企微/飞书/钉钉）、市场页（Skill/MCP，只取自用 + 权限 + 审计，不要社区评分）、本地资源诊断。

## 6. 不做 / 已并

- **本地模型下载管理** → 砍（云端编排 Codex，不在本机跑模型；真要本地模型再议）。
- **执行图交互增强** → 并入「工作流画布重做为无限画布」条，不单列。
- **聊天虚拟列表 / 流式分离 / 回到底部** → 已做（2026-06-17 会话引擎，commit `b56bad8`）。
- **不建议（保持砍）**：Skill 市场社区评分、50/50 聊天分屏当首页、AI 管家人设、把任务/异常/权限/通知都塞进聊天流。

## 7. 与蓝图关系

不偏离：第一批挂甲、第二批挂乙，与既定阶梯一致；乙（工作流连环的角色编排）仍是蓝图核心。本表**只排 UI 顺序与分工**，不改治理 / 角色 / 安全结构。
