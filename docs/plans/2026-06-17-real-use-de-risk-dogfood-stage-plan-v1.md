## 拍板摘要（先读这条）

- **要批的事**：花一个小阶段，**拿一个真项目、在工作台里真用一遍，真写进第一条真实记忆**；顺手记下「驾驶舱顺不顺手」喂给 UI 那条；最后给「要不要开 B（真指挥 Codex）」出一个**用过之后**的去/不去结论。
- **代价**：基本是你在自己 Mac 上**真用一阵**（我负责出计划、帮你搭场子、事后核实物）；几乎不写代码，除非真机第一次走真路径时卡住，才另开一个窄小任务补。
- **不批的后果**：记忆层永远 0 条真数据、全靠 fixture（假数据）撑着，L5 收不了口；UI 改没有真内容可对照，又在对着假数据调；「要不要开 B」只能凭感觉拍，而不是凭一次真用过的体感。
- **零解锁**：全程**不开真 Codex（K3-B1/B2 维持封死）、不切真库（R3 的 C 维持后置）、不真 retry/stop/restart/resume**。可逆、低风险。

## 一句话判据

判一件事算不算本阶段该做的——问：**「它能不能在不解锁任何真实执行的前提下，用真内容把工作台走一遍、并产出第一条真记忆？」** 能就做；要解锁（真 Codex / 真库切换）才能做的，一律不在本阶段。

## 1. 为什么是这个阶段（去险逻辑）

- 现在**真实正式记忆 0 条、全是 fixture**——工作台到底能不能拿来真用，其实从没验过。
- 你介意的是**布局/UI**（已交给另一对话）；那条改起来需要**真内容**对照，否则还是在对着假数据调。
- 这一步**不碰任何封印**就能：① 给 L5 兑现它真正的完工线（「真写进一条真实记忆」）；② 给 UI 那条喂真摩擦点；③ 给「要不要开 B」出一个用过之后的结论。
- 它也正是上一轮聊的、**打破「先有鸡先有蛋」错觉的那颗种子**：先用非执行的真用，产出第一批真数据。

## 3. 不做（维持所有安全锁）

- 不开真 Codex 执行（K3-B1 / K3-B2 维持封死）。
- 不切真库（R3 的 C 维持后置）。
- 不真 retry / stop / restart / resume。
- **不为了打勾硬造一条合成记忆**——必须是**真项目里掉出来的真记忆**（这是你自己的原则）。
- 不读 `/Users/yoyi/.codex` / secret / token / 凭据等。

## 4. 步骤（三步，小阶段）

### RU1 · 真机跑通 + 真项目落地
- 你在 Mac 上 `tauri dev` 把工作台真打开（我这环境跑不了，这步必须你来）。
- 选**一个真实的小项目**（选型见 §5），在工作台里建成一个**真·非 fixture 项目**，排个工作流骨架——**只当结构/计划，不执行**。
- **关键去险点**：确认「建真项目 → 真落盘 → 重开还在」这条**非 fixture 真路径**真能走通（以前全跑 fixture，这条很可能是第一次走）。卡住就停下、记下来，我再判断要不要开个窄小任务补。

### RU2 · 走日常 + 真写一条记忆
- 在这个真项目上真做点事 / 真想点事，把真实的判断**捕成观察 → 候选 → 经 M2 确认门采纳成 1 条（最多三条）真实正式记忆**。
- **核实物（我来）**：确认这条记忆是**真的、带真来源、不在 fixtures 目录下**——这才算兑现 L5 的完工线。

### RU3 · 去险结论
- 出一份短**真用结论**：① 驾驶舱拿来真用顺不顺手、卡在哪（**摩擦清单交给 UI 那条**）；② L5 完工线是否达成、可否收口；③ **要不要开 B、什么时候开**的去/不去建议。
- 把结论喂给 L6（Stage L 最终冻结）。
