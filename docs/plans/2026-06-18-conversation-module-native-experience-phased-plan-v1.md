## 拍板摘要（先读这段）

- **这是什么**：把"对话模块"做到 codex/claude 原生体验的分阶段开发计划。
- **范围（用户 2026-06-18 拍板）**：**只做对话模块**（不翻整 app）· **Codex-only**（claude/多软件按总路线图后续）· **回复整段出现**（真流式列为下一阶段、本轮不做）· **任意已有对话可发 + 能新建对话**。
- **为什么要重做**：现状不是"对话模块"，是「只读历史查看器 + 发完不回头的发送器」拼在一起。三条硬伤：① 只有带项目路径(cwd)的对话能发 → 满屏会话只一条亮、其余全灰；② 发完 codex 回复不回显到界面；③ 发完 UI 卡死在 running、输入锁死发不了下一句。补丁救不了，按阶段重做对话回路 + 原生化。
- **代价**：4 个阶段（核心回路 → 新建对话 → 原生打磨 →〔下一阶段〕真流式）。每阶段一个任务包，走治理：执行角色实现 → 独立复核 → 咨询线审实物 → 用户拍板才 commit。
- **谁干**：咨询秘书（我）统筹 / 拆任务包 / 复核把关；**实现交执行角色（Codex/子线），我不亲自埋头写代码**。
- **不批 / 不碰**：不解锁 relay 以外的真实执行；不动 sandbox / 审批 / 限项目这套**命根子**；不碰记忆层 / 工作流 / 底座 / 旧安全闸。
- **设计总则（用户 2026-06-18 拍板）**：所有对话功能**照搬 codex 原生行为**——任何设计取舍一律「codex 怎么做就怎么做」，不自创、不另想方案；新建对话也照搬 codex 的新会话模型。
- **已定决策点**：① 在飞 spike → **已还原工作树**（不作数）；② 新建对话细节 → **照搬 codex**（不再单独问，按 codex 实际行为做）。

## 0. 现状与事实底牌（计划基于此，非猜测）

本轮真机实测 + 读码已确认（作为设计输入，不再调试）：

- **relay 后端整条链是通的**：用户在真桌面 app 点发，codex 真启动、真收消息、真回复，回复落在工作台管理的 `last-message.txt`（实测："收到，中转测试正常。"）。**所以后端"把话送到 codex 并拿回回复"的能力已具备**，缺的是把它接回界面。
- **三条硬伤定位**（见拍板摘要）：根因——(①) 绑定要求对话有 `project_root`(=cwd)，无 cwd 的对话被置灰（`deriveRelayBindingState`）；(②③) GUI 直发走"起进程→回 running→不管了"，全仓库无"完成检测/回复读回"通路，唯一能解锁的是名叫"Stop"的按钮。
- **在飞 spike**：咨询线越位手改过一版（后端加 poll/读回命令 + 回执带回复文本，16 测通过；前端加轮询回路 + 干净撰写区）——**未验通（回复仍没回显）、未提交、不作数**。其暴露的缺陷与候选机制写入下方各阶段供执行参考；spike 本身按 ⟦待定①⟧ 处置。

## 1. 分阶段（每阶段：做什么 / 前后端分工 / 能用判据）

> 分工三类沿用 UI 批次表：【后端做】【前端开】【先定接口】。对话回路前后端都重 → 关键步必须**先定接口**，防"劈两半"。

### Phase 0 · 定接口契约 + 清在飞（前置小步）

- **定一张「对话回路接口约定」**（**先定接口**，最易劈两半，必须先写）：
  - 读：对话历史从哪读（复用现有 codex rollout transcript 引擎）。
  - 发：消息怎么投给 codex（resume 指定会话 / new session 的命令契约、字段）。
  - 回：codex 回复怎么回来（完成检测 + `last-message` 读回；是否再重读 rollout 取"规范线程"）。
  - 状态机：草稿 → 发出 → 运行中 → 完成/失败/停止；输入锁定与解锁的确切时机。
- **建立「codex 原生行为参考基线」**：摸清真实 Codex（用户已装 `com.openai.codex`）在「发消息 / 新建会话 / 回复与思考·工具渲染 / 运行·停止状态 / 会话列表切换」上的实际行为，作为本计划"照搬 codex"的规格底本——后续每个设计点都对照它，不自创。
- **在飞 spike 已还原**（用户拍板还原、不作数）；其暴露的缺陷 + 候选机制(poll/读回)写进 Phase 1 任务包供执行参考。
- 产出：①「对话回路接口约定」契约文件 ②「codex 原生行为参考基线」。**前后端此后都依此契约 + 基线，不各排各的、不自创。**

### Phase 1 · 核心回路：任意会话可发 + 回复回显〔最高优先，杀三条硬伤〕

- **后端【后端做】**：
  - 放宽绑定：**每条 codex 对话都可发**——为缺 cwd 的对话推导/补一个工作目录（或发送时定），不再因无 `project_root` 置灰。
  - 完成检测 + 回复读回：发出后能得知 codex 跑完并取回回复（候选=spike 的 `poll` 命令，重做 + 测）。
  - **不动 sandbox/审批/限项目。**
- **前端【前端开】**：发送 → 乐观显示你的消息 → "codex 运行中（可停）" → 完成把回复落进对话 → **自动解锁** → 可再发；撰写区去开发者字段墙。
- **能用判据（真机验收）**：任挑一条 codex 对话，发一句，**看见自己消息 + codex 回复落进对话、输入解锁、能连发第二句**。三条硬伤全消。

### Phase 2 · 新建对话

- **照搬 codex 新会话模型**：codex 自己怎么起新会话、怎么定工作目录，就怎么做（按 P0 摸到的 codex 行为基线落地，不自创 folder-picker UX）。
- **后端【后端做】**：new-session 真发（放宽 GUI 直发命令收 new_session，**复用同一套安全壳**）。
- **前端【前端开】**："新建对话"入口；新会话起好后成为当前线程、可连聊。
- **能用判据**：点新建 → 发 → 得回复 → 该会话真落盘、能在会话列表里再找到并续聊。

### Phase 3 · 原生质感打磨

- **前端为主【前端开】+ 少量后端【先定接口】**：
  - 规范线程：发完重读该会话 rollout，显示真实往返（去重乐观气泡），而非只贴乐观条。
  - 消息渲染到原生：markdown / 代码块 /（rollout 内有的话）工具调用·思考摘要。
  - 会话列表/切换/新建的原生交互；停止/重发；错误态/空态/加载态；撰写区（多行、快捷键）。
  - 清掉所有残留开发脚手架。
- **能用判据**：与 codex/claude 并排，对话这块体感"像原生聊天"（你主观验收 + 一份具体清单逐条过）。

### Phase 4 ·〔下一阶段，本轮不做〕真流式

- 逐字流式 + 中途思考/工具调用可见。要把 codex 的流式输出真接出来（现状 stdout 被丢弃，工程量大）。按你拍板本轮不做，列为紧接的下一阶段、单独排期。

## 2. 横切关注点（贯穿各阶段）

- **安全**：relay 安全壳一寸不动（sandbox=workspace-write + 限项目 + 拒审批绕过）；new-session 复用同壳；不解锁其他真实执行；不碰记忆/工作流/底座/旧闸。每阶段任务包重申命根子边界。
- **治理**：每阶段 1 个任务包 → 执行角色实现 → 独立复核线 → 咨询线审实物 → 用户拍板才 commit；子线不 commit。咨询秘书（我）统筹拆包、复核、把关，不亲自实现。
- **真机验收硬规矩**（本轮教训）：每阶段"能用判据"**必须在真桌面 app 上当你面验通**，才算完工——不再 offline 测完就报。
- **与总路线图关系**：本计划 = master-roadmap 的 **A线③b-2「GUI 真用」+ B线「对话部分」** 的聚焦细化与重排（把原本分开的两条线拧成"对话原生"一个目标）。推进时把状态回写 `master-roadmap` 与 `CURRENT.md`，保持"说的=写的=做的"。
- **Codex-only**：claude / 多软件按总路线图后续阶段，本计划不含。
