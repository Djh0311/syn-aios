## 0. 一句话
让工作流**按图（拓扑序）从一句命令起、自动逐节点连跑到底**，圈死固定测试项目、四护栏兜底。人在环 = **起链那一下 + 随时可中断**（已按用户拍板去掉逐步审批）。原设计的"链自动·放行手动"已变成"链自动·放行也自动、只靠圈测试项目 + 四护栏压住"。

## 1. 阶梯定位
- **甲·手动中转（已收口）**：用户绑会话、一次手动发一个节点给 codex（唯一真指挥 codex 的路径，`manual_relay`）。
- **中间·半自动（本设计·已落地）**：用户一句命令起链，系统按工作流图**自动逐节点连跑到底**（已去逐步审批），圈死固定测试项目、四护栏兜底、随时可中断。= 把「跑一个工作流」的体验给到。⚠️ 去掉逐步审批后，本台阶实质已贴近乙、只靠"圈测试项目 + 四护栏"压住风险。
- **乙·自动连环（终局，高危#4，锁着）**：主管对话「按计划开干」（真·NL）→ 放开非测试项目 + 重护栏拧到生产 + 明确授权。开它要把对应重闸全加回来。

## 2. 中间·半自动 是什么（已落地，按"直接全跑"对齐）
- **链驱动 controller**：读项目工作流（画布节点 + 边 + run-check），按依赖序（拓扑序，确定性 Kahn 变体）走图。
- **每个可跑节点**：① 解析会话（resume，per node）② 过 run-check（可跑？）③ runaway 上限 + stop 标志检查 → ④ 调**现有 gated `execute_project_workflow_node`**（双闸 + 沙箱 + 自动临时 work_item）真派发 → ⑤ 完成 → 推进到下一个 / 失败 → **链停**（不自动重试、不跳过）。**无逐步审批**（已按用户拍板去掉；原"审批卡"流程作废）。
- **链状态进 workflow-state**：`workflow_chain_runs` 记当前节点、pending / running / completed / failed、stop_requested、max_nodes，持久化（支持断点续）；链经**状态机 + 权限**推进，不靠聊天绕过改状态（principles §4）。
- **对话启动（P2）**：用户在发令台打「按计划跑工作流 W」→ controller 启动链（**自动连跑到底**）。对话 = 发令台 + 定范围（只启动 / 停、不改状态）；真跑仍走状态机 + 闸。**这是「一句话启动」的第一步**——现为固定命令格式，真·自然语言 + 主对话留给乙。

## 3. 安全护栏（去逐步审批后，靠这四条压住）
> ⚠️ 原"每真执行步人明确批准"是本设计当"中间"的核心闸；用户拍"直接全跑"后**该闸已撤**，本设计跨进高危#4。剩下四护栏是**仅有**的安全，必须硬：
- **① runaway 上限**：单链最多派发 min(节点数, 硬顶 50)、拓扑序每节点最多一次、失败即停不自动重试——防自动连环跑飞（即便在沙箱内）。
- **② 可中断**：stop_requested 标志，每个节点边界检查 → 停。
- **③ 审计**：链起 / 续、每节点 start·done·fail、链停 / 完成 / 失败 全进 `audit_events`。
- **④ 可回滚**：测试项目 git 可回滚 + 起链前 backup。
- **只打固定测试项目**（path-lock，高危#1 轻档）；**非测试真实项目仍锁死**（高危#1 不动）。
- **每节点派发走现有双闸 + 沙箱**（`codex_local_runner` 不动、不新开闸、不绕）。
- **不靠聊天绕状态**：对话只能「启动 / 停」，状态改经状态机 + 权限（principles §4）。

## 4. 为「乙」铺路（本设计建的、乙 复用）
去掉逐步审批后，本设计与乙的差距已很小——乙 主要剩「明确授权 + 重护栏拧到生产档 + 放开非测试项目 + 真·NL 主对话」：
- 链驱动 + 依赖序（拓扑序）走图；
- per-node 状态机（pending / running / completed / failed）+ 持久化（`workflow_chain_runs`，支持断点续）；
- 可中断 / 审计 / 回滚 / runaway 上限 的基础设施；
- 对话启动（发令台）+ 定范围。
→ **乙 = 本设计 + 明确授权那一下 + 重护栏拧到生产 + 放开非测试项目（另一道明确授权）+ 真·NL 主对话启动。** 注：真·多智能体编排（数据传递 + 主管派活）是另一条线（#20、四角色引擎），不在本阶梯的"放行"维度上。

## 5. 接现有件（grounded）
- **真派发**：复用 `execute_project_workflow_node`（已 gated、resume 会话、自动临时 work_item）——链每节点调它，不旁路。
- **计划书**：项目画布（节点 + 边）= 工作流图；run-check = 节点可跑判据。
- **状态**：workflow-state（nodes / edges / work_items / bindings / dispatches + 链状态 `workflow_chain_runs`）。
- **注（已定）**：存在一个**锁着的四角色多节点编排引擎**（`workflow_execution_entrypoints.rs`，stub 测过、无真 runner，见 CURRENT ④a）。本设计**没用它**——实际新写了薄 controller `workflow_chain_controller.rs` 复用走图逻辑 + 复用已 gated 的单节点派发。那个四角色引擎留给 **#20 真编排**（节点间传数据 + 主管真派活 + 审查复核产出）当底座，另起设计。

## 7. 决策点（已全部拍定，见顶部「决策更新」）
- **审批粒度**：→ **直接全跑、无逐步审批**（圈测试项目兜底）。
- **对话启动的范围**：→ **整条工作流**；对话**只能启动 / 停**、不改状态（已实现，正则只认起 / 停）。
- **中断后恢复**：→ **断点续**（已完成节点跳过、被中断的半截节点重跑、往下接）。
- **失败处理**：→ **链停 + 用户定**（不自动重试 / 跳过）。
