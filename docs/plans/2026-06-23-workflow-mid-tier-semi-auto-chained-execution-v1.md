## 0. 一句话
让工作流**按图自动推进到下一个节点，但每个真执行步都停下等人点「批准」**——系统自动准备、人逐步放行。介于「甲·一次手动发一个节点」和「乙·一句话全自动跑完」之间：**链是自动的，放行是手动的。**

## 1. 阶梯定位
- **甲·手动中转（已收口）**：用户绑会话、一次手动发一个节点给 codex（唯一真指挥 codex 的路径，`manual_relay`）。
- **中间·半自动（本设计）**：系统按工作流图自动走到下一个可跑节点，**停下、给用户看「下一步：跑节点 X」、用户批准才派发**，完成后自动推进到下一个。= 把「跑一个工作流」的体验给到，但每步真执行有人在环。
- **乙·自动连环（终局，高危#4，锁着）**：主管对话「按计划开干」→ 自动跑完、无逐步放行。开它要重护栏全加回来 + 明确授权。

## 2. 中间·半自动 是什么
- **链驱动 controller**：读项目工作流（画布节点 + 边 + run-check），按依赖序走图。
- **每个可跑节点**：① 解析会话（resume，per node）② 过 run-check（可跑？）③ **暂停 → 浮出「下一步：跑节点 X」审批卡**（目标 = 固定测试项目、沙箱模式、会话、指令预览）→ ④ 用户批准 → 调**现有 gated `execute_project_workflow_node`**（双闸 + 沙箱 + 自动临时 work_item）真派发 → ⑤ 完成 / 失败 → 推进到下一个 / 停。
- **链状态进 workflow-state**：当前节点、待批准 / 运行中 / 完成 / blocked，持久化；链经**状态机 + 权限**推进，不靠聊天绕过改状态（principles §4）。
- **对话启动（P2）**：用户对话说「按计划跑工作流 W」→ controller 启动链（**但仍逐节点停下等批准**）。对话 = 发令台 + 定范围；真跑仍走状态机 + 闸 + 逐步放行。**这是「一句话启动」的第一步，带逐步放行的安全。**

## 3. 安全护栏（为什么是「中间」不是「乙」）
- **每个真执行步 = 人明确批准**（核心闸）——无「无人值守自动连环」，故**不碰高危#4**。
- **只打固定测试项目**（path-lock，高危#1 轻档）；非测试真实项目仍锁。
- **每节点派发走现有双闸 + 沙箱**（`codex_local_runner` 不动、不新开闸、不绕）。
- **可中断**：用户随时停链。**可回滚**：测试项目 git 可回滚 + 写前备份。**审计**：每步记审计事件。**边界**：每节点 sandbox / scope 限定。
- **不靠聊天绕状态**：对话只能「启动 / 停」，状态改经状态机 + 权限（principles §4）。

## 4. 为「乙」铺路（本设计建的、乙 复用）
中间·半自动建好这些，乙 几乎就是「把逐步放行换成自动放行 + 明确授权 + 重护栏拧到生产档」：
- 链驱动 + 依赖序走图；
- per-node 状态机（待批准 / 运行 / 完成 / blocked）+ 持久化；
- 审批卡 / 可中断 / 审计 / 回滚 的基础设施；
- 对话启动 + 定范围。
→ **乙 = 本设计 + auto-approve（去掉逐步放行）+ 明确授权那一下 + 重护栏拧到生产 + 放开非测试项目（另一道明确授权）。**

## 5. 接现有件（grounded）
- **真派发**：复用 `execute_project_workflow_node`（已 gated、resume 会话、自动临时 work_item）——链每节点调它，不旁路。
- **计划书**：项目画布（节点 + 边）= 工作流图；run-check = 节点可跑判据。
- **状态**：workflow-state（nodes / edges / work_items / bindings / dispatches + 新增链状态）。
- **注**：存在一个**锁着的四角色多节点编排引擎**（`workflow_execution_entrypoints.rs`，stub 测过、无真 runner，见 CURRENT ④a）——中间·半自动可在其上**接真 gated runner + 加逐步审批**解封，或新写薄 controller 复用它的走图逻辑。择一，实现时定。

## 6. 分期
- **P1 链驱动 + 状态机 + 手动「下一步」**：无对话启动；用户在画布点「开始链」→ 每节点停下审批卡 → 批准派发 → 推进。全程测试项目、逐步放行。验：cargo + 真机跑一条多节点链（每步批准、codex 真执行、只动测试目录）。
- **P2 对话启动**：对话「按计划跑工作流 W」→ 启动链（仍逐步放行）。发令台 + 定范围；不绕状态机。
- **P3 = 乙（后置、另立）**：auto-approve + 明确授权 + 重护栏 + 放开非测试项目。**不在本设计实现范围。**

## 7. 决策点（待用户 / 后续定）
- **审批粒度**：每个节点都停，还是只在「真执行 / 写 / 高风险」节点停、纯读节点放行连跑？（越粗越接近乙、越要小心）
- **对话启动的范围**：「跑整个工作流」vs「从节点 X 跑到 Y」；对话能不能改计划（应只能启动 / 停、不能聊天改状态）。
- **中断后恢复**：停在中途，从断点续还是重来。
- **失败处理**：某节点失败 → 链停 / 跳过 / 重试？

## 8. 不在本设计
- **乙 的 auto-approve / 无人值守连跑**（高危#4，P3 另立 + 明确授权）。
- **真跑进非测试真实项目**（高危#1，仍锁）。
- **多项目接力**（高危#4 的一部分）。

## 验证
- 机器：cargo（链状态机 + 每节点经双闸）/ typecheck / offline / build。
- 真机（必做）：画一条多节点工作流 → 起链 → 每步批准 → codex 真执行、只动测试目录、链推进到完成；中途停 / 恢复；某步失败的处理。**机器绿 ≠ 真机。**
