## 0. 一句话目标

把「运行中工作流」从“运行统计仪表盘”改成“工作流执行画布”：打开页面先看见流程跑到哪、哪个节点在干活、右侧为什么是这个状态，而不是先看一堆 0 指标卡。

## 1. 背景与依据

用户给了两张对比图：

- 目标图：画布优先。顶部是工作流标题和状态摘要；中间是节点流程图；右侧是当前节点详情；底部是模式切换和操作按钮。
- 现状图：指标卡优先。首屏大量统计卡、运行队列卡、记忆候选卡，像后台监控页，不像工作流执行页。

结论：这不是局部视觉微调，而是页面信息架构错误。当前页面在回答“有多少东西”，目标页面要回答“当前工作流走到哪一步”。

## 2. 产品目标

用户打开「运行中工作流」后，一眼能知道：

1. 当前工作流叫什么。
2. 属于哪个项目/主管/模型/子智能体配置。
3. 节点进度到第几步。
4. 哪个节点正在执行。
5. 上下游节点是什么。
6. 当前节点为什么是这个状态。
7. 是否有阻断、违规、证据缺口、读回异常。
8. 下一步能做什么。

## 3. 非目标

- 不新增真实执行能力。
- 不自动触发 runner。
- 不扩大 guard / sandbox / relay 权限。
- 不把空数据伪造成真实运行结果。
- 不把项目工作流详情页、智能体页、首页一起重构。
- 不做拖拽编排编辑器；第一版只做执行态/只读态画布。

## 4. 现状问题

| 问题 | 现状表现 | 影响 |
|---|---|---|
| 主对象缺失 | 页面没有明确的“当前工作流”作为视觉中心 | 用户不知道自己正在看哪条流程 |
| 指标过重 | 首屏是 0/统计卡网格 | 像监控后台，不像执行工作台 |
| 流程关系不可见 | 队列、读回、记忆候选是散卡 | 看不到它们属于哪个节点 |
| 当前节点不突出 | 没有“正在执行节点”的视觉锚点 | 难判断下一步关注哪里 |
| 详情无归属 | 右侧/下方信息堆叠 | 用户要自己拼上下文 |

## 5. 目标界面结构

### 5.1 顶部：工作流标题区

顶部不做卡片，做页面标题栏。

左侧：

- 小字：`CANVAS · 工作流画布`
- 大标题：当前工作流名，例如 `UI 蓝图收口`

右侧：

- 项目名
- 节点进度，例如 `节点 4 / 6`
- 运行时长，例如 `12m`
- 主管/模型/子智能体数量，例如 `项目主管 Codex · opus · 2 子智能体`

### 5.2 第二行：运行状态带

标题下方加一条细状态带，横向显示最关键系统口径：

- harness：例如 `codex-strict`
- 运行性：`可运行 / 阻断 / 待确认`
- 违规数
- 证据完整度
- 当前链路：例如 `主管 → 子 · UI 卡牌`
- 当前视图：`运行状态`

这条状态带替代当前大面积 summary card。

### 5.3 主体：左画布 + 右详情

主体采用左右结构：

- 左侧约 70%：工作流节点画布。
- 右侧约 30%：当前节点详情栏。

左侧节点画布：

- 节点以卡片形式展示，按流程空间排布（参目标图：上排 设计咨询 → 项目主管 → UI 卡牌 → 审查智能体；下排 待决策 / 阶段汇报）。
- **用连线表达上下游关系**（用户已确认要连线）：连线画出「谁先谁后 / 主管派给谁 / 谁等谁完成」，整条流程走向一眼可见。当前执行段连线加重 / 着色，已完成段弱化，未到段虚线。
- 顶部再配一条**阶段进度段带**（参目标图顶部彩色线段）：每阶段一小段横线，按状态着色（已通过深实线 / 执行中红实线 / 未开始灰虚线）。与连线互补——**连线表「关系」，段带表「进度」**。
- 当前执行节点用更重边框 / 状态点 / 进度数字（参目标图 UI 卡牌：红框 + 「执行中 68%」）。
- 已通过节点弱化但保留可读性；未开始节点低强调。
- 待决策 / 阻断节点用暖色状态点，不只靠颜色，还要有文字。

第一版节点固定布局，不做自由拖拽（连线随固定布局画）。

### 5.4 右侧：当前节点详情栏

右侧只解释当前节点，不再做杂项堆叠。

建议字段：

- 状态：执行中 / 等待 / 阻断 / 未开始 / 已通过
- 会话：软件 + 角色 + 任务域
- 模型
- 技能
- 知识库
- 工具
- 验收
- 审查要求
- harness

原则：右栏每一行都回答“当前节点为什么安全/为什么能跑/为什么卡住”。

### 5.5 底部：模式切换 + 操作区

底部左侧做 segmented control：

- 运行状态
- 建议方案
- 手动编排

底部右侧放操作按钮：

- 展开任务包
- 暂停

第一版按钮可以沿用现有安全动作；没有真实动作时只做只读/禁用/跳转，不伪造能力。

## 6. 现有信息如何迁移

| 现有内容 | 新位置 |
|---|---|
| 工作流数量/运行关注/等权限/读回异常等指标卡 | 降级为状态带或右栏摘要，不再占首屏主体 |
| 运行队列 | 映射到当前节点状态或底部“运行状态”面板 |
| 失败控制 | 当前节点详情里的阻断/恢复建议 |
| 操作控制 | 底部操作区或右栏“审查要求” |
| 记忆待处理 | 对应节点的辅助状态；必要时放入右栏折叠 |
| 自动编排 | 作为节点链路或底部模式之一 |
| 读回异常 | 挂到相关节点，右栏显示“读回：未知/不可用/失败” |

## 7. 数据映射规则

优先级：

1. 有真实 `workflowState`：用真实 workflow / node / run summary 派生画布。
2. 有运行队列但无完整 workflow：生成只读运行链路，不声明完整工作流。
3. 有读回异常：挂到“当前关注节点”或右栏诊断。
4. 完全为空：显示空画布状态，不能显示成“0 条成功结果”。

空状态文案方向：

- “当前没有运行中的工作流。”
- “可在项目工作流中创建/打开工作流。”
- 不显示一堆 0 卡片。

## 8. 视觉原则

- 仍沿用当前水墨/纸面风格，不照搬 Codex 深色或其它产品配色。
- 目标图决定“布局骨架”，现有设计 token 决定“质感”。
- 避免卡片套卡片；页面主体是画布，不是 dashboard。
- **用连线表达节点上下游关系**（用户已确认要连线）；连线 + 顶部阶段进度段一起表达流程走向与进度。
- 节点卡可以有边框，但不要变成营销卡片。
- 字号密度偏工具型：标题明确，节点信息紧凑。
- 状态不能只靠颜色表达，必须有文字。
- 底部操作区要稳定，不因内容变化跳动。

## 10. 建议实施步骤

### P1 · 骨架替换

- 把 `RunningWorkflowsView` 首屏从指标卡网格改成标题区 + 状态带 + 左画布 + 右详情 + 底部操作。
- 保留原有数据读取入口。
- 不新增真实操作。

验收：首屏不再是 0 指标卡；能看见工作流标题、画布节点、右侧详情。

### P2 · 数据挂接

- 将 workflowState / run queue / failure boundary / readback summary 映射到节点和右栏。
- 空数据走空画布，不走 dashboard 0 卡。

验收：离线 fixture 和浏览器预览都能显示合理工作流；空状态不撒谎。

### P3 · 交互收口

- 节点可点击切换右侧详情。
- 底部三个模式可以先做前端态切换。
- 操作按钮按已有安全能力接入；无能力则禁用或只读。

验收：点击节点不会触发执行，只切换详情。

### P4 · 细节打磨

- 对齐目标图的密度、节点连线、顶部阶段进度段、节点间距、右栏行高、底部按钮。
- 响应式处理：窄宽度下右栏下移或折叠。

验收：桌面宽屏接近目标图结构；窄屏不横向炸裂。

## 11. 验证标准

自动验证：

- `npm run typecheck`
- `npm run test:offline-interaction`
- `git diff --check`

手动验证：

1. 打开「运行中工作流」。
2. 首屏中心必须是工作流画布，不是指标卡大盘。
3. 当前执行节点必须一眼可见。
4. 右侧必须解释当前节点。
5. 空数据不得显示成真实 0 结果。
6. 页面不得出现“自动执行已启用”“已成功”等未被真实数据支持的文案。
7. 点击节点只切换详情，不触发真实执行。

## 12. 风险与处理

| 风险 | 处理 |
|---|---|
| 真实 workflow 数据不足 | 做空画布/降级链路，不伪造完整工作流 |
| 旧测试依赖 dashboard 文案 | 更新测试期望到画布结构 |
| 用户以为按钮能真实执行 | 无后端安全能力时禁用或标明只读 |
| 画布变得像项目工作流详情页重复 | 本页只展示“运行中的当前态”，项目页仍是工作流管理/详情 |
| 信息再次堆叠 | 右栏只服务当前节点，统计信息不回到首屏 |
