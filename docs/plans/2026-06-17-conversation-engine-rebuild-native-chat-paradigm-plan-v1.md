# 方案：会话引擎重做（原生聊天范式 · 照 Codex/Xuanji 行为）v1

日期：2026-06-17

出自：咨询线（Claude）。性质：会话 / 对话引擎重做的**方案**（现状 → 目标 → 范围 → 分阶段 → 执行）。基于 2026-06-17 只读探测（我们现状 + Xuanji renderer 源码参照 + Codex/Claude 原生范式）。用户已确认参照足够，**具体视觉 / UI 显示由用户自己细调**。

## 拍板摘要

- **要做的事**：把会话 / 对话引擎从「后端分页 + 状态全量渲染」换成「**原生聊天范式**」（虚拟化 + 流式追加 + 滚动黏底 + 选中即显示 + 打字即发），达到 Codex / Claude 那种流畅。**不是再打补丁，是照现成范式重做前端引擎。**
- **代价**：一轮前端引擎重做（坐在现有后端分页地基上），分阶段、每阶段可验。
- **不做的后果**：会话页「用不了 / 卡 / 要重读 / 6 步发送」继续，真用走不动。
- **边界**：不碰真执行（甲，仍封）、记忆层、编排 / 画布、整体工作台布局（另一对话）；**视觉 / 显示细节是用户的细调区，本方案不硬定**。

## 一句话判据

判某改动在不在本方案内——问：**「是不是为了让『会话 / 对话』达到原生聊天范式（虚拟化 / 流式 / 黏底 / 选中即显 / 打字即发），且坐在现有只读元数据地基上、不碰执行 / 记忆 / 编排、不硬定视觉？」** 是 → 做。

## 1. 现状 → 目标（差距，2026-06-17 探测所得）

三家（Codex / Claude / Xuanji）是**同一套现代聊天范式**；我们是另一套。差距：

| 我们现状（实测） | 原生做法（Xuanji 源码坐实 + Codex/Claude 同款） | 对应痛点 |
|---|---|---|
| 消息**全量进 DOM**、无虚拟化（默认 12，展开全部全塞 → 卡 3-5 秒） | `@tanstack/react-virtual` 虚拟化 + 流式消息单独走自然流 | 消息太多卡 |
| 选中会话先 `transcript=null`、再**异步重读** rollout（等 1-5 秒） | 选中即载入历史 + **立刻渲染 + 自动黏底** | 默认不读对话、要重读 |
| 撰写区 **6 步串行确认**（生成预览→写入准备→用户确认→记录预检→执行），改字全重置 | **Enter 直发**、无预览、立刻清空 + 立刻冒泡 | 不要发送预览、要直接发 |
| 无流式追加（整列表状态重渲染） | 细粒度 store 选择器 + rAF 节流，只追加流式那条 | 不流畅 |
| 无滚动锚定 / 黏底（只有手动「回到最新」） | 距底 <100px 判定 + rAF 降频滚动 + 悬浮「回到底部」+ 切页存滚动位 | 不流畅 |

**目标 = 上表右列那套范式。**

## 2. 范围

- **重做（前端会话引擎）**：消息列表虚拟化、选中即显示、流式追加分离、滚动黏底、Codex 式打字即发撰写区。
- **坐在现成安全地基上、不重造**：本会话已做的 `read_threads_page` 只读元数据分页（**当前未提交**）+ `.codex` 只读口径（已拍板）+ 既有 transcript viewer（带遮挡边界）。
- **用户细调区（本方案不硬定）**：消息气泡样式、配色、间距、布局微调、空态文案、水墨质感——**引擎给结构，你用 `Claude Preview` 边看边调**。引擎照 Codex 的**行为 / 结构**，视觉收尾归你。
- **不碰**：真执行（甲，仍封）、记忆层、编排 / 画布、整体 Xuanji 工作台布局（另一对话）。

## 3. 分阶段（每阶段：Codex 执行 → Claude Preview + 真机验流畅 → 用户细调视觉）

- **P1 · 数据与骨架**：选中会话**即一次性载入历史 + 立刻渲染**（去掉「先 null 再异步重读」）；消息列表上**真虚拟化**（react-virtual 类），替换前端手写 `renderLimit` 窗口。→ 治「消息太多卡」+「要重读才有对话」。
- **P2 · 流畅层**：滚动**黏底**（距底判定 + rAF 降频 + 悬浮回到底部 + 切页存位）；**流式追加分离**（细粒度 store，只追加流式那条；为将来真执行的流式输出预留接口，本阶段不接真执行）。
- **P3 · 撰写区照 Codex**：**打字即发** UX（Enter 直发、即清空、即冒泡）；**送出仍走决策面、不解锁真执行**（甲）——把现在脸上的 6 步搬到幕后 / 收成单道，界面上只留「发送」。
- 全程：**视觉 / 显示由用户用 Claude Preview 细调**；每阶段在你 Mac 上真机验流畅度。

## 4. 执行模型

- **Codex 执行**（在用户 Mac，真机验流畅度）→ 独立复核线只读复核 → 咨询线（Claude）审实物。
- **看图**：`Claude Preview` MCP（已定口径，不自建工具）。
- **参照**：用户日常用的 Codex / Xuanji 会话界面（**行为基准**）+ 探测所得工程做法（虚拟化 / 流式 / 黏底 / 选中即显 / 打字即发）。
- **每阶段一个窄任务包 + kickoff**，不一次性大爆改。

## 5. 与现有工作的关系

- 坐在本会话已做的后端分页（`read_threads_page`，目前**未提交**在工作树）之上：P1 保留它、把前端手写窗口化换成真虚拟化。
- 不影响：RU / 记忆 / Stage L 其他项；整体工作台布局（另一对话的 Xuanji 布局 track）。
- 这条是**会话 / 对话这一块**的引擎重做；和「整体布局重做」是两件事（一个管"对话怎么流"，一个管"工作台怎么摆"）。

## 6. 不接受为

- 不接受为解锁真执行 / 开 B、改记忆层、动编排 / 画布、整体布局重做（另一对话）。
- 不接受为**硬定了视觉**（视觉是用户细调区）。
- 不接受为一次性大爆改（分阶段、每阶段验）。
