## 0. 完整工作台 = 什么（终态·一句话）

一个本地的、**像一个小公司**的 AI 工作台：**你说个目标 → 角色们（咨询 / 主管 / worker / 全局主管 / 秘书）在你授权的范围内、经状态机+权限+审计，把项目推进一轮 → 你主要看方案、结果和必须拍板的事**。

终态完整流程：
```
你说目标(自然语言)
 → 项目咨询 出方案(grounded)
 → 你审 · 方案授权(确认一段自动执行范围)        ← 人闸·永不省
 → 全局主管 复核方案边界
 → 项目主管 拆任务
 → worker(子智能体·codex) 在授权范围内自动干
 → worker 汇报 + 事实确认 → 沉淀记忆(下个 worker 召回)
 → 全局主管 复核最终结果
 → 你看结果
 秘书全程: 整理 / 提醒 / 解释(不当裁判)
```
画布在旁：设计/编辑工作流（多工作流）。自动化沿阶梯：授权范围内自动推进（半自动·现在）→ 北极星 NL 启动 → 乙·放开非测试真实项目（终局）。

## 2. 指导原则（校正「太乱」）

1. **功能先成体系、再配治理闸**：别在核心流程还没跑通时堆 per-step 治理（C4「只认默认」就是教训——简化假设当死闸、卡死 e2e）。**治理强度跟阶段**：现在轻档（圈固定测试项目）→ 乙才重档（非测试·生产护栏）。
2. **基础功能验证归两条线、不丢给用户**：后端线机器测 + UI 线真机，**「能不能端到端跑」这种基础验证我们做**；用户只在**每阶段成型后做最终验收**，不一遍遍替我们试 bug。
3. **每阶段交付一个「能用一遍」的完整切片**，不堆 piecemeal 半成品。
4. **守住不变的**（任何阶段）：方案授权人闸（§0.3/principles §4）；path-lock 圈测试项目（到乙才放）；不内置 LLM（依赖 codex）；经状态机+权限+审计，不靠聊天绕状态。

## 3. 阶段路线

### Phase A · 角色循环在 app 里真能用一遍（核心闭环 MVP）✅ 已收口（2026-07-06）
**目标**：用户在自己项目的工作流上，**说目标 → AI 出方案 → 审 → 自动推进 → worker 干 → 看结果**，端到端跑通一遍。
**交付**：
- UI 接通（P3·件 D·UI 线）：触发口 + 方案授权卡（人话）+ 一键自动推进 + 进度/结果；锚**项目选中工作流**（配合 (b)）。
- 后端 (b)：放开 C4「只认默认」→ 角色循环跑在项目内合法工作流上（`tasks/2026-06-27-role-loop-run-on-project-workflows-v1.md`）。
- 闭环后半段前端接：worker 汇报 + 事实确认、全局主管复核结果（暂用户演）、记忆召回 surface。
- 收口挂起件（C1 按钮 + 3 bug 修）。
**依赖**：后端引擎（✅）。**治理**：轻档·圈测试项目·方案授权人闸。**验收**：两条线合验端到端（机器+真机）→ 用户最终验收"我能在 app 里走一遍"。
**收口记录（2026-07-06）**：验收被 `decisions/2026-07-02-project-jiaoban-tab-final-design-v1.md` 抬成「好用地交办一遍」并达成——交办五态 / 所批即所跑 / 残料三层自愈 / 回程契约 / 口供上脸+黄牌 / 事实确认 / 记忆召回全落地，2026-07-05/06 用户真机验收；逐项证据 `CURRENT.md` ②，尾账（两处定稿偏离 + 真机软尾巴）见 `CURRENT.md` ③。

### Phase B · 角色补全（5 角色齐）✅ 已收口（2026-07-07）
**目标**：秘书 + 全局主管做成 agent，把"用户演的角色"还给 agent。
**交付**：
- **全局主管 agent**：复核方案边界 / 最终结果**自动**（替用户演那两道）——这是**审查闸自动化**，需单独决策 + 谨慎（守"该停就停"，不是橡皮章）。
- **秘书 agent**：整理 / 提醒 / 解释（不当裁判·中间版 §0）；前端真用上。
**依赖**：Phase A（✅）。**治理**：全局主管自动审 = 重一点，**实现前补决策**（拍板范围：全局主管读口供后的权限档 / 秘书首版边界 / 第一砖——细目见 `CURRENT.md` ③）。
**收口记录（2026-07-07）**：开门定稿 `decisions/2026-07-07-phase-b-advisory-supervisor-and-secretary-v1.md`（四拍：判+建议人执行 / 秘书确定性优先 / 每单自动复核·幂等 / 机会简报排后）；B1 结果复核、B2 批前边界、B3 秘书面三片全落地并真机验收——「审查闸自动化」以 **advisory** 形态落地，**闸权未外放**，升档 = 信任阶梯单独拍（审计回归正典 audit_events 为前置）。逐片证据 `CURRENT.md` ②。

### Phase E · 乙·生产档（终局）
**目标**：放开非测试真实项目 + 重护栏拧到生产 + 明确授权。
**交付**：path-lock 放开非测试（高危#1）+ 自动连环放开非测试/多项目（高危#4）+ 真·无人值守的重护栏（可中断/边界/审计/可回滚拧到生产）+ 信任建立。
**依赖**：A–D 在测试项目跑稳。**治理**：**重档·明确授权那一下不可省**。这是真正风险变大的台阶。
