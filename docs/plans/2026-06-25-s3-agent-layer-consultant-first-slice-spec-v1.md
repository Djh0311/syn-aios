# S3 agent 智能层 · 咨询第一刀 spec v1

日期：2026-06-25 · 出自：主导线（Claude）+ 用户对话逐项拍定。

> **这是什么**：S3 第一刀的**设计 spec**——基座决策 + 咨询角色形状 + 真实项目实例 + 验收。
> **不是什么**：不是 build 任务包（spec 过目后另写）、不是整个 S3 弧（只第一刀）。
> 上游：`docs/plans/2026-06-23-next-stage-unify-and-requirements-plan-v1.md`（S3）、`CURRENT.md` ③。

## 1. 北极星 + 解的核

S1/S2-3 后角色循环**能跑**，但"脑子"薄——本质是 codex 被结构化文本驱动，判断不够智能。
**S3 = 把角色从"填表壳"换成真 agent**：agent = **借来的 LM + 真 harness**（档案 + 工具面 + 上下文注入 + loop/校验）。第一刀只做**一个角色：项目咨询**。

## 2. 基座决策（已拍）

- **不 fork opencode**：它是单 agent 编码工具（工具/prompt 形状错、自带权限模型跟 Rust 闸打架、单人维护扛不住）。**只当机制参考。**
- **薄·自有 harness，住 Rust 内（src-tauri）**：和安全闸**同进程**，触发执行直接 in-process 调 `decide_real_execution_command`/path-lock，无 IPC 边界可漏。无 sidecar、无新语言。
- **契约缝**（换得起的关键）——稳定 trait，下游循环只认它：
  ```
  trait ConsultantAgent {
      fn consult(&self, ctx: ProjectContext, question: &str) -> Result<ConsultationProposal>;
  }
  ```
  - **Impl·现在（CLI / tier-1）**：拼 prompt（档案+ctx）→ 驱动 codex/claude CLI（**复用现成 `codex_local_runner`**）→ 抠出方案。薄。
  - **Impl·后续（API / tier-2）**：真 loop（system=档案、注入 ctx、挂只读工具、迭代、校验）。等 API key 到位。
  - 两 impl 同吐 `ConsultationProposal` → 喂现有 `create_project_consultation_proposal`（C1），下游一字不动。
- **provider-agnostic**：写薄适配器（claude/openai API 各 ~百行 HTTP），不继承 opencode 一坨。**"通用"做到能换真用的脑即可，不造万能适配器。**
- **诚实**：CLI（脑自带 loop）和 API（loop 在你手）是**两个抽象层级**，不能塞一个 loop 后面。换 = 写 tier-2 impl 落在**同一契约**后；可复用三块（**档案 / 上下文构造器 / 契约**）照搬，只 loop+调脑那截重写。**好不好换 = 缝切在契约上、功夫投在可复用层、脑和 loop 保持薄。**

## 3. 咨询第一刀 · 形状

**角色边界**：解答用户对项目的问题、定大方向；**不主导执行**（那是项目主管）、**只读不写**。产出 = 交循环审的咨询方案。

### A. ProjectContext（注入）
- **常驻注入（策展核心·小而高值）**：项目身份+态、**入口文档全文**、文档/结构地图、黑板摘要（人话化·收字段）、项目记忆（索引+相关）、最新信号。
- **按需取（工具拉，不预载）**：具体文件、完整决策/黑板单条、grep、深挖历史。
- **两条硬原则**：
  1. **curated core = 项目的入口/索引文档**（README / CURRENT / index，因项目而异）——harness 小启发式：root 或 docs/ 下找入口 + 扫结构地图。
  2. **防御式降级**：无 git 跳 git-log 用版本/mtime；黑板/记忆空就纯靠文档。**注入 = 有啥塞啥，不假设齐全。**

### B. 工具面（全只读·~6 个）
`read_file` / `list_tree` / `grep` / `git_log·git_show`（有 git 才用）/ `read_memory` / `read_blackboard`。
**没有写、没有执行、没有起 codex** → **结构性保证**它碰不到执行闸（没那只手，不靠纪律）。工具撞错要**响且有用**。

### C. 档案（怎么写 + 怎么活）
**三种东西各去各处，别一锅倒进档案：**
| 种类 | 例 | 去哪 |
|---|---|---|
| 结构核（不 derive） | 咨询是谁 / 只读不执行 / 产出 C1 方案 | 档案固定骨 |
| 行为层（从**行为类记忆** derive） | 不讨好 / 落地不假设 / 不虚高 | 档案可变段 |
| 项目事实（不进档案） | "这项目会话走 sqlite" | 进 ProjectContext |

**v0 静态起手**（已是手抽，先上、能跑）：
```
你是「项目咨询」。
职责:解答用户对这个项目的问题、帮定大方向。你不主导执行(那是项目主管)、不自己改任何东西。
铁律·落地:每个判断都必须基于你真读到的项目状态。不确定就用工具去读——不许假设某文件/状态/历史存在。结论里引用读到的具体依据。
边界:只读、不写、不执行。给的是建议和方向。若认为该真跑某事,写进方案交项目主管走授权——你自己永不触发执行。
风格:直接、先讲风险和不确定、不讨好。该泼冷水就泼。
产出:结构化咨询方案——目标/范围/为什么这么判/风险与不确定/必停点/建议的下一步。这份进角色循环交用户审。
```
**v1 升级**：行为层改从"行为类记忆"装配（起步可只**注入相关行为记忆片段**进 system，不必 LM 合成）。接 **每日自动记忆采集** → agent 随项目积累自动变好；但需"哪些行为记忆喂档案"的**策展 + lint/冲突**，非无脑 auto-grow（坏记忆毒化、过多稀释）。

**种子来源**：可从 Claude `~/.claude/memory` 的**行为类**记忆筛着搬（不讨好/落地/不虚高），但**执行线专属**（如 dont-implement-without-go）和**项目事实**不搬；且只是种子，产品长出自己的行为记忆后断奶。

### 流程
`你问 → harness 拼 ProjectContext+问题 → 咨询(LM·现走 CLI)边读边想 → 产出结构化方案 → 喂 C1 → 下游授权/复核一字不动`
**全程只读 → 天然在闸后**（没有执行工具可绕）。这是它能当第一刀的根本。

## 4. ProjectContext 实例 · `/Users/yoyi/project/猫猫点菜小程序`

早期规划项目（恋点·情侣投喂点餐小程序）、**非 git**、文档全套。首次咨询注入：
- **身份+态**：微信小程序 + 云开发 + 企业主体；需求✅→设计✅→评审✅→开发🔨(M0 可起)。
- **入口**：`docs/README.md` 全文（自带进度表 + 关键结论速览 + 合规硬线，23 行）。
- **结构地图**：01-需求(PRD V2.2/配色 V2.2/立项) · 02-设计(技术设计 V1.2/形态选型) · 03-评审(红队 19 条收口) · 04-开发(计划拆解 V1.0)。
- **黑板/记忆**：空（没进过工作台）→ 纯靠读文档。
- **最新信号**：无 git → README「进展更新 2026-06」+ 版本号 + mtime。

## 5. 验收（第一刀算不算通）

- **真问题·只能靠读文档答**（防幻觉验收）：示例——"红队 19 条说全收口，抽查开发计划 M0，有没有红队点了、开发计划没接的?" 逼它**交叉读红队+开发计划**、编了一眼看穿。
- **判通**：答案**落地引用真读到的文档**、给出能进循环的结构化方向；产出能喂 C1；全程只读未碰执行闸。
- 机器侧：trait/impl 单测；CLI impl 真跑一次（`#[ignore]`，注意真 codex 偶发 flake、retry，见记忆 `real-codex-run-flaky-verify-by-artifact`）。

## 6. 分期

- **第一刀（本 spec → 下个任务包）**：v0 静态档案 + CLI/tier-1 impl + 只读工具面 + ProjectContext（猫猫点菜实例）+ 喂 C1。**先证"LM+harness 能就着真项目落地答出有用方向"。**
- **后续**：API/tier-2 impl（同契约）/ 档案行为层 derive / 其余角色（主管/worker/秘书/全局主管）/ NL 拆解 / 一句话启动 / 套模版 / 沿层级反馈边 / 每日自动记忆采集。**别在第一刀撑大。**

## 7. 安全

- 咨询**全只读** → 结构性在闸后（无执行工具）。**读真实(非测试)项目不碰高危#1**（#1 是写/执行，不是读）。
- harness 住 Rust、同进程；将来 tier-2 若加任何"会真跑"的能力，必经现有 `decide_real_execution_command`/path-lock，**不另开闸、不绕**。
