# Workbench Frontend Display Boundary v1

日期：2026-06-03

状态：**当前前端显示边界正本，已按 2026-08-01 全工作台运行模型修订。** 本文说明产品默认显示什么、专业 / 管理 / 开发面显示什么，以及迁移阶段如何保留现有桌面壳；不代表目标读模型已经实现。

## 0. 先说薄弱点

- 本文不是视觉稿，不规定具体颜色、间距、图标和组件样式。
- 本文不是实现任务包，不能让 agent 一次性照本文全部开发。
- 本轮确认范围已经超过中间版本，包含最终产品方向、UI 信息架构、后端读模型依赖和后置能力。
- 后续任务包必须先判断属于“中间版本必须做”还是“最终形态后置”，不能把本文所有内容都塞进最近一批开发。
- 现有 Tauri 桌面壳、项目壳、知识、记忆和专业页面优先保留并渐进接新读模型；本轮不要求推倒整个前端。
- 首页允许重构为秘书的“当前情境 + 持续对话”，但本文不规定具体视觉稿。
- 旧拟人悬浮秘书、旧五角色或“首页只显示几个计数”的承诺，被 2026-08-01 运行模型覆盖。

## 0.1 平台边界硬规则

本工作台 UI 只按桌面端 Tauri 工作台设计和验收。

明确禁止：

- 不做手机端 UI。
- 不新增移动端导航、手机端页面、移动端专属布局或触控优先交互。
- 不把 responsive / mobile-first 当作本项目 UI 目标。
- 不为了手机窄屏重排一级入口、右侧入口、项目画布、智能体页、记忆页或知识库页。
- 不把手机浏览器、移动视口截图或移动端 smoke 当作验收要求。

允许的最小兼容：

- 允许保留历史遗留的基础 CSS 回退，避免窗口极窄时完全不可访问。
- 允许为了桌面窗口缩放做轻量防溢出处理。
- 这些兼容不能发展成手机端产品设计，也不能在任务包里扩展为移动端适配任务。

验收口径：

- UI 验收默认只看桌面 Tauri 窗口。
- 浏览器 smoke 只能作为辅助加载检查，不能替代真实 Tauri 桌面窗口验收。
- 后续如果有人提出移动端适配，必须先改蓝图和权威入口；没有明确改口前一律拒绝进入开发。

## 1. 本文解决什么问题

本文解决的是：工作台前端到底应该把哪些信息显示给用户，哪些信息只在详情里显示，哪些信息要进入管理或开发者模式，哪些信息不应该出现在普通产品 UI 里。

大白话：

- 主界面要像工作台，不像治理后台。
- 用户必须能明确进入秘书、全局主管和具体项目；项目内默认面对该项目主管。
- 项目、成员、知识、记忆、工作流、画布、连接器和审计是可直接打开的专业对象 / 工作面，不全部挤进聊天。
- 内部 schema、raw event、日志、adapter 细节、数据库状态默认不打扰用户。
- 需要确认的事进入“待你处理”聚合，但每项都能回到原角色 / 项目 / 对象；不把每一步 worker 过程铺满屏幕。
- 页面始终让用户看见当前角色、scope、对象、日常 / 开发通道和会影响什么。

## 2. 显示边界分层

后续所有 UI 任务都按四层拆解。

### 2.1 最终产品显示边界

这是最终工作台应该长成的样子，可以进入设计和长期架构文档。

### 2.2 当前迁移阶段必须落地

当前迁移以 master / stage plan 为准：先稳定角色、scope、会话和读模型，再改首页和日常闭环。既有工作流能力保留，但不再是日常 UI 中心。

### 2.3 后端和数据依赖

前端不能靠假数据或硬编码显示关键能力。需要正式读模型、状态机、审计、日志或权限对象支撑的内容，必须先拆后端任务包。

### 2.4 后置能力

最终需要，但不抢当前阶段。后置不等于取消。

## 3. 一级入口

### 3.1 最终产品边界

工作台顶层必须明确可达：

- 秘书；
- 全局主管；
- 项目列表，以及进入项目后的常驻项目主管。

专业入口可以沿用现有桌面导航并渐进调整：

- 成员 / Agent；
- 知识；
- 记忆；
- 工作流 / 画布；
- 管理 / 设置。

本文不锁定它们必须都在左栏，也不要求本轮重画项目 tab。日常通道可以弱化工作流 / 画布 / Harness 等开发能力；开发通道或专业对象入口仍能直接找到。

不设为日常一级入口：

- 模型、adapter、凭据和能力声明。

原因：这些是底层 / 管理能力，不应该成为普通用户每天进入的主页面。成员 / Agent 目录仍可保留为专业入口，用来找人、找会话和看记录。

### 3.2 当前迁移阶段必须落地

- 增加明确的秘书与全局主管入口；项目内角色由当前项目固定。
- `智能体 / 成员` 承载稳定内部成员、临时 agent、会话、运行状态和历史记录；它是目录和专业工作面，不替代角色入口。
- `记忆` 和 `知识库` 都作为一级入口存在。
- 模型、adapter、凭据、能力声明暂时藏在智能体、设置或管理详情里。

### 3.3 后端和数据依赖

- 智能体可用状态需要 adapter descriptor 和健康状态读模型。
- 模型 / 凭据状态只允许显示可用性和问题，不显示 token 或敏感内容。

### 3.4 后置能力

- 完整模型库。
- 项目模型池。
- 成本统计。
- 多 provider 凭据管理。

## 4. 右侧全局入口

### 4.1 最终产品边界

右侧固定入口：

- 秘书
- 通知
- 待办
- 运行中
- 管理

`管理` 内部包含：

- 审计
- 日志
- 权限
- 健康状态
- 数据位置

右侧“秘书”只能是同一秘书角色入口的快捷方式，不能形成另一份会话、权限或状态。若首页已经是秘书首页，右侧可以保留快捷打开 / 回到当前会话，也可以在迁移后弱化；具体位置不属于架构合同。

### 4.2 中间版本必须落地

- 通知、待办、运行中不能混成一个列表。
- 审计和日志不再作为右侧顶级图标散开，统一收进管理。
- 管理默认显示健康状态和最近错误，详细审计和日志点进去看。

### 4.3 后端和数据依赖

- 通知需要事件摘要读模型。
- 待办需要确认事项读模型。
- 运行中需要工作流运行和智能体运行状态。
- 审计必须来自正式审计事件，不从普通日志伪造。
- 日志必须来自运行日志体系，不把日志当审计。

### 4.4 后置能力

- 运维日志检索。
- 系统健康诊断页。
- 错误码知识库。
- 日志导出和脱敏。

## 5. 秘书显示边界

### 5.1 最终产品边界

秘书是顶层明确角色入口，也是首页的主要日常协作角色。它不绑定半身形象、悬浮球、桌面宠物或固定侧栏；是否使用头像和轻量动效属于后续视觉选择，不是产品能力合同。

打开秘书后：

- 主体显示持续角色会话和输入框；
- 当前情境显示外部承诺 / 时限、待决定、异常 / 阻塞、完成和延续；
- 每条 OpenLoop / Decision / 提醒显示来源、owner、为什么出现、最后变化，并能回到原对象；
- 项目只显示受控摘要和跳转，不复制项目事实；
- 无新事件时不伪造“正在思考”或持续调用模型。

秘书不能做：

- 不确认 worker 汇报。
- 不判断项目过程事实。
- 不当工作成果裁判。
- 不绕过记忆政策写正式记忆，也不把推断冒充用户事实。
- 不直接派发任务。
- 不因内部关注自动创建任务、工作流、项目、日程或想法箱。
- 不静默切到全局主管 / 项目主管或开发通道。

### 5.2 当前迁移阶段必须落地

- 后端持久 `RoleSession`，App 重启后仍能找到并续接同一秘书会话。
- 首页情境和右侧快捷入口指向同一秘书身份和会话。
- 内部关注可 read / dismiss / snooze / close / reopen，且不改 source object。
- 简单决定可在聚合面回答并回写原 owner；复杂决定打开原对象。
- 秘书可以主动查询内部进度和发起留痕的全局主管只读咨询，但不能改项目。

### 5.3 后端和数据依赖

- 最近聊天内容需要秘书会话 store。
- 当前情境需要 Attention / OpenLoop / Decision / ProjectSummary / DailyBrief 正式读模型和 typed ObjectRef。
- 影响面报告需要记忆关系、来源、引用、权限和使用记录读模型。
- 待确认事项需要统一确认队列。

### 5.4 后置能力

- 更完整的视觉人格和非干扰动效。
- 多连接器后的跨软件情境。
- 经过治理的长期个性化和解释深度适配。

## 6. 项目页显示边界

### 6.1 最终产品边界

项目页结构：

- 左侧：项目列表，只显示项目名和少量状态。
- 中间：当前项目主区域。
- 项目内横向切换：工作流 / 智能体 / 文档 / 记忆 / 设置。
- 右侧：节点详情或项目上下文详情。

各 tab 只显示自己该显示的内容：

- 工作流：只显示项目工作流画布。
- 智能体：只显示该项目相关智能体会话。
- 文档：只显示该项目知识库资料。
- 记忆：只显示该项目相关记忆。
- 设置：只显示项目设置。

全局通知、待办、审计、运行中不塞进项目主画布。

### 6.2 中间版本必须落地

- 项目工作流页保持画布为主。
- 候选治理、任务包、权限、readback、审计等复杂信息进入节点详情或侧栏，不铺在画布主区域。
- 项目页不变成任务包管理器。

### 6.3 后端和数据依赖

- 项目详情需要 project read model。
- 项目画布需要 workflow read model。
- 项目记忆需要正式记忆读模型和权限过滤。
- 项目文档需要知识库索引。

### 6.4 后置能力

- 项目内完整设置页。
- 项目文档和 Obsidian vault 深度联动。
- 项目级记忆关系图可视化。

## 7. 智能体入口显示边界

### 7.1 最终产品边界

`智能体` 是原会话中心，但应接近 Codex 原生体验。

默认显示：

- 智能体列表：Codex、Claude Code、OpenClaw、OpenCode，先有谁显示谁。
- 会话列表：按项目、时间、状态收纳。
- 会话详情：用户消息和智能体回复，长内容默认收纳。
- 运行中会话：正在执行什么、是否需要权限、是否卡住。
- 搜索和过滤：按项目、时间、标题、智能体、状态。

不默认显示：

- adapter schema
- 模型能力声明
- 内部 transcript key
- sqlite / index 来源
- 原始 event log

中间版本最终必须支持发消息继续会话。

### 7.2 中间版本必须落地

- 查看、搜索、过滤、收纳、错误分类。
- 会话详情默认只显示用户消息和智能体回复。
- 工具调用、命令输出、权限记录和长日志默认折叠。
- 发消息继续会话要进入中间版本最终目标，但必须单独设计权限和安全边界。

### 7.3 后端和数据依赖

- 会话目录主权威是 sqlite，index 只能作为缓存 / 兼容 / 辅助。
- transcript 读取应走 Rust 原生 parser。
- 发消息需要 agent controller、权限确认、运行状态、取消和 readback 错误可见化。

### 7.4 后置能力

- 停止、重启、resume 操作完善。
- 删除、导出、标记、收藏、分享。
- 多会话对比。
- 会话 lineage。

## 8. 画布入口显示边界

### 8.1 最终产品边界

一级 `画布` 默认打开是可编辑无限画布，不是列表页。

一级画布可以切换到：

- 画布库
- 工作流总览
- 模板
- 运行记录

项目里的画布和一级画布调用同一个画布模块，功能模块复用；区别在上下文、数据归属和执行权限。

### 8.2 中间版本必须落地

- 一级画布可以实验运行。
- 实验运行不能写正式项目状态、正式记忆或项目任务。
- 真实项目工作流必须绑定项目或发布到项目后运行。
- 项目画布里的运行才是正式项目工作流运行。

### 8.3 后端和数据依赖

- 画布模块需要明确 canvas context：global / project / template / experiment。
- 项目执行必须经过控制核心和 workflow state。
- React Flow 只是渲染映射，不是事实源。

### 8.4 后置能力

- ComfyUI 类可视编辑深度能力。
- 画布库资产管理。
- 模板发布流。
- 复杂节点运行预览。

## 9. 记忆中心显示边界

### 9.1 最终产品边界

`记忆` 是能看懂的记忆中心，不是治理后台。

默认显示：

- 用户偏好
- 项目记忆
- 待确认记忆
- 最近变化
- 冲突和过期
- 使用记录

默认不显示：

- schema
- 内部 key / id
- 原始召回分数
- 原始审计结构
- 原始图谱结构

正式记忆可以编辑，但不是直接覆盖：

1. 用户点击编辑。
2. 系统生成修改提案。
3. 秘书输出影响面报告。
4. 用户确认。
5. 系统写入正式记忆并留下审计。

确认权：

- 用户偏好：必须用户确认。
- 安全边界：必须用户确认。
- 跨项目记忆：必须用户确认。
- 项目事实：可以由项目主管确认，高风险交给用户。
- 临时任务记忆：可以进入候选，不自动写正式记忆。

图关系可以作为展开项显示，但必须翻译成人话。

### 9.2 中间版本必须落地

- 记忆中心作为一级入口。
- 展示正式记忆、候选记忆、最近变化和待确认事项。
- 记忆被任务使用时轻提示，例如“使用了 3 条记忆”。
- 重要决策受记忆影响时，结果报告里说明。
- 冲突、过期、需要确认时进入待办。

### 9.3 后端和数据依赖

- FormalMemoryStore。
- MemoryVersion。
- MemoryAuditEvent。
- MemoryCandidate。
- MemorySourceRef。
- MemoryConflict。
- Memory relation / entity read model。
- TaskMemoryPacketBuilder。
- 权限过滤。

### 9.4 后置能力

- 成熟模式。
- 跨项目记忆提升和下沉。
- 记忆合并、拆分、冻结、归档。
- 图谱可视化高级编辑。

## 10. 知识库显示边界

### 10.1 最终产品边界

`知识库` 是资料和笔记空间，偏 Obsidian / vault / 文档管理，不是另一套记忆。

默认显示：

- 文档库 / 笔记库
- 项目资料
- 设计文档
- 决策记录
- 研究材料
- Obsidian vault
- 最近编辑
- 和记忆有关联的文档

知识库文档详情可以显示：

- 关联记忆
- 待确认记忆候选
- 哪些正式记忆引用了这篇文档
- 从文档选段提取为记忆候选

知识库不直接编辑正式记忆。

### 10.2 中间版本必须落地

- 知识库作为一级入口。
- 明确知识库和记忆的边界。
- 文档内容可以被引用、总结、提出记忆候选。
- 只有经过记忆流程确认后，才进入正式记忆。

### 10.3 后端和数据依赖

- 文档索引。
- 文档引用和来源锚点。
- 记忆候选生成入口。
- Obsidian-compatible vault 配置。

### 10.4 后置能力

- Obsidian 原生功能深度内置。
- 双链、标签、图谱、插件兼容。
- 文档版本和引用漂移检测。

## 11. 通知、待办、运行中

### 11.1 最终产品边界

- 通知：发生了什么。
- 待办：需要用户处理什么。
- 运行中：系统现在正在干什么。

三者不合并。

### 11.2 中间版本必须落地

- 方案确认、结果验收、记忆修改确认、高风险权限进入待办。
- 任务完成、agent 出错、权限被拒绝、记忆候选生成进入通知。
- 项目工作流运行、智能体执行、卡住状态进入运行中。

### 11.3 后端和数据依赖

- Notification read model。
- Todo / approval queue。
- Running workflow / agent run read model。

## 12. 管理和设置边界

### 12.1 管理

管理显示系统运维、审计、日志和健康状态。

包含：

- 审计
- 日志
- 权限
- 健康状态
- 数据位置

默认只显示健康状态和最近错误。

### 12.2 设置

设置只管用户主动配置。

包含：

- 外观和布局
- 默认智能体偏好
- 自动化程度
- 通知方式
- 秘书显示方式
- 知识库 / Obsidian 基础配置
- 项目默认规则
- 数据备份和导出

设置不显示：

- 原始日志
- 错误堆栈
- adapter schema
- 内部数据库状态

## 13. 首页显示边界

首页可以按 current master plan 渐进重构为秘书首页，不要求推倒整个前端壳。

默认显示：

- 当前情境：已与别人约定 / 时间敏感、待决定、异常 / 阻塞、近期完成、今日延续；
- 秘书持续会话与输入；
- 每项的来源、owner、scope、最后变化和精确回源；
- 最近项目、运行和系统状态的必要摘要；
- 日常 / 开发通道和当前角色 / 对象的清楚标识。

不在首页展开：

- 记忆系统细节
- 审计流水
- 原始日志
- adapter 细节
- 项目原始材料或完整事件流
- 密钥、token 和 connector secret
- 全部内部组织图、worker raw transcript 或 Harness 细节

首页是聚合读模型，不是第二数据库。点击项目摘要回到项目真源；回答简单决定后回到原 owner；复杂决定打开原角色 / 项目 / 对象。

## 14. 工作流画布节点显示边界

画布节点默认只显示：

- 节点名称
- 节点类型
- 当前状态
- 负责方
- 少量进度或提醒

点击节点后，右侧详情显示：

- 输入和输出
- 执行摘要
- 关联会话
- 关联文档
- 关联记忆
- 权限请求
- 日志摘要
- 错误原因
- 可执行操作

不默认显示：

- 原始 JSON
- schema
- 内部 id
- raw transcript
- 完整日志
- adapter 细节

## 15. 自动化工作流过程显示

用户默认看到：

- 方案待确认
- 正在执行
- 等待结果验收
- 已完成
- 出错

点开详情才看到：

- 执行摘要
- 关键风险
- 失败原因
- 产物列表
- 证据链接
- worker 汇报
- 项目主管确认过程

不默认把每个 worker 长汇报、日志、原始会话全部铺出来。

## 16. 权限和安全边界显示

低风险自动操作不弹窗，只在运行中和审计里留记录。

高风险操作才弹确认，例如：

- 写文件
- 改正式记忆
- 执行命令
- 迁移数据库
- 删除内容
- 访问敏感路径

权限弹窗必须用人话说明：

- 要做什么
- 为什么要做
- 会影响哪里
- 风险是什么
- 谁提出的
- 批准后会发生什么

按钮：

- 允许一次
- 拒绝
- 查看详情

默认不提供永久允许。永久允许只能在设置或权限规则里专门配置。

所有批准和拒绝进入 `管理 > 审计`。

## 17. 错误和失败显示

错误分三层：

1. 普通用户层：一句人话说明。
2. 影响层：说明影响什么。
3. 技术详情层：可展开给开发或运维看。

错误分类：

- 数据缺失
- 文件不可读
- 权限不足
- 智能体不可用
- 工作流失败
- 记忆冲突
- 系统异常

不直接把 traceback 扔给用户。

## 18. 智能体会话详情显示

默认显示：

- 用户消息
- 智能体回复
- 代码块和复制按钮
- 工具调用摘要
- 权限请求记录
- 最终结果摘要

默认收纳：

- thinking / 推理过程
- 工具原始输出
- 长日志
- 系统提醒
- 大段执行记录
- 原始 transcript event

可展开查看：

- 工具调用详情
- 命令输出
- 文件变更
- 错误详情
- 时间线

## 19. 记忆使用提示

记忆被自动使用时默认轻提示：

- 任务详情显示“使用了几条记忆”。
- 点击可展开具体记忆。
- 重要决策受记忆影响时，结果报告里说明。
- 普通召回不弹通知。
- 记忆冲突、过期或需要确认时进入待办。

## 20. 角色显示

普通用户不需要面对角色管理后台，但必须能在成员目录寻找、查看和直接联系稳定内部成员；临时 agent 的任务、结果和审计也可搜索。

只在相关位置显示责任方：

- 全局主管：跨项目优先级、边界、风险和独立复核意见。
- 项目主管：明确项目内的目标、方案、执行过程和 worker 回收。
- worker：具体任务节点执行者。
- 秘书：态势、未闭环、解释、整理、提醒、日报和显式交接，不当审批者或项目执行者。

每个会话、交接和正式动作显示 `role / scope / current object / execution channel / permission profile` 的人话版本。内部 ID 可在开发者模式查看，普通界面不暴露 schema。

## 21. 证据、handoff 和开发者模式

普通产品 UI 不直接显示 `evidence` / `handoff` 这类工程文件名。

结果报告用人话显示：

- 改了什么
- 验证了什么
- 还没验证什么
- 相关文件

管理 > 审计 可以看到更完整记录。

开发者模式默认关闭。打开后才显示：

- 原始 evidence / handoff 路径
- 内部 id / key
- schema / version
- raw transcript event
- 原始日志路径
- adapter capability 细节
- sqlite / index / cache 状态
- 诊断按钮

## 22. 对当前迁移开发的约束

迁移不是一次性完成本文全部最终形态，也不先画一套新的项目页布局。

按 current master plan 的前端顺序：

1. 固定角色 / scope / object / channel / permission，并持久恢复会话；
2. 增加秘书和全局主管顶层入口，Agent 面变成员 / 会话目录；
3. 用 typed Attention / OpenLoop / Decision 读模型重构秘书首页；
4. 让普通项目主管对话通过明确动作接入既有方案 / 授权 / 执行能力；
5. 接入记忆、日报、个人模型、连接器和专业工作面；
6. 逐页切换读模型并退掉 App.tsx / 右栏的临时拼装状态。

后置但必须保留方向的是：

- 秘书更完整的视觉人格和动效（不是半身悬浮的硬要求）。
- Obsidian 原生功能深度内置。
- ComfyUI 类复杂画布能力。
- 多 agent 完整操作集。
- 图谱高级编辑。

## 23. 验收标准

后续 UI 任务验收时，必须检查：

- 主界面有没有把内部治理信息直接铺给用户。
- 记忆和知识库有没有混成一套东西。
- 秘书有没有越权审批、改项目、绕过政策写记忆或派任务。
- 首页每项是否有来源、owner 和精确回源，是否复制了第二份项目事实。
- 三类角色入口是否固定 role / scope，跨角色是否显式交接。
- 日常 / 开发通道是否可见且没有静默切换。
- 项目页是否保留专业能力且没有重新被工作流 / 任务包吞掉；具体布局不拿旧 canon 外推。
- 成员页是否能找到稳定成员和历史临时 agent，又没有把它变成万能入口。
- 权限、错误、证据是否用人话表达。
- 开发者模式是否默认关闭。
- 需要后端读模型的内容是否没有靠前端假数据冒充。
- Station 3b、跨项目和 connector capability 是否由后端拒绝，而不是只隐藏按钮。
- 浏览器 / synthetic / build 是否没有冒充 Tauri 真实 App。
