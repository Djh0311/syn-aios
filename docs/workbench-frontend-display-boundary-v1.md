# Workbench Frontend Display Boundary v1

日期：2026-06-03

状态：当前前端显示边界权威文档。本文来自用户问答确认，负责说明最终工作台 UI 应该显示什么、不显示什么，以及中间版本先做到哪里。

## 0. 先说薄弱点

- 本文不是视觉稿，不规定具体颜色、间距、图标和组件样式。
- 本文不是实现任务包，不能让 agent 一次性照本文全部开发。
- 本轮确认范围已经超过中间版本，包含最终产品方向、UI 信息架构、后端读模型依赖和后置能力。
- 后续任务包必须先判断属于“中间版本必须做”还是“最终形态后置”，不能把本文所有内容都塞进最近一批开发。
- 首页 UI 内容此前已经确定，本文只确认首页能显示哪些轻量状态，不重新设计首页。

## 0.1 平台边界硬规则

本工作台 UI 只按桌面端 Tauri 工作台设计和验收。

明确禁止：

- 不做手机端 UI。
- 不新增移动端导航、手机端页面、移动端专属布局或触控优先交互。
- 不把 responsive / mobile-first 当作本项目 UI 目标。
- 不为了手机窄屏重排一级入口、右侧入口、项目画布、智能体页、记忆页或知识库页。
- 不把手机浏览器、移动视口截图或移动端 smoke 当作验收要求。

允许的最小兼容：

- 允许保留历史遗留的基础 CSS 回退，避免窗口极窄时完全不可访问。
- 允许为了桌面窗口缩放做轻量防溢出处理。
- 这些兼容不能发展成手机端产品设计，也不能在任务包里扩展为移动端适配任务。

验收口径：

- UI 验收默认只看桌面 Tauri 窗口。
- 浏览器 smoke 只能作为辅助加载检查，不能替代真实 Tauri 桌面窗口验收。
- 后续如果有人提出移动端适配，必须先改蓝图和权威入口；没有明确改口前一律拒绝进入开发。

## 1. 本文解决什么问题

本文解决的是：工作台前端到底应该把哪些信息显示给用户，哪些信息只在详情里显示，哪些信息要进入管理或开发者模式，哪些信息不应该出现在普通产品 UI 里。

大白话：

- 主界面要像工作台，不像治理后台。
- 用户默认看项目、智能体、画布、记忆、知识库和必要状态。
- 内部 schema、raw event、日志、adapter 细节、数据库状态默认不打扰用户。
- 需要确认的事进入待办或秘书对话，不把每一步 worker 过程都铺满屏幕。

## 2. 显示边界分层

后续所有 UI 任务都按四层拆解。

### 2.1 最终产品显示边界

这是最终工作台应该长成的样子，可以进入设计和长期架构文档。

### 2.2 中间版本必须落地

这是当前中间版本需要实现或至少形成可验证入口的内容。中间版本目标仍是自动化工作流和完整记忆系统闭环，不是把所有最终 UI 都做完。

### 2.3 后端和数据依赖

前端不能靠假数据或硬编码显示关键能力。需要正式读模型、状态机、审计、日志或权限对象支撑的内容，必须先拆后端任务包。

### 2.4 后置能力

最终需要，但不抢当前阶段。后置不等于取消。

## 3. 一级入口

### 3.1 最终产品边界

左侧主导航保留：

- 项目
- 智能体
- 画布
- 记忆
- 知识库
- 设置

不设当前一级入口：

- 模型与 Agent

原因：模型、adapter、凭据、能力声明是底层能力，不应该暴露成普通用户每天进入的主页面。

### 3.2 中间版本必须落地

- 左侧“会话”统一命名为“智能体”。
- `智能体` 承载 Codex、Claude Code、OpenClaw、OpenCode 等 agent 产品的会话、运行状态和历史记录。
- `记忆` 和 `知识库` 都作为一级入口存在。
- 模型、adapter、凭据、能力声明暂时藏在智能体、设置或管理详情里。

### 3.3 后端和数据依赖

- 智能体可用状态需要 adapter descriptor 和健康状态读模型。
- 模型 / 凭据状态只允许显示可用性和问题，不显示 token 或敏感内容。

### 3.4 后置能力

- 完整模型库。
- 项目模型池。
- 成本统计。
- 多 provider 凭据管理。

## 4. 右侧全局入口

### 4.1 最终产品边界

右侧固定入口：

- 秘书
- 通知
- 待办
- 运行中
- 管理

`管理` 内部包含：

- 审计
- 日志
- 权限
- 健康状态
- 数据位置

### 4.2 中间版本必须落地

- 通知、待办、运行中不能混成一个列表。
- 审计和日志不再作为右侧顶级图标散开，统一收进管理。
- 管理默认显示健康状态和最近错误，详细审计和日志点进去看。

### 4.3 后端和数据依赖

- 通知需要事件摘要读模型。
- 待办需要确认事项读模型。
- 运行中需要工作流运行和智能体运行状态。
- 审计必须来自正式审计事件，不从普通日志伪造。
- 日志必须来自运行日志体系，不把日志当审计。

### 4.4 后置能力

- 运维日志检索。
- 系统健康诊断页。
- 错误码知识库。
- 日志导出和脱敏。

## 5. 秘书显示边界

### 5.1 最终产品边界

秘书是独立的人性半身悬浮标，不是普通右侧详情里的一个小组件。

已确认：

- 工作台下方常驻聊天框取消。
- 秘书悬浮标默认右下角，可拖动。
- 不挡住画布节点、项目列表、消息输入框。
- 全屏画布、会话详情、项目工作流里都显示。
- 设置页、登录页、错误页可以弱化或隐藏。
- 有待确认事项时显示红点或数量，不主动弹窗打扰。
- 工作台右侧也可以有秘书入口，但和悬浮秘书指向同一秘书能力。

打开秘书后：

- 主体显示最近聊天内容和输入框。
- 待确认事项、影响面报告、当前上下文、相关记忆、最近整理放在聊天框左侧或右侧辅助区。

秘书不能做：

- 不确认 worker 汇报。
- 不判断项目过程事实。
- 不当工作成果裁判。
- 不批准正式记忆。
- 不直接写正式记忆。
- 不直接派发任务。

### 5.2 中间版本必须落地

- 秘书入口和其他右侧详情分离。
- 秘书可显示最近聊天内容的入口形态。
- 秘书在记忆修改时可以输出影响面报告。
- 秘书只能整理、提醒、解释和收纳想法。

### 5.3 后端和数据依赖

- 最近聊天内容需要秘书会话 store。
- 影响面报告需要记忆关系、来源、引用、权限和使用记录读模型。
- 待确认事项需要统一确认队列。

### 5.4 后置能力

- 半身悬浮形象的完整视觉和动画。
- 跨页面连续对话。
- 秘书长期人格和偏好记忆。

## 6. 项目页显示边界

### 6.1 最终产品边界

项目页结构：

- 左侧：项目列表，只显示项目名和少量状态。
- 中间：当前项目主区域。
- 项目内横向切换：工作流 / 智能体 / 文档 / 记忆 / 设置。
- 右侧：节点详情或项目上下文详情。

各 tab 只显示自己该显示的内容：

- 工作流：只显示项目工作流画布。
- 智能体：只显示该项目相关智能体会话。
- 文档：只显示该项目知识库资料。
- 记忆：只显示该项目相关记忆。
- 设置：只显示项目设置。

全局通知、待办、审计、运行中不塞进项目主画布。

### 6.2 中间版本必须落地

- 项目工作流页保持画布为主。
- 候选治理、任务包、权限、readback、审计等复杂信息进入节点详情或侧栏，不铺在画布主区域。
- 项目页不变成任务包管理器。

### 6.3 后端和数据依赖

- 项目详情需要 project read model。
- 项目画布需要 workflow read model。
- 项目记忆需要正式记忆读模型和权限过滤。
- 项目文档需要知识库索引。

### 6.4 后置能力

- 项目内完整设置页。
- 项目文档和 Obsidian vault 深度联动。
- 项目级记忆关系图可视化。

## 7. 智能体入口显示边界

### 7.1 最终产品边界

`智能体` 是原会话中心，但应接近 Codex 原生体验。

默认显示：

- 智能体列表：Codex、Claude Code、OpenClaw、OpenCode，先有谁显示谁。
- 会话列表：按项目、时间、状态收纳。
- 会话详情：用户消息和智能体回复，长内容默认收纳。
- 运行中会话：正在执行什么、是否需要权限、是否卡住。
- 搜索和过滤：按项目、时间、标题、智能体、状态。

不默认显示：

- adapter schema
- 模型能力声明
- 内部 transcript key
- sqlite / index 来源
- 原始 event log

中间版本最终必须支持发消息继续会话。

### 7.2 中间版本必须落地

- 查看、搜索、过滤、收纳、错误分类。
- 会话详情默认只显示用户消息和智能体回复。
- 工具调用、命令输出、权限记录和长日志默认折叠。
- 发消息继续会话要进入中间版本最终目标，但必须单独设计权限和安全边界。

### 7.3 后端和数据依赖

- 会话目录主权威是 sqlite，index 只能作为缓存 / 兼容 / 辅助。
- transcript 读取应走 Rust 原生 parser。
- 发消息需要 agent controller、权限确认、运行状态、取消和 readback 错误可见化。

### 7.4 后置能力

- 停止、重启、resume 操作完善。
- 删除、导出、标记、收藏、分享。
- 多会话对比。
- 会话 lineage。

## 8. 画布入口显示边界

### 8.1 最终产品边界

一级 `画布` 默认打开是可编辑无限画布，不是列表页。

一级画布可以切换到：

- 画布库
- 工作流总览
- 模板
- 运行记录

项目里的画布和一级画布调用同一个画布模块，功能模块复用；区别在上下文、数据归属和执行权限。

### 8.2 中间版本必须落地

- 一级画布可以实验运行。
- 实验运行不能写正式项目状态、正式记忆或项目任务。
- 真实项目工作流必须绑定项目或发布到项目后运行。
- 项目画布里的运行才是正式项目工作流运行。

### 8.3 后端和数据依赖

- 画布模块需要明确 canvas context：global / project / template / experiment。
- 项目执行必须经过控制核心和 workflow state。
- React Flow 只是渲染映射，不是事实源。

### 8.4 后置能力

- ComfyUI 类可视编辑深度能力。
- 画布库资产管理。
- 模板发布流。
- 复杂节点运行预览。

## 9. 记忆中心显示边界

### 9.1 最终产品边界

`记忆` 是能看懂的记忆中心，不是治理后台。

默认显示：

- 用户偏好
- 项目记忆
- 待确认记忆
- 最近变化
- 冲突和过期
- 使用记录

默认不显示：

- schema
- 内部 key / id
- 原始召回分数
- 原始审计结构
- 原始图谱结构

正式记忆可以编辑，但不是直接覆盖：

1. 用户点击编辑。
2. 系统生成修改提案。
3. 秘书输出影响面报告。
4. 用户确认。
5. 系统写入正式记忆并留下审计。

确认权：

- 用户偏好：必须用户确认。
- 安全边界：必须用户确认。
- 跨项目记忆：必须用户确认。
- 项目事实：可以由项目主管确认，高风险交给用户。
- 临时任务记忆：可以进入候选，不自动写正式记忆。

图关系可以作为展开项显示，但必须翻译成人话。

### 9.2 中间版本必须落地

- 记忆中心作为一级入口。
- 展示正式记忆、候选记忆、最近变化和待确认事项。
- 记忆被任务使用时轻提示，例如“使用了 3 条记忆”。
- 重要决策受记忆影响时，结果报告里说明。
- 冲突、过期、需要确认时进入待办。

### 9.3 后端和数据依赖

- FormalMemoryStore。
- MemoryVersion。
- MemoryAuditEvent。
- MemoryCandidate。
- MemorySourceRef。
- MemoryConflict。
- Memory relation / entity read model。
- TaskMemoryPacketBuilder。
- 权限过滤。

### 9.4 后置能力

- 成熟模式。
- 跨项目记忆提升和下沉。
- 记忆合并、拆分、冻结、归档。
- 图谱可视化高级编辑。

## 10. 知识库显示边界

### 10.1 最终产品边界

`知识库` 是资料和笔记空间，偏 Obsidian / vault / 文档管理，不是另一套记忆。

默认显示：

- 文档库 / 笔记库
- 项目资料
- 设计文档
- 决策记录
- 研究材料
- Obsidian vault
- 最近编辑
- 和记忆有关联的文档

知识库文档详情可以显示：

- 关联记忆
- 待确认记忆候选
- 哪些正式记忆引用了这篇文档
- 从文档选段提取为记忆候选

知识库不直接编辑正式记忆。

### 10.2 中间版本必须落地

- 知识库作为一级入口。
- 明确知识库和记忆的边界。
- 文档内容可以被引用、总结、提出记忆候选。
- 只有经过记忆流程确认后，才进入正式记忆。

### 10.3 后端和数据依赖

- 文档索引。
- 文档引用和来源锚点。
- 记忆候选生成入口。
- Obsidian-compatible vault 配置。

### 10.4 后置能力

- Obsidian 原生功能深度内置。
- 双链、标签、图谱、插件兼容。
- 文档版本和引用漂移检测。

## 11. 通知、待办、运行中

### 11.1 最终产品边界

- 通知：发生了什么。
- 待办：需要用户处理什么。
- 运行中：系统现在正在干什么。

三者不合并。

### 11.2 中间版本必须落地

- 方案确认、结果验收、记忆修改确认、高风险权限进入待办。
- 任务完成、agent 出错、权限被拒绝、记忆候选生成进入通知。
- 项目工作流运行、智能体执行、卡住状态进入运行中。

### 11.3 后端和数据依赖

- Notification read model。
- Todo / approval queue。
- Running workflow / agent run read model。

## 12. 管理和设置边界

### 12.1 管理

管理显示系统运维、审计、日志和健康状态。

包含：

- 审计
- 日志
- 权限
- 健康状态
- 数据位置

默认只显示健康状态和最近错误。

### 12.2 设置

设置只管用户主动配置。

包含：

- 外观和布局
- 默认智能体偏好
- 自动化程度
- 通知方式
- 秘书显示方式
- 知识库 / Obsidian 基础配置
- 项目默认规则
- 数据备份和导出

设置不显示：

- 原始日志
- 错误堆栈
- adapter schema
- 内部数据库状态

## 13. 首页显示边界

首页 UI 内容已经确定，本文不重新设计首页。

允许轻量显示：

- 最近项目
- 待确认事项数量
- 运行中项目 / 工作流数量
- 秘书悬浮标

不在首页展开：

- 记忆系统细节
- 审计流水
- 原始日志
- adapter 细节

## 14. 工作流画布节点显示边界

画布节点默认只显示：

- 节点名称
- 节点类型
- 当前状态
- 负责方
- 少量进度或提醒

点击节点后，右侧详情显示：

- 输入和输出
- 执行摘要
- 关联会话
- 关联文档
- 关联记忆
- 权限请求
- 日志摘要
- 错误原因
- 可执行操作

不默认显示：

- 原始 JSON
- schema
- 内部 id
- raw transcript
- 完整日志
- adapter 细节

## 15. 自动化工作流过程显示

用户默认看到：

- 方案待确认
- 正在执行
- 等待结果验收
- 已完成
- 出错

点开详情才看到：

- 执行摘要
- 关键风险
- 失败原因
- 产物列表
- 证据链接
- worker 汇报
- 项目主管确认过程

不默认把每个 worker 长汇报、日志、原始会话全部铺出来。

## 16. 权限和安全边界显示

低风险自动操作不弹窗，只在运行中和审计里留记录。

高风险操作才弹确认，例如：

- 写文件
- 改正式记忆
- 执行命令
- 迁移数据库
- 删除内容
- 访问敏感路径

权限弹窗必须用人话说明：

- 要做什么
- 为什么要做
- 会影响哪里
- 风险是什么
- 谁提出的
- 批准后会发生什么

按钮：

- 允许一次
- 拒绝
- 查看详情

默认不提供永久允许。永久允许只能在设置或权限规则里专门配置。

所有批准和拒绝进入 `管理 > 审计`。

## 17. 错误和失败显示

错误分三层：

1. 普通用户层：一句人话说明。
2. 影响层：说明影响什么。
3. 技术详情层：可展开给开发或运维看。

错误分类：

- 数据缺失
- 文件不可读
- 权限不足
- 智能体不可用
- 工作流失败
- 记忆冲突
- 系统异常

不直接把 traceback 扔给用户。

## 18. 智能体会话详情显示

默认显示：

- 用户消息
- 智能体回复
- 代码块和复制按钮
- 工具调用摘要
- 权限请求记录
- 最终结果摘要

默认收纳：

- thinking / 推理过程
- 工具原始输出
- 长日志
- 系统提醒
- 大段执行记录
- 原始 transcript event

可展开查看：

- 工具调用详情
- 命令输出
- 文件变更
- 错误详情
- 时间线

## 19. 记忆使用提示

记忆被自动使用时默认轻提示：

- 任务详情显示“使用了几条记忆”。
- 点击可展开具体记忆。
- 重要决策受记忆影响时，结果报告里说明。
- 普通召回不弹通知。
- 记忆冲突、过期或需要确认时进入待办。

## 20. 角色显示

不做角色管理后台。

只在相关位置显示责任方：

- 全局主管：方案边界和最终结果。
- 项目主管：项目执行过程和 worker 汇报。
- worker：具体任务节点执行者。
- 秘书：解释、整理、提醒、影响面报告，不当审批者。

## 21. 证据、handoff 和开发者模式

普通产品 UI 不直接显示 `evidence` / `handoff` 这类工程文件名。

结果报告用人话显示：

- 改了什么
- 验证了什么
- 还没验证什么
- 相关文件

管理 > 审计 可以看到更完整记录。

开发者模式默认关闭。打开后才显示：

- 原始 evidence / handoff 路径
- 内部 id / key
- schema / version
- raw transcript event
- 原始日志路径
- adapter capability 细节
- sqlite / index / cache 状态
- 诊断按钮

## 22. 对中间版本开发的约束

中间版本不是一次性完成本文全部最终形态。

当前最应该优先进入任务包的是：

1. 记忆中心的 M4-M13 显示和后端配套。
2. 自动化工作流的方案、执行、结果、风险和确认事项显示。
3. 智能体会话的发消息、运行状态和权限边界。
4. 管理入口里的审计、日志、健康状态和数据位置。
5. 一级画布与项目画布复用模块的上下文边界。

后置但必须保留方向的是：

- 秘书半身悬浮形象完整视觉。
- Obsidian 原生功能深度内置。
- ComfyUI 类复杂画布能力。
- 多 agent 完整操作集。
- 图谱高级编辑。

## 23. 验收标准

后续 UI 任务验收时，必须检查：

- 主界面有没有把内部治理信息直接铺给用户。
- 记忆和知识库有没有混成一套东西。
- 秘书有没有越权审批、写记忆或派任务。
- 项目页是不是仍以项目工作流画布为主。
- 智能体页是否默认只显示主对话和必要摘要。
- 权限、错误、证据是否用人话表达。
- 开发者模式是否默认关闭。
- 需要后端读模型的内容是否没有靠前端假数据冒充。
