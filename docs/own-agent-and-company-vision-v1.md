## 1. 公司类比：已有什么、缺什么

公司的本质不是一群人，是一套让普通员工也能产出可靠结果的制度。按这个标准对照现状：

| 公司部件 | 工作台对应物 | 状态 |
|---|---|---|
| 公司制度 | 任务包 / decisions / evidence / handoff | 已有，146+ 任务包验证 |
| 组织结构 | 全局主管 / 项目主管 / worker / 复核线 | 已有 |
| 档案室 | 记忆层 M1-M13（含候选→确认→转正链） | 已有 |
| 审计部 | audit events，不可删除 | 已有 |
| 人事部 | 角色技能派发 / 技能注册表 | backlog 种子 |
| 秘书 / 顾问 / 监察 | CEO 秘书 / 咨询 agent / 方案+反对双 agent | backlog 种子 |
| **账房** | **无**——记了谁干了什么、干得怎么样，没记花了多少 | **缺口**，已登记 backlog「Agent 成本记账」 |

类比的失效边界（防止用过头）：**agent 员工不担责**。真公司员工搞砸要负责所以可以放权；agent 搞砸，后果全部由用户承担。推论：确认门、审计、evidence 不是创业期脚手架，是**永久宪法**——agent 接管的管理职能越多越重要。任何"agent 足够聪明了能不能跳过确认"的提议，答案预先写在这里。

## 2. 自有 agent 的定义（用户已拍板）

**自有 agent = 常驻角色 = 固定 LM + 固定能力/权限，能力外部文件化。**

展开成职位模型：

- **职位 = 档案（能力）+ 权限面 + 当前配的脑（LM）。**档案 = 角色说明（prompt）+ 工具面（给哪些 MCP 工具）+ 上下文注入（开机读哪些文件）。
- **员工 = 档案，不 = 模型。**模型是职位配的"脑"。
- **"常驻"指身份、权限、记忆常驻（落文件层），不必指进程常驻。**与 `decisions/2026-05-31-editable-canvas-codex-as-director-v1.md` 的主管每次重起、记忆全落文件层不冲突：进程按需拉起，起来就是"同一个人"，因为读的是同一份档案和同一份记忆。
- 固定权限 = 权限面声明式写在职位档案里，对应权限四层设计（吸收文档 §2.4）中"角色策略"的实体。

为什么固定 LM 重要：**信任记账需要稳定对象。**授权额度挂在"档案+权限+LM"都钉死的职位上才有所指。

为什么能力/立场必须外部文件化（2026-06-11 审计讨论的结构性理由）：**LLM 没有"立场存档"，只有当场连贯性**——上一轮定下的口径不会自动约束下一轮生成，前后矛盾不是粗心是结构缺陷（当日实例：Claude 同场先说"员工=档案"、后又顺嘴说"换模型=换人"）。解药不是更强的模型（更强只是矛盾得更隐蔽），是把立场从对话里拽出来写成文件、开机注入。**decisions/ 制度对人是好习惯，对自有 agent 是刚需**——任何常驻角色的档案都必须含"开机读哪些立场文件"。

## 3. 咨询团（用户已拍板）

- **咨询角色不止一名，且应是不同模型。**用户判断依据：Claude 强，但 Codex 给出的是不同角度的思考。
- 口径：**能力来自档案，视角来自模型。**（修正用户早先"擅长与模型无关"的说法：能力确实来自 prompt+工具+上下文，但视角多样性来自模型差异。）
- 推论：方案+反对双 agent 必须用不同模型——同一模型自己反对自己，会在同样的盲区里一起瞎。
- 会诊规则：同一问题各自**独立**出意见（互相看不到对方的，防带偏）→ **分歧点并排呈现** → 用户只裁分歧，一致部分直接过。
- 成本控制：顾问越多裁决负担越重。日常小事单顾问；**要写进 decisions/ 的事才开会诊**。
- 咨询角色的档案规格（六条）见 backlog「咨询 agent」条目（2026-06-11 版）。

## 4. 模型升级与信用（用户已拍板 + Claude 建议待表态）

- **已拍板：升级非换人，已挣授权额度继承。**新模型拿同样档案不算新人，不归零、不设试用期。依据：员工=档案，模型是职位配的脑；模型代际升级总体各方面变强。
- **Claude 建议（待表态）**：换脑后免确认照旧，仅对头 N 次免确认操作加密**事后抽查**（体检不是试用期；理由：新脑能力不降但行为风格会漂，而免确认区恰恰没人看）。模型版本号写进职位档案，**升级作为显式人事事件留审计**——万一行为漂移可定位"从哪天换脑开始"。

## 5. 权力边界与授权分级

- **agent 管事，用户管决定。**管理分两层：管平台运转（整理信息、维护记忆、巡查审计、排队列）可放手给 agent；管用户的决定（做什么、算不算完成）永远不交。理由不是 agent 不够聪明，是不担后果（见 §1 失效边界）。
- **扩编的通路 = 授权分级 = 成熟模式升级为授权机制**：某类操作在用户亲手确认下成功 N 次 → 允许"转正"为免确认 + 留审计 + 随时可召回。**每一次转正本身必须用户拍板，召回权永远在用户。**这是 M12 成熟模式的延伸（对应吸收文档 §3.2 mature pattern → harness rule 方向）。
- 配套件已在吸收文档：稳定工作流豁免、临时一跳授权、有效期、确认队列。

## 6. 信任阶梯的顶端：脚本化

完整的信任阶梯：

```
LLM 即兴（每次确认）
  → LLM 受确认（高风险点确认）
    → LLM 免确认（成熟模式转正，留审计）
      → 脚本（不再需要 LLM：零 token、零随机、可测试、无需信任）
```

- 判据一句话：**"这件事的输入输出，能不能用一句话说清规则？"能 → 写脚本或调已有脚本；不能 → 才派 LLM。**
- 分类澄清（防误引）：世界上有三种程序，不是两种——写出来的脚本（规则可读、行为确定、近零成本）/ 学出来的窄模型（如推荐算法：与 LLM 同物种，学出来的、不可读、概率的，只是赛道窄）/ 学出来的通用模型（LLM）。"推荐算法很强"支持的是**专才碾压通才**，不是"脚本碾压 AI"；真命题是**规则说得清的事，脚本碾压 LLM**。prompt/skill 不与脚本竞争，它们是给"规则说不清"的剩余部分用的。
- 健康分工：LLM 负责判断，脚本负责执行，prompt 把两者接起来。手脑解耦再下推一层：手分确定的手（脚本）和灵巧的手（worker agent），能用确定的手就不用灵巧的手。
- 项目已有同款投票：shape gate 用脚本数行数、readback stats 迁 Rust 原生 parser。
- 落地条目：backlog「成熟模式沉淀为可执行脚本/工具」。

## 7. 扩编顺序与第一个自有员工

- 扩编顺序**不变**：先跑通单 Director + specialist → 加咨询（旁路风险低）→ Director 上下文塞不下或调度成瓶颈才分组。公司化愿景不改变这个节奏——**活多到干不完才招人，不先画满组织架构图**（最大的坑是组织架构表演：一堆头衔好听没活干的角色，白烧 token）。
- 第一个自有员工建议（Claude 提名，未拍板）：**记录员/秘书**——只管信息不管决定，风险最低，直接治原始痛点"接住 vibe"。
- 量化配套：成本与信任指标遵守哈伯德"只测会改变决策的数字" + 古德哈特警示"指标只当证据不当裁判"（见 backlog「Agent 成本记账」参考材料）。
