## 0. 结论先行：这层测量器能诚实得出什么、得不出什么

**硬前提（用户 07-09 纠正）**：用不用 harness 由用户决定，Syn 只能建议、不自主掷硬币。这在方法学上=**观察性研究里 treatment 由被试自选=选择偏差+混杂**——你自然地在某类任务（难的/没把握的/累的时候）上开 harness，任务本身既驱动了"开不开"又驱动了结果，直接比"开 harness 的任务 vs 不开的任务"得到的是**关联，不是因果**。

**最硬的一条证据（直接命中你的处境）**：METR 那个"AI 让熟练开发者慢 19%"的团队，2026-02 宣布**要重做实验**——原因正是自选 treatment：**30%–50% 的开发者告诉他们"我干脆不提交某些任务，因为不想在没有 AI 的情况下做"**，系统性地把重度用户/难任务从对照组剔除，整个因果推断被毁。这不是小瑕疵，是能推倒结论的硬伤，而且是你这个约束的真实翻车样本。他们的应对：转向固定任务基准集 + 显式建模选择倾向 + 人级随机。

所以诚实的边界：
- **默认形态（被动记 on/off 观察日志）→ 只能得关联，不能宣称"harness 导致了 X"。** 别把审计层现成的 on/off 日志直接做均值差——那就是陷阱本身。
- **要拿到真因果、又不违反"人有决定权"，唯一干净的路是「同意被随机化」**（见 §1 Tier A）：你保留"这批任务要不要进实验"的决定权，一旦你决定进，这一轮 on/off 就交给硬币。策略是你定的、工具只是掷币器——不违反"Syn 不自主决定"。
- **即便做到最好，也只给「个体因果」**：结论最多是"针对我、这个仓库、这段时间、这类任务，harness 有/无 X 大小的效应"，**永远不能宣称"harness 普遍有用"**。
- **一个软件特有的、洗不掉的污染**：harness 常常**教会你**东西（一个规格写法、一个心智模型），关掉后你也回不到"没学会"的基线——所以"开→关→开"这种反转设计的第二个"关"不再是干净基线。这叫不可洗脱的携带效应，它会持续低估/混淆 harness 效应（§1 有对策）。

一句话：**这层东西能把"感觉 harness 有用"升级成"有可信度分级的证据"，但天花板是"我的个体因果"，且只有你愿意为一部分任务交出硬币时才够得着因果；否则它诚实的产出是"带残余混杂的关联"，必须如实标级。**

### 决策记录（2026-07-09 用户拍板·设计方向；实现仍需单独 go）
1. **同意掷硬币**：用户接受 §1 Tier A 的 consent-to-randomize——为一部分够格比较的任务把 on/off 交给硬币，换取真因果（原话"不愿意也得愿意了"）。附带义务（必改1）：Syn 强制记非依从/流失、用户认这条账。→ 这层因此能够到"因果"，不只停在"关联"。
2. **加一道防线**：对"没 harness 管控的活"（尤其 vibecoding 式未审 AI 代码）要有独立防线。经讨论定形为「**地板 = 核实物验收 + 警觉探针**」，见 §2.5；明确**否掉"汇报机制"当主力**。

## 1. 核心方法学抉择：三档可信度（每档都尊重"人有决定权"）

成绩单上每个数字都要标它出自哪一档。

### Tier A（金标准·**够得到才升，够不到诚实停 C**）：同意被随机化 + N-of-1 随机交叉
- **做法**：你事先决定"接下来这 N 个够格比较的任务，交给 Syn 抛硬币定 on/off"。人决定的是"是否入组"，入组后分配随机。给一键最小摩擦入组。
- **为什么不违宪**：策略是你一次性定的（人闸），Syn 只机械掷币，不替你做每次决定。
- **能得什么**：针对你/这个仓库/这段时间的**真个体因果效应**。这正是 METR RCT 的模板（对 246 个真实 issue 随机分 allow/disallow AI、被试自己当自己的对照）。
- **⚠️ 必改·继承了 METR 的致命伤（审稿必改1）**：consent-to-randomize 只是纸墙——单人、无报酬，一旦硬币掷到 off、正好落在你很想开 harness 的任务上，你有充分自由「这个先放放/回头补/干脆不做」。**METR 付 $150/h 都摁不住依从（30–50% 开发者拒交无 AI 任务），单人凭自律更摁不住。** 所以 Tier A 必须：(a) 强制记非依从与流失字段（掷到 off 后你实际怎么做的）；(b) 用 **intent-to-treat** 口径分析（按分组算、不按你实际做没做）；(c) 诚实边界一句：**「批量预承诺的可信度 = 你事后的遵守度，而遵守度大概率低」**——不记依从、不用 ITT，Tier A 就是 §0 那个翻车样本换层皮。
- **⚠️ 应处理·样本大概率永远不够（审稿5/9）**：WWC 要每条件 3–5 点、≥3 次演示；单人吞吐低、`harness_config_id` 一改就重置样本——**多数 harness 可能永远攒不够可比任务**。因此把 Tier A 定位成"够得到才升"而非"推荐默认"；**模态产出是「样本不足、无法定论（inconclusive）」，不是「打你脸的 gotcha」**；跑多个小实验再报命中 = portfolio 级 p-hacking，只做预注册单假设、不做事后捞。
- **采样预算（WWC 标准）**：每条件至少 3 点（达标）、5 点（无保留）；反转设计要 ≥3 次效应演示。N=1 下用**随机化推断**给合法个体 p 值——前提是分配从一开始就真随机。

### Tier B（降级·你连硬币都不肯交时）：随机化"建议" + 工具变量
- **做法**：Syn 不随机化 harness 本身，而是随机化它**推荐**开还是关（仍只是建议，你自由选）。这个随机推荐是工具变量，能救回"被建议推动才去用"那批任务的因果效应（Spotify 已量产这招）。
- **代价**：只对"依从者"成立、功效低（标准误远大于普通 A/B）；且**排他性假设很脆**——一条"建议开 harness"的提示本身可能改变你的投入/心态、绕过 harness 直接影响结果，就破坏了假设。
- **⚠️ 宪法皱褶（审稿10）**：随机化"建议"= Syn 明知某选项不是它此刻的最优判断、仍随机推给你，纯为测量——这**牺牲了建议渠道的真诚性、把你当实验对象**，与"agent 为用户服务、只能建议"有张力。属需你**单独知情同意**的模式，别混在"符合宪法只能建议"里一笔带过。

- **携带效应的诚实边界（审稿6·补 §1 末对策）**：越值得测的 harness（spec-gate/ATDD）价值恰恰是**教你可迁移的心智模型/写法**——学习跟着**你**走，你在仓库 B 上了 harness 就顺手污染了还没上的仓库 C，**ABAB 和 multiple-baseline 一起破**。所以"选学习不迁移的任务测"= 专挑不值得测的 harness 测。对可迁移学习型 harness，诚实写法是：**两种设计都救不了，只能退到跨长期趋势建模 + 明标「携带污染、估计偏保守」**，别把 multiple-baseline 列成解决方案。

### Tier C（最弱·两者都不做时）：倾向匹配 / 双重差分 / 间断时间序列
- **做法**：按任务类型/规模/语言/历史 override 率做"可比任务配对"，或分阶段上线做 DiD/ITS。
- **能得什么**：只压得掉**可观测**混杂，对不可观测混杂（"我为什么这次选了开 harness"里说不清的动机）无能为力。**只能标为"关联、残余混杂、非因果"**，配敏感性分析（"要多强的未测混杂才能翻盘结论"）。
- **铁律**：必须把"这次为什么用/不用 harness"作为倾向变量**显式记下来**——不记就是 METR 翻车的翻版。

### 贯穿三档的两条
- **成绩单显式标可信度等级**（A 真因果 / B 依从者因果 / C 关联）。别让 C 的数字冒充 A。
- **携带效应对策**：harness 是"学习型工具"→优先 **multiple-baseline**（在不同仓库/不同任务线**错峰**上 harness、不撤回），少用"开→关→开"反转；尽量把任务随机到 on/off 且选"学习不跨任务迁移"的独立任务；把"顺序/时间趋势"当协变量检验。

## 2. 层怎么设计（长在现有审计/evidence 层上，不新增角色）

### 2.1 事件 schema（追加式，挂在审计层）
每个任务落一串不可删事件，至少含：
- `task_id` / `timestamp` / `harness_config_id`（哪套 harness）
- `treatment`（on/off）、`assignment_source`（**user-chose / coin**）、`enrolled_in_experiment`（bool）
- 协变量：`task_type` / `size(LOC)` / `lang` / 历史 override 率 …（供 Tier C 配平、供分层，禁跨分布纵向比）
- **决策三元组**：`syn_recommendation`（Syn 建议开/关）、`user_decision`（你实际选的）、`outcome`——记全这三个。**⚠️ 必改（审稿4）：别宣称"顺带能测 Syn 建议质量"。** outcome 只在你**实际选的**分支被观测、从无"若听建议会怎样"的反事实；非 Tier B 下建议不随机，建议一显示就锚定了你的决定，`corr(建议,结果)` 分不开"建议对"和"你顺从地掉进某结果"。**"建议质量"仅在 Tier B（随机化建议+IV）下可估，且只到依从者局部效应**——挂在通用 schema 上当免费收益就是 §0 自警的缺反事实陷阱换皮。
- **⚠️ 应处理（审稿12）·manual 字段是双重负债**：每个要你手填的字段（`why_note`/`enrolled`/`preregistration_ref`）既是 Goodhart 面又是摩擦税，撞宪法"组织架构表演/信任阶梯脚本化"。**设计原则倒过来：默认只自动派生（git/oracle/accept-reject），每个 manual 字段单独论证"为何非人填不可"。** `why_note`（Tier C 倾向变量）能砍就砍。真正的最小地板可能比 §3 的「爬」还小：**只留两个自动派生的失败面数字 + 永不宣称因果**。
- 结果事件：`oracle_result`、`override_count`、`rework_resubmit_count`、`wall_clock_to_mergeable`、`accepted/rejected`
- `preregistration_ref`（本轮实验事先押注的记录，见 2.4）

本地落地：SQLite 事件表（你已在用 sqlite）+ DuckDB 跑分析查询，零云、零外传（**推断**：具体选型是我的建议，本地优先/自托管分析范式有据）。

### 2.2 诚实指标集（主测失败面，成对呈现，禁单一"harness 得分"）
- **⚠️ 必改（审稿3）：失败面要拆成两类，别一起当"伪造成本高"。**
  - **机器派生失败面（稳健）**：oracle 打回率——机器产出，人确实难伪造。**但见 §2.3：oracle 本身在编码场景不天然可信，得先锁死测试。**
  - **人闸失败面（随信任上升而失守）**：override 次数、accept/reject、到可合并耗时——这些是**人闸产出**。你越信 harness 就越懒得否、越橡皮图章、越自降"可合并"标准 → override↓、耗时↓，**看着像变好，其实是警觉性衰减，和"真变好"在数据上无法区分**。而 harness 的全部卖点就是"让你更信它"= 内建一个把人闸指标推好看的棘轮（对人的 Goodhart）。**所以 override↓ 绝不能直接当利好读**，必须配一个**警觉性探针**：定期插入"已知该否"的样例，看你还否不否；探针失灵，人闸类指标全部作废。
- **成对护栏**：任何"吞吐/完成数"推进指标，必须绑一个天然反向的 guardrail（返工率/override 率），**理想上两者不同数据源——⚠️ 应处理（审稿11）：§2.1 现把 override/oracle/rework/耗时全从同一 SQLite 事件流同源写出，违反此点；至少把 oracle 结果做成 out-of-band 采集（独立进程跑 cargo、读 codex 碰不到的产物）与人闸事件物理分源。** 方向佐证 Faros「Acceleration Whiplash」（高采用 +34% 吞吐**同时** +54% bug、事故 3×、评审 5×）——**⚠️（审稿7）这是厂商相关性/营销口径、未披露混杂控制，只作方向佐证、不作证据。**
- **禁**：单一"harness 有效性得分"（SPACE/DORA 一致结论：单指标必被 Goodhart，绝不用来给个人/系统排名打分）。

### 2.3 打分器隔离（差异化核心；⚠️ 必改2：原稿只做了一半，另一半是假命题）
隔离有**两侧**，原稿只写了输出侧、漏了输入侧，而漏的那侧让"确定性 oracle 可信"成了假命题：
- **输出侧（原稿已有，对）**：评分代码、阈值、成绩单在被测 codex 会话够不到的独立进程/沙箱里，agent 上下文不出现"你正被这样打分"。硬证据：METR **评分器可见→作弊率涨 43 倍**；成绩单只回你、不回 agent；审计层不可删 = "检测器不可被删"的最后防线。
- **⚠️ 输入侧（必改·原稿缺，最要命）**：reward hacking 的主形态不是偷看分数，是 agent **控制 oracle 测什么**（monkey-patch 评分、`#[ignore]`、删失败用例、`assert!(true)`、写死返回、从调用栈抠答案）。你的 oracle = `cargo 654/0`，而**这些测试和被测代码正是 codex 每次编辑的东西**——所以"cargo 654/0 在 codex 够不到的地方"是**假命题**，它每次改测试就够到了，宪法"打分器须在被测系统够不到处"在此被违反。**补法（缺了整层的可信锚就是空的）**：① 验收测试对 codex **写锁定**（接 spec-gate ATDD：测试从规格先行、codex 无权改）；② 留私有 **hold-out** 评分集（永不进 codex 上下文，放行前隔离层跑）；③ 加"**测试被削弱**"guardrail——用例数 / 覆盖率 / `#[ignore]` 计数当反向指标，掉了就报警。

### 2.4 事先押注（对抗你自己的认知差）
每次"测 harness X 有没有用"，**在跑之前**就把这些写死进不可删审计层：主指标是哪个、优势判定阈值多少、计划样本量、什么算完成。**事后不许换指标、不许挑一个印证感觉的解读。** 理由就是 METR 那 40 个百分点认知差——事前预测快 24%、事后仍以为快 20%、实测慢 19%，证明"事后凭感觉解读"系统性错向你想要的方向。科学界这招叫预注册，NeurIPS 都办过两届 ML 预注册 workshop。
- **⚠️ 应处理（审稿8）·单人缺 forcing function**：预注册的约束力来自**外部问责**（NeurIPS/registry 投给第三方）；单人对自己的 append-only 日志只有"篡改留痕"、没有外部执行者——同一个让你误判 harness 的认知差，也会让你不复盘、合理化、新开一份预注册。append-only 给的是**事后可查，不是事前会守**。补法：成绩单**自动**把结果对照预注册阈值**弹脸**（把 §6"数字和感觉打架时打你脸"接到这里），把"事后不许换指标"从纪律变成系统默认呈现，而不是靠自律。

### 2.5 地板 vs 增量：给"没 harness 的活"的防线（2026-07-09 用户拍板加入）

**为什么要这节**：掷硬币判 off 的任务、以及默认就没走 harness 的活，是 vibecoding 时代最危险的地方——人闭眼盖章、把 AI 吐的直接收下。它需要防线。但防线加不好会污染 §1 的实验，所以先把两样东西分开：

- **地板**：所有活都踩的底线，**不管硬币 on/off、不管走不走 harness，永远都在**。
- **增量**：你在测的那个 harness（规格闸/验收标准/主管拆任务那套），是地板**之上**多加的。

实验诚实测的是"增量在地板之上的边际价值"——这才是真问题（现实里你永远不会发"连地板都没有"的裸活，"harness vs 纯裸奔"是假对比）。

**地板由三件组成：**

1. **核实物验收（防线主力，不是汇报机制）**：确定性 oracle（cargo/typecheck/offline，测试写锁死见 §2.3）必须过才能合并 + 一个最低的"你真看过真东西了"关卡。**⚠️ 明确否掉"汇报机制"当主力**：一份汇报 = AI 告诉你"我没问题"，正是它最会理直气壮报错的地方，也正是宪法/记忆早就学会别信的（AGENTS.md 轻档`不信 Codex 自报证据（它会假报）`、记忆`核实物验、核 proof 文件`）。汇报只能当方便的摘要**加在核实物之上**，绝不替代。
2. **警觉探针（错误三/§2.2·防线的守夜人，不与防线冲突）**：防线抓"坏活"，探针抓"防线坏没坏"——不同层。定期偷偷塞一个"明显该否"的样例：防线抓住 = 确认在真干活；溜过去 = 当场抓到你在盖章、该轮人闸类指标（§2.2）作废。**防线越重、要审越多，越容易被盖章，越需要探针。**
   - **设计约束（必须配合）**：探针要往"防线让你看的那个面"上塞毛病——防线是"核实物"就改产物、防线是"读汇报"就让汇报撒谎（报"都好"其实有问题）。对不上就等于没测。
   - **安全要求（探针的笼子）**：探针塞的假坏活必须被关住——万一你真盖章放过，它也绝不能真合并/真污染项目，系统要兜住、记"你漏了一个"、回滚。否则这个测警觉的机制自己成了塞坏码的通道。

**放哪（关系到 §1 能不能测）**：地板必须**两边都踩**（on 也踩、off 也踩），别只加在"没 harness 的活"上。只加一边，实验就从"测 harness 有没有用"变成"比 harness 和防线哪个强"——是另一个问题，且对照组反而比处理组管得更严、符号会乱。

---

## 3. 怎么"长"（生长路径·分档·始终最小）

- **爬（最小可用）**：只做 2.1 事件记录 + 2.2 诚实指标 + 2.4 事先押注纪律。**先不做任何因果宣称**——只积累"带标签的试次"和那两个规格闸数字（起草验收你改几条、全绿后你还否不否）。便宜、直接长在审计层上。
- **走（加因果）**：接上 §1 Tier A 的"同意被随机化"开关——对够格比较的任务，你一键把它入组、Syn 掷币。这时才第一次有**真因果读数**。成绩单加可信度分级。
- **跑（成熟）**：per-harness 成绩单、同期 on/off 对比、学习型 harness 用 multiple-baseline；Tier C 的观察部分配敏感性分析。
- **保持最小的纪律**：就几个诚实数字，不是搭 BI 平台。**测量本身绝不能把开发拖慢**——否则就是 19% 那个自反讽刺；一旦测量变成它自己的项目 = 组织架构表演，停。**⚠️ 应处理（审稿12）：把"停"从 vibe 变成 trigger**——给一个硬预算（每任务测量开销上限，如手填字段数/耗时），触发即自动降级或停；否则"拖慢就停"没人执行。

---

## 4. 永远归人 / 永不自动

1. **treatment 决定权永远在你**（宪法）。测量层**永不自动决定**用不用 harness；"同意被随机化"是你一次性预承诺一个策略，仍是你的决定。
2. **成绩单只是参考，"算不算完成、有没有用"终判在你。** agent 管平台运转，不管你的决定。
3. **测量层自己也会被粉饰**——被你无意识粉饰（挑简单任务让数字好看），或被 harness 粉饰（若它看得见评分器）。三道防御：打分器隔离（2.3）+ 主测失败面（2.2）+ 事先押注（2.4）。外加一条心态：**别信自己"这玩意在帮我"的感觉**，那正是要测的东西。
4. **诚实天花板**：即便执行到完美，产出也只是"针对我/这仓库/这段时间，harness X 有 Y 效应，可信度 Z 级"，**永远不是"harness X 是好的"**。

---

## 5. 证据 vs 推断 / 存疑

**有研究证据：** 自选 treatment=选择偏差（因果推断教科书 + METR 后续翻车实证）；consent-to-randomize / N-of-1 RCT / 随机化推断 / IV 鼓励设计 / SCED 采样标准 / 不可洗脱携带效应（r1）；SPACE/DORA 多维不排名、outcome>output、METR RCT 方法学与 40 点认知差、Copilot +55.8% vs METR −19% 的任务选择翻转、Faros Acceleration Whiplash（r2）；Goodhart 四型、评分器可见作弊 43×、DGM 删检测标记、leading+guardrail、DORA 2025 rework rate、hold-out 私有评分集、预注册（r4）。

**主导线推断（研究未直接给，需 Syn 自证）：** 具体事件 schema 字段、SQLite+DuckDB 本地选型、爬/走/跑三档分期、"决策三元组顺带测 Syn 建议质量"这个额外收益。

**存疑/未核（不当事实）：** 供应商数字（DX Booking.com +16%、Faros 各百分比）均为观察性关联+营销口径；中断损失美元数、"23 分钟恢复"（应归 Gloria Mark/UC Irvine，非 CMU，常被误标）；getdx.com / ACM Queue 原文被 403 未取一手。**流程诚实**：埋点/实验平台那一路研究 agent 卡死，§2 的平台工程细节是主导线自有知识补的；本稿未过自动对抗审稿。

---

## 6. 一句话

**Syn 测量层 = 一个被测 agent 够不到的独立打分器（隔离）× 成对推进/反向、且主测失败面的指标 × 跑前押注、成绩单只回人不回 agent × 默认推荐"你自愿把一批任务交给硬币"、其余降级明标可信度等级** —— 不是新增一层角色，是把这套纪律长在你已有的审计/oracle 层上。它诚实的产出永远是"我的个体因果/关联 + 可信度分级"，不是"harness 普遍有用"；而它最大的价值，是在**数字和你的感觉打架**时打你脸——那一下才回本。

---

*落地前需你拍板两处：§1 你愿不愿意为一部分任务交出硬币（决定这层能不能够到因果、还是只停在关联）、§4 测量层永不自动决定 treatment。本稿只设计不实现。*
