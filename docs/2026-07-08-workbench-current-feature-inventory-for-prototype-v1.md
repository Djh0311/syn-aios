## 一、按面盘点(对应原型六面)

### 面1 · 首页/工作台外壳
- 现状:左导航九入口;右侧栏 = 秘书 brief(待拍板计数/风险/建议)+ 详情面板;「打开秘书」钮。
- **没有**:项目群总览首屏;⌘K/NL 入口(Phase C);多项目并行视图(Phase E)。

### 面2 · 项目页(主体 UI / 执行资产已有真机证据；共享主管 transport 已离线接入，真实 App 尚未验收)
**交办 tab(默认页)·五态一块面**:
- **说（已实现的离线接线，非真实 App 验收）**:左栏通过与智能体页共用的 Conversation Transport 发送、续聊、poll 与 Stop；在 07-22 shared transport 基线中，主管入口由服务端固定为 `read-only + 空写根`，可信 turn binding 精确授予 `submit_proposal`。L3 v2 另行实现 `knowledge_search/read/open/cite` 四项只读能力；自然 reply、工具、projection 与 canonical 采用独立安全 receipt。旧 resident 路保留兼容但不再是交办主发送路径。**没有运行真实 App 或真实 Codex/MCP，因此不能把离线接线写成真实消息、落卡或产品可用已验收。**
- **批(右区授权卡)**:我来做 / 会改的文件 / 怎么验 / 🔓需要你允许 / 想改直接说 / [允许并开始][按我说的改][先不做]；**全局主管意见(批前边界)**块自动、async 不挡批、按方案幂等；复杂活的工序图只读展示步骤/依赖，保持「所批即所跑」。会话选择不再混在批卡或工序图里。
- **干**:逐格亮 + 「主管正在拆任务…(最长十几分钟)」+ [停下] + 看原始对话;新会话单显「正在为这单活新建会话(约 1 分钟)」;
- **交货**:「✓ 做好了(有 N 项要看一眼)」;产出行;**每任务行 = 标题 + 自述(worker 汇报)+ 徽章**(绿✓ / **黄牌⚠**[自述没干完·失败·没交汇报] / 执行态红灰优先);绿行 **[属实,沉淀]** → 记忆候选;**全局主管意见(结果复核)**块——自动、async、按轮幂等、pass/needs_rework/needs_human_check + 建议动作([按建议打回重拆]·意见不是闸);看原始对话/看最近对话;
- **卡住**:人话停因 + 死配对按钮**绝不零按钮**([接着跑,不用重批] / [重新出方案] 等)——**永不冻**;
- **自动行为(不露脸但塑造体验)**:崩溃残料三层自愈;界外角色钳位;tier-1 抽风 retry 一次;额度死/断供人话「codex 服务不可用」;纯建议方案开工口直接拒(不建垃圾授权);**任务超时自动打回主管重拆一次**(交货/卡住脸见「已自动打回主管重拆 1 次」);**重拆自带「本单已完成·别重做」事实块 + 项目记忆**。
**怎么跑 / P2-B（07-21 已收口 `e9ad7f3`）**:每个执行节点默认新对话；需要复用时只在右区「怎么跑」逐节点挑已有对话。同 proposal 重挂载保留逐节点选择，换 proposal 全部重置；工序图不再承担选择器。
**工作流 tab**:画布(React Flow)——只读运行视图 + 可编辑多工作流(新建/编辑/提交写回)+ 全屏 HUD + 发令台 + 交办的**任务级节点+虚线依赖边**落画布、跑到哪亮到哪(任务节点只看不点);「运行选中节点」= 手动挡 override 非主路径。
- **历届方案索引 = 已实现(07-08 数据能力；07-19 S1C 移位正名)**:桌面位于左对话与右方案/交货实体之间，点选只切右侧实体、不扰动对话；目标一句+九态人话状态+日期，缺方案实体的旧单如实标「旧单·无方案记录」；筛选 chips / 旧单只读详情卡仍在，[接着跑]归卡住脸。后端继续复用 `list_project_run_history` 读模型(方案为脊·链时间窗归属如实标 exact/time_window)。

### 面3 · 智能体页(能力已存在，产品地位次要 / 待定)
- 会话列表:按软件分组 / subagent 过滤 / 标题截断 / 拖拽改宽;会话流:虚拟化 + 按轮分组 + 过程折叠;绑会话 Enter 直发；`focusedThreadId` 选中态(交办「看原始对话」跳入即此)。relay 的 existing/new、thread event、poll、Stop 与 readback 已被共享 transport controller 复用。
- **当前边界**:direct send 仍只对 Codex 开放，Agent 固定保持 `workspace-write + 项目根写根` 与既有用户配置行为；主管固定 profile、项目/工作流/turn binding 与 MCP capability set 已离线实现。智能体页不再作为交办主线产品验收阻塞项，但在另有退役决定前不删除。
- **仍没有**:真实 App 中已验证的主管会话/落卡体验；首版也未接入 Codex 以外的 adapter。

### 面4 · 记忆中心
- 记忆中心已为左列表四语义组 + 右侧单选三态详情；候选、待核 lint、按项目正式记忆、全局正式记忆均用真数，候选「确认」与「转正」分开。采集仍为治理钩子攒候选 + **确认制**，正式记忆 top5 进入主管事实注入/重建。
- **知识库第一片（07-20～21）**:工作台自管 `knowledge-vault/`，md 文件即真相；列表/阅读/编辑/新建、`[[双链]]`、受限 md 渲染、路径锁与确认式 AI 写入均已落地，无 agent 直写通道。三类 audit 已固定走 Batch 2 production writer：DB-primary 先 DB 后 JSON，JSON-only/Blocked 沿现有 validator/CAS/fallback；non-test check 与 Tauri debug build 已通过。
- **L3 第二片离线现状**:Syn 原生工作区的目录/索引、Markdown、反链、搜索、图谱、JSON Canvas、附件/恢复和确认式 AI 写后刷新已实现并离线验证；它不是同步路线，也不以 Obsidian 为前置。真实 App 十二项和 `knowledge_open` 的原生视图打开仍未验收，原因是缺少受信任 host dispatch；vault 属用户数据，不并入仓外代码备份口径。

### 面5 · 秘书
- 右栏 brief:**待你拍板**三组(待批方案 / 主管提醒[needs_human_check·human_verify·mismatch·caution 刻意不入] / 记忆候选)+ 计数 + 文字去处 + **[让 AI 解释现状]**(按需·约 1-2 分钟·会话内缓存)+ 边界话「提醒不是命令·秘书零写入」。
- **秘书看板 = 已实现(07-08 当日)**:专门界面·四泳道(等你拍板/主管提醒/记忆候选/风险建议)·卡片只读不许拖·[让 AI 解释现状]在看板;**入口(07-08 对调后)**:右下角浮钮=开看板界面,右侧栏图标=开侧边栏摘要(与通知/待办同一套面板开法·不再单独浮层)。
- **没有**:机会简报(B3+ 已拍收编排后);对话式秘书(Phase C 同期)。

### 面6 · 审计
- 现状:审计事件**落库全**(工作流状态 audit_events + 主管两意见的 store 内嵌审计),开发者详情面板可看原始；知识库三类写 audit 已进入 Batch 2 的 DB-primary/JSON 投影与重启 reconcile 证据面。
- **没有**:「给人看的审计」界面(按单/按天时间线)——原型面6 的正题。

1. 工序图/任务节点挂**项目选中工作流**(07-06 拍板转正式默认;定稿旧文「每单自动生成一条」已修订,降 Phase D 议题)——**别照抄旧句**;
2. 全局主管/秘书现为 **advisory·零闸权·零写入**(Phase B 定稿):架构 §7「可授予低风险自动整理」、中间版「全局主管复核=自动裁决」是**未来态**,升档走信任阶梯另拍;
3. 记忆 source_type 按代码 8 种(canon 文档 11-14 是旧文·决策 06-25);
4. agent 档案在代码内,**未**外部文件化(愿景 §2 刚需 = Phase D 认下的债);
5. C4「只认默认工作流」**已放开**(角色循环跑项目内选中工作流);
6. 主管两意见的审计**内嵌自家 store**(非 state audit_events;升档给闸权时回正典·已记前置);
7. 旧四角色机器(`run_workflow_machine`)= 废弃留档;S2 手动角色循环 UI = 手动挡 override,非主路径;
8. 中间版 §0.6 十步:第 6 步「主管确认过程事实」现 = **用户点[属实]**;第 8 步「产物喂下一步」现只喂**已完成事实摘要**,产物本体明令另批;
9. 「工作桌首页/导航收编」07-02 被否——终局骨架重画时打「构想·待拍(当年否过·供重议)」徽标(包 §0 已定此规矩)。
10. S1B-H2 / R4F-R1 的 resident/private-home 链仍在当前代码与历史 evidence 中，但已暂停作为交办主运输；替代性验收前保留、不删除、不继续当当前第一优先。
11. 当前 MCP capability plane 已有单一服务端 registry，`tools/list` 与 `tools/call` 同源；**只有 Active、已绑定 host-observed thread 的 trusted binding** 下，主管 `supervisor-read-only` 才可见并调用精确 allowlist：07-22 基线的 `submit_proposal` 与 L3 v2 另行授权的只读 `knowledge_search/read/open/cite`。缺 binding/Starting/过期时 list 为空、call 拒绝；大小写/空白/通配/未注册变体均拒绝。`knowledge_open` 目前只返回 host-dispatch-required 意图，不可称为已打开；dispatch/follow-up/finalize 等内部控制动作仍为 host-only。此为离线实现事实，不等于真实 MCP client 已完成工具发现/调用验收。
12. “所有 agent 通用”仍是架构目标，不是当前能力；真实 direct transport 只有 Codex，Claude Code/OpenClaw/OpenCode 等 adapter 尚未实现。
