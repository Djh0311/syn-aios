## 1. 当前结论

记忆层不能做成一个普通向量库，也不能做成 agent 自己随手写的便签。

记忆层在本地 AI 工作台里负责：

- 保存用户确认过、项目主管总结过、工作流沉淀过的长期事实。
- 保留每条记忆的来源、版本、状态、权限、审计链接。
- 给秘书、全局主管、项目主管、子智能体提供不同范围的上下文。
- 发现冲突、过期、重复、缺来源、应上升或下沉的记忆。
- 把成熟流程沉淀成可复用模式候选。

记忆层不负责：

- 替代审计中心。
- 替代知识库原文。
- 替代工作流账本。
- 替代建议方案。
- 让子智能体直接写正式项目记忆。
- 自动把普通聊天内容塞进长期记忆。

### 1.1 R5 蓝图经验沉淀口径

Root Treatment / R5 将外部蓝图 §17（记忆层）、§22（策略系统里的成熟模式沉淀）和 §26.4（Successful Run Pattern / 成功运行模式）统一解释为同一条 product-line 落地路径：

```text
工作流 / 阶段 / 成功运行证据
-> observation / candidate / cross-project report
-> MaturePatternCandidate
-> 用户确认
-> mature pattern formal memory / 项目记忆 / 全局成熟模式
-> 后续任务包按权限召回，并保留来源、版本、审计和反例
```

当前已落地的对应项是 M12 / M12.1 / M13：成熟模式候选、跨项目主题报告、用户确认后的 mature pattern 正式记忆写入、任务包召回边界、acceptance summary freshness 和最终权威验收。R5 不把蓝图中的 Successful Run Pattern 解释成自动技能化、自动 harness 规则改写、自动全局策略升级或绕过用户确认的经验写入；这些仍必须另有任务包、证据和用户确认。

## 2. 蓝图约束

最终蓝图已确认：

- 记忆类型包括用户个人偏好记忆、全局产品蓝图记忆、项目记忆、会话摘要、成熟模式记录。
- 普通聊天内容不自动进入长期记忆。
- 可以自动进入记忆的来源包括工作流总结、阶段汇报、用户确认采纳的建议方案。
- 子智能体汇报先进入工作流账本。
- 审查或项目主管总结后，再进入项目记忆。
- 旧记忆被新记忆替代时，不直接覆盖，保留旧版本。
- 记忆冲突由秘书汇总，同时由记忆系统自动提示。
- 记忆结构调整由角色提出建议，用户确认后生效。
- 记忆管理界面要支持查看、编辑、删除或废弃、冻结、查看来源、查看版本、查看冲突。

这些约束优先于外部项目做法。

## 3. 外部项目第二轮结论

本节记录第二轮可落地理解。

硬边界：

- 外部项目只能作为证据和设计参考，不能覆盖最终蓝图。
- 正式记忆必须有来源、版本、状态、权限和审计链接。
- LLM 生成的实体、关系、摘要、claim、图谱、导览默认都是候选或派生索引，不是权威事实。
- 从最终形态倒推阶段开发，不再用“第一版不做什么”来定义最终能力。

### 3.1 GBrain

定位：

- GBrain 的价值不是单纯 Markdown，而是结构化数据库、人可读 Markdown、resolver 规则和 schema 约束结合。
- 它适合影响 `MemoryPage`、`MemoryResolverPolicy`、`MemoryEntityRegistry` 和记忆 lint。

可吸收：

- 人机共读的记忆页。
- 当前结论加时间线的页面结构。
- `RESOLVER.md` 式放置规则和 schema 约束。
- 实体注册、规范 slug、别名、去重、合并。
- 可重建索引，不把派生数据库当唯一事实源。
- 记忆 lint：冲突、过期、重复、缺来源、放错位置。

不能照搬：

- 不能让普通 agent 直接写正式项目记忆。
- 不能把 Markdown 文件夹结构当权限边界。
- 不能把检索命中当成事实采纳。
- 不能把 agent 自主维护脑图等同于项目主管确认。

落地到本设计：

- `MemoryPage` 必须有人可读正文、当前结论、时间线、来源区。
- `MemoryResolverPolicy` 决定一条事实应该进入用户偏好、全局蓝图、项目记忆、会话摘要还是成熟模式。
- `MemoryEntityRegistry` 维护项目、角色、工具、文档、模型、harness、建议方案等对象的统一身份。

### 3.2 GraphRAG

定位：

- GraphRAG 是大规模资料的理解索引和检索增强层，不是正式记忆治理系统。
- 它适合跨项目主题总结、成熟模式候选、全局到局部的证据下钻。

可吸收：

- 全局摘要和局部证据分层。
- `CommunityReport` 式社区摘要，用于跨项目主题和成熟模式候选。
- 先全局再局部的查询思路。
- Global Search、Local Search、DRIFT Search 分别对应全局概览、局部证据和复杂下钻。

不能照搬：

- LLM 抽取的实体、关系、claim 不能直接成为权威事实。
- 社区摘要不能作为用户默认看到的真相。
- 重索引成本高，不能阻塞每轮工作流结束。
- 不能让 GraphRAG 输出绕过用户确认、项目主管审查和权限检查。

落地到本设计：

- 增加 `MemoryClusterReport`，只属于派生理解索引或候选层。
- GraphRAG 的 `TextUnit` 映射为 `MemorySourceRef` 的可引用片段。
- GraphRAG 的实体、关系、claim 映射为 `MemoryEntityCandidate`、`MemoryRelationCandidate`、`MemoryCandidate`。
- 检索结果进入 `TaskMemoryPacket` 前必须标明来源、状态、版本、权限、冲突和选择理由。

### 3.3 Graphify

定位：

- Graphify 是项目资料和代码的图谱化理解工具，不是长期记忆。
- 它适合帮助项目主管找结构、找影响范围、找可疑跨域连接。

可吸收：

- 项目代码和文档图谱。
- 影响范围分析。
- 置信标签，例如静态抽取、LLM 推断、有歧义。
- `GRAPH_REPORT.md` 这类人可读项目理解报告。
- MCP 图查询能力，例如节点、邻居、路径、影响范围。

不能照搬：

- 不把图谱报告直接写入长期记忆。
- 不默认把文档、PDF、图片发给云模型做语义提取。
- 不把图谱工具设为所有项目默认启用。
- 不默认提交包含私密结构摘要的图谱产物。

落地到本设计：

- `Graphify node` 映射为 `ProjectKnowledgeNode` 或 `MemoryEntityCandidate`。
- `Graphify edge` 映射为 `MemoryRelationCandidate`。
- `EXTRACTED`、`INFERRED`、`AMBIGUOUS` 映射到关系置信来源。
- 图谱报告进入 `ProjectUnderstandingReport`，不能直接成为 `MemoryPage`。

### 3.4 LLMWiki

定位：

- LLMWiki 是人机共读的编译知识层，接近记忆治理形态，但原始设想里 LLM 直接维护 wiki 的部分不能照搬。
- 它适合影响 `MemoryPage`、`MemoryVersion`、`MemoryResolverPolicy`、`MemoryLintFinding`。

可吸收：

- 原始来源、编译记忆、规则文件三层结构。
- `index` 和 `log` 思路。
- claim 级来源引用。
- 记忆 lint：孤立、冲突、过期、缺来源、重复。
- 信任状态，例如 `authoritative`、`draft`、`proposal`、`needs-review`、`historical`、`deprecated`。
- 页面元数据，例如 owner、status、source trace、last reviewed、sensitivity、agent_use、typed relations。

不能照搬：

- LLM 不直接维护正式项目记忆。
- wiki 不是原始事实源。
- 用户聊天不自动编译进长期记忆。
- “好答案写回 wiki”必须经过候选层和确认流程。

落地到本设计：

- `MemoryPage` 采用可审查、可引用、可维护的人机共读结构。
- `index` 对应 `MemoryResolverPolicy` 和角色读取入口。
- `log` 对应 `MemoryVersion` 和审计链接。
- 编译结果先进入 `MemoryCandidate`，不是直接写正式记忆。

### 3.5 AgentMemory

定位：

- AgentMemory 是会话观察、压缩、召回和可视化层，不是正式记忆权威。
- 它适合影响 `ObservationStore`、生命周期 hook、`TaskMemoryPacket`、会话 replay。

可吸收：

- 自动观察层。
- 会话级召回。
- raw observation 到 semantic memory 的压缩。
- session explorer 和 live observation 思路。
- `SessionStart`、`PreCompact`、`Stop`、`SessionEnd` 这类生命周期节点。
- BM25、向量、图、RRF 等混合召回策略。

不能照搬：

- 不默认 capture everything 到正式记忆。
- 不让所有 agent 共享同一记忆。
- 不把自动 decay 用在审计事实上。
- 不让 MCP 或 REST 直接写正式记忆。

落地到本设计：

- `raw observation` 进入 `ObservationStore`。
- 压缩后的语义内容进入 `MemoryCandidate`。
- procedural memory 进入 `MaturePatternCandidate`。
- session replay 作为 `MemorySourceRef` 和审计查看能力。
- agent 隔离要升级为项目、角色、会话、文档权限的复合 `MemoryScope`。

### 3.6 MAGMA

定位：

- MAGMA 是多关系图记忆架构，重点是语义、时间、因果、实体分图和按意图检索。
- 它适合影响关系层和任务包召回策略，不负责治理。

可吸收：

- 语义、时间、因果、实体四类关系。
- 按查询意图选择不同关系图。
- 用因果和时间线回答为什么现在不能这么做。
- 快通道记录事件和时间，慢通道异步整理语义、实体、因果关系。

不能照搬：

- 不让 LLM 自动抽因果关系后直接写权威记忆。
- 不把论文评测结果外推为产品可用性证据。
- 不用访问频率或相似度替代记忆状态。

落地到本设计：

- `MemoryRelation` 至少保留 `semantic`、`temporal`、`causal`、`entity`。
- 因果边先进入 `MemoryRelationCandidate`，确认后才能进入正式关系。
- `TaskMemoryPacket` 根据检索意图优先选择不同关系。
- 时间线是最稳定底座，项目、任务、会话、审计、决策都必须可排序和追来源。

### 3.7 CodeGraph

定位：

- CodeGraph 是本地代码结构索引和影响范围工具，不是正式记忆。
- 它适合影响项目工具能力、任务包上下文、审查和验证建议。

可吸收：

- 本地代码结构索引。
- 调用链、影响范围、文件 stale 信号。
- 作为项目工具能力，而不是正式记忆。
- 路由、框架、调用方、被调用方、受影响测试等结构查询。

不能照搬：

- 不把代码图谱索引当长期项目记忆。
- 不让 agent 因为图谱命中就不读目标文件。
- 不把代码图谱结果写进工作流账本全文。
- 不默认把索引目录提交或共享。

落地到本设计：

- 代码索引映射为 `ProjectCodeIndex`。
- 符号、调用、导入、继承、路由映射为 `CodeSymbol` 和 `CodeRelation`。
- 影响范围映射为 `ImpactReport` 和 `VerificationHint`。
- 过期提示映射为 `StalenessSignal`。
- 代码结构结论只能进入候选或任务包来源引用，不能直接成为 `MemoryPage`。

### 3.8 Understand Anything

定位：

- Understand Anything 是项目理解图谱、业务域图和导览工具。
- 它适合补强记忆层的浏览、导览、review 和 onboarding 能力。

可吸收：

- 项目理解图谱。
- 业务域图和 guided tour。
- 从知识库材料、正式记忆和代码索引生成理解图。
- 图谱 review 思路。
- 结构抽取和 LLM 语义解释分层。
- 业务流程和领域概念的可视化入口。

不能照搬：

- 不把生成的 knowledge graph 当正式记忆。
- 不把 LLM 生成摘要当已验证事实。
- 不默认提交包含私密摘要的图谱。
- 不让 guided tour 替代源文件、正式记忆和决策文档。

落地到本设计：

- `knowledge-graph.json` 映射为 `ProjectUnderstandingMap`。
- guided tour 映射为 `ProjectOnboardingPath`。
- 业务域、流程、步骤映射为 `DomainFlowCandidate`。
- graph reviewer 映射为 `UnderstandingGraphReview`。
- 理解图谱搜索结果只能作为 `TaskMemoryPacket` 的辅助上下文。

### 3.9 Everything Claude Code

定位：

- Everything Claude Code 是 agent 工具箱和生命周期实践集合，不是记忆层模型。
- 它适合影响工作台生命周期事件、技能沉淀、工具启用治理和上下文压缩策略。

可吸收：

- session start、session end、pre-compact、evaluate-session 这类生命周期 hook。
- continuous learning 生成成熟模式候选。
- strategic compaction 对应工作流阶段边界。
- harness、hook、MCP、skill 安全扫描。
- skills、rules、commands、MCP configs 分层。

不能照搬：

- 不默认安装大量 MCP 和 hook。
- 不把 session 学到的 pattern 自动升级成技能或全局记忆。
- 不让 hook 自动写正式项目记忆。
- 不用个人 Claude Code 配置替代多项目工作台治理。

落地到本设计：

- `SessionStart` 映射为 `TaskMemoryPacketBuilder`。
- `PreCompact` 映射为 `CompactionCheckpoint`。
- `SessionEnd` 映射为 `SessionSummary`。
- `evaluate-session` 映射为 `MaturePatternCandidate`。
- MCP 配置进入工具和 API 注册中心，按项目启用、按任务包授权、进入审计。

## 4. 分层设计

最终记忆层分为七层。

### 4.1 观察层

观察层保存还没有成为正式记忆的事实痕迹。

来源：

- 会话执行摘要。
- 工具调用摘要。
- 子智能体结构化汇报。
- 审查结果。
- 项目主管阶段总结草稿。
- 用户在建议方案里的确认动作。

观察层只作为候选来源，不是长期记忆权威。

### 4.2 候选层

候选层保存准备进入长期记忆的候选。

候选来源：

- 工作流总结。
- 阶段汇报。
- 用户确认采纳的建议方案。
- 项目主管总结。
- 记忆 lint 建议。
- 成熟模式候选。

候选必须有：

- 来源引用。
- 生成者。
- 所属项目或全局范围。
- 推荐记忆类型。
- 风险和权限标记。
- 是否需要用户确认。

候选不能直接进入任务包上下文，除非明确标记为仅供审查。

### 4.3 正式记忆层

正式记忆是经过确认或项目策略允许后保存的长期内容。

正式记忆类型：

- 用户个人偏好记忆。
- 全局产品蓝图记忆。
- 项目记忆。
- 会话摘要。
- 成熟模式记录。

正式记忆必须可版本化、可废弃、可冻结、可追来源。

### 4.4 关系层

关系层保存记忆和对象之间的边。

关系层至少保留四类关系：

- `entity`：项目、会话、角色、文档、工具、模型、harness、建议方案之间的实体关系。
- `temporal`：生效、过期、替代、阶段顺序。
- `causal`：失败导致规则、建议导致任务、审计事件导致回滚建议。
- `semantic`：主题相似、问题相似、成熟模式相似。

阶段实现可以先用结构化字段和简单边表，最终再接复杂图检索。

因果关系默认先进入候选关系。

### 4.5 派生理解索引层

派生理解索引层保存可重建的项目理解产物。

来源：

- GraphRAG 式主题社区和社区摘要。
- Graphify 式资料图谱。
- CodeGraph 式代码图谱。
- Understand Anything 式理解地图和导览。

硬边界：

- 派生理解索引不是正式记忆。
- 派生理解索引不能绕过知识库权限和模型外发策略。
- 派生理解索引可以生成候选、lint、影响范围和任务包来源引用。
- 派生理解索引可以删除或重建，不删除正式记忆和审计。

### 4.6 检索层

检索层给不同角色生成上下文。

检索结果必须带：

- 来源。
- 状态。
- 版本。
- 是否过期。
- 是否冲突。
- 权限范围。
- 为什么被选中。

角色差异：

- 秘书可以看用户偏好、全局状态、项目摘要。
- 全局咨询可以看全局产品蓝图记忆和跨项目方法论。
- 全局主管可以看跨项目建议、成熟模式、全局异常。
- 项目主管只能读自己的项目。
- 子智能体只拿任务包允许的最小上下文。

### 4.7 审计层

审计层记录记忆相关动作。

必须审计：

- 候选创建。
- 候选采纳。
- 候选拒绝。
- 记忆修改。
- 记忆废弃。
- 记忆冻结。
- 记忆合并或拆分。
- 上升为全局记忆。
- 下沉为项目记忆。
- 记忆结构调整。
- 记忆冲突处理。

## 6. 写入流程

### 6.1 工作流结束入记忆

流程：

1. 子智能体完成结构化汇报。
2. 汇报进入工作流账本。
3. 审查智能体或 harness 产生审查结果。
4. 项目主管总结。
5. 系统生成 `MemoryCandidate`。
6. 项目主管审查候选。
7. 需要用户确认时，生成建议方案或待确认动作。
8. 确认后写入 `MemoryPage` 和 `MemoryVersion`。
9. 写入审计记录。

### 6.2 用户采纳建议入记忆

流程：

1. 建议方案被用户采纳。
2. 系统判断建议是否包含长期事实。
3. 生成 `MemoryCandidate`。
4. 低风险项目内事实可以由项目主管确认。
5. 跨项目、全局蓝图、用户偏好类记忆需要用户确认。
6. 写入正式记忆和审计。

### 6.3 会话摘要入记忆

会话摘要不是项目记忆。

流程：

1. 会话结束或阶段 checkpoint 生成摘要。
2. 摘要保存为会话摘要。
3. 如果摘要包含长期项目事实，生成项目记忆候选。
4. 项目主管确认后，才进入项目记忆。

### 6.4 成熟模式候选

流程：

1. 多次工作流出现相似流程、错误或修复。
2. 系统生成成熟模式候选。
3. 秘书或全局主管汇总。
4. 用户确认后，进入成熟模式记录。
5. 如果适用范围改变，必须写审计。

## 7. 修改和废弃流程

记忆修改不覆盖旧版。

允许动作：

- 编辑。
- 废弃。
- 冻结。
- 合并。
- 拆分。
- 上升为全局记忆。
- 下沉为项目记忆。

通用流程：

1. 生成修改建议。
2. 展示影响范围。
3. 用户或对应主管确认。
4. 创建新版本或新记忆。
5. 旧版本保留。
6. 写审计。

硬规则：

- 审计事实不能删。
- 已经外发的数据不能通过记忆回滚消除。
- 已经被模型读过的内容不能从历史上下文中抹掉。
- 记忆撤回只影响未来召回和未来任务包。

## 8. 冲突处理

冲突来源：

- 新旧记忆互相矛盾。
- 记忆和当前代码不一致。
- 记忆和当前决策文档不一致。
- 记忆和用户最新确认不一致。
- 项目记忆和全局蓝图记忆冲突。

处理流程：

1. 记忆系统生成 `MemoryLintFinding`。
2. 秘书汇总冲突。
3. 低风险项目内冲突交给项目主管。
4. 全局蓝图、用户偏好、跨项目冲突交给用户确认。
5. 处理结果写入新版本或废弃旧记忆。
6. 写审计。

## 9. 检索和上下文包

用户默认不看检索细节。

用户看到：

- 建议方案。
- 来源摘要。
- 风险。
- 待确认。
- 影响范围。

项目主管内部可以看：

- 检索命中的记忆。
- 代码图谱引用。
- 知识库引用。
- 审计引用。
- 冲突和过期提示。

子智能体只看：

- 任务目标。
- 允许读写。
- 必要记忆。
- 必要知识库引用。
- 禁止事项。
- 汇报格式。

检索意图候选：

- `current_state`
- `why`
- `what_changed`
- `impact`
- `similar_case`
- `timeline`
- `permission_reason`
- `global_theme`
- `local_evidence`
- `onboarding_path`
- `pattern_candidate`

检索策略：

- `current_state` 优先读正式记忆、最新版本、工作流账本和项目主管总结。
- `why` 优先读时间线、因果候选、审计记录、决策来源和失败记录。
- `what_changed` 优先读 `MemoryVersion`、审计事件、代码索引 stale 信号。
- `impact` 优先读 `ProjectCodeIndex`、`ImpactReport`、关系层和知识库引用。
- `similar_case` 优先读成熟模式候选、语义关系、历史项目摘要。
- `timeline` 优先读时间边、会话摘要、阶段报告、审计记录。
- `permission_reason` 优先读授权记录、知识库权限、任务包权限。
- `global_theme` 优先读 `MemoryClusterReport` 和全局蓝图记忆。
- `local_evidence` 优先读 `MemorySourceRef` 和原始来源锚点。
- `onboarding_path` 优先读 `ProjectUnderstandingMap` 和 guided tour。

阶段实现：

- 早期可以先用关键词、标签、来源引用和简单关系查询。
- 中期接入代码索引、理解地图、实体注册和 staleness 检查。
- 后期接入 GraphRAG 式社区摘要、MAGMA 式多关系路由、向量检索和复杂图检索。
- 无论阶段如何，检索结果进入任务包前都必须经过权限、状态、冲突、过期检查。

## 11. 从最终形态倒推阶段开发

最终形态不是普通向量库，也不是 agent 便签，而是带治理的本地项目记忆系统。

### 11.1 阶段 0：对象和边界

目标：

- 先把正式记忆、候选、观察、派生理解索引、知识库、审计分清。
- 不急着做复杂图检索。

必须完成：

- `MemorySourceRef`
- `MemoryCandidate`
- `MemoryPage`
- `MemoryVersion`
- `MemoryRelation`
- `MemoryLintFinding`
- `TaskMemoryPacket`
- 记忆和知识库边界规则
- 正式记忆写入权限规则
- 来源、版本、状态、权限字段

### 11.2 阶段 1：真实闭环

目标：

- 支撑一个项目从工作流结束到项目记忆沉淀，再到下一次任务包召回。

必须完成：

- 工作流总结生成 `MemoryCandidate`。
- 项目主管确认后进入项目记忆。
- 用户采纳建议进入候选。
- 会话摘要和项目记忆分开。
- 基础冲突、缺来源、过期检查。
- 记忆管理页面的列表、详情、来源、版本、冲突、操作区。
- 子智能体任务包只包含允许的最小记忆。

### 11.3 阶段 2：实体和关系治理

目标：

- 解决记忆漂移、重复实体、关系不清、因果误写的问题。

必须完成：

- `MemoryEntityRegistry`
- `MemoryRelationCandidate`
- 实体 alias、merge、dedupe。
- `semantic`、`temporal`、`entity`、`causal` 四类关系。
- 因果关系确认流程。
- 关系 lint：孤立、重复、冲突、放错层级、未审推断关系。

### 11.4 阶段 3：项目理解索引

目标：

- 让项目主管和子智能体能快速理解项目结构，但不把理解索引当正式记忆。

必须完成：

- `ProjectCodeIndex`
- `ProjectUnderstandingMap`
- `ProjectUnderstandingReport`
- `ImpactReport`
- `VerificationHint`
- `StalenessSignal`
- 代码图谱引用和当前文件验证规则。
- 私密文档进入理解索引前的权限和模型外发检查。

### 11.5 阶段 4：跨项目主题和成熟模式

目标：

- 发现跨项目重复问题、成熟流程、可上升为全局记忆或技能的模式。

必须完成：

- `MemoryClusterReport`
- `MaturePatternCandidate`
- 全局主管或秘书汇总流程。
- 成熟模式候选 review。
- 上升为全局记忆、下沉为项目记忆、适用范围变化的审计。
- GraphRAG 式全局摘要和局部证据下钻。

### 11.6 阶段 5：多关系检索和生命周期自动化

目标：

- 让记忆进入完整 agent 生命周期，同时保持治理边界。

必须完成：

- `TaskMemoryPacketBuilder`
- `CompactionCheckpoint`
- `SessionSummary`
- session start、pre-compact、session end、evaluate-session 生命周期事件。
- MAGMA 式按意图选择语义、时间、因果、实体关系。
- 向量检索、图检索、关键词检索混合召回。
- 工具、MCP、技能按项目启用、按任务包授权。

### 11.7 永远不作为默认行为

- 普通聊天自动进入长期记忆。
- 子智能体直接写正式记忆。
- LLM 推断关系直接成为权威事实。
- 私密文档默认摘要入记忆。
- 所有 agent 共享同一无边界记忆池。
- 记忆或理解索引绕过权限和审计。
- 图谱命中替代源文件、决策文档或用户确认。

## 15. 权威来源优先级

状态：已确认。

记忆层不能做成一条简单排行榜。

原因是不同问题要听不同来源：

- 问最终目标，要看用户确认和最终蓝图。
- 问当前实现，要看当前代码和当前运行结果。
- 问历史发生过什么，要看审计、工作流和证据记录。
- 问谁能看什么，要看当前权限。
- 问某个知识点怎么理解，要先看知识库原始材料。

### 15.1 最终要做成什么

优先级：

1. 用户最新明确确认。
2. 最终蓝图。
3. 已确认设计决策。
4. 全局记忆。
5. 项目记忆。
6. 会话摘要。

规则：

- 如果记忆里写 A，但用户后来明确说 B，听 B。
- 如果项目文档和最终蓝图冲突，先按最终蓝图，除非用户后来明确改过。

### 15.2 当前代码实际是什么样

优先级：

1. 当前代码。
2. 当前测试或当前运行结果。
3. 最新证据记录。
4. 项目文档。
5. 项目记忆。
6. 图谱或自动摘要。

规则：

- 记忆说功能已完成，但代码里没有，不能信记忆。
- 图谱说某文件影响很大，但源码已经变化，必须重新看源码。

### 15.3 以前发生过什么

优先级：

1. 审计记录。
2. 工作流记录。
3. 证据记录。
4. 项目主管总结。
5. 会话摘要。
6. 记忆里的概括。

规则：

- 历史事件不能靠记忆概括覆盖。
- 谁授权、谁修改、何时废弃、何时冻结，要看当时记录。

### 15.4 谁能看什么

优先级：

1. 当前权限设置。
2. 授权记录。
3. 项目规则。
4. 记忆里的旧权限描述。

规则：

- 记忆里说文档可用，但当前权限撤了，不能再用。
- 权限撤回只影响未来读取和未来任务包，不要求抹掉历史上下文。

### 15.5 某个知识点怎么理解

优先级：

1. 知识库原始材料。
2. 已确认项目记忆。
3. 项目主管总结。
4. 自动生成的图谱、摘要、导览。

规则：

- 自动图谱和摘要只能帮忙找路，不能直接当真。
- 如果摘要和知识库原始材料冲突，按知识库原始材料。
- 知识库材料说明资料本身写了什么。
- 记忆说明系统确认以后怎么做。

### 15.6 硬规则

- 用户最新明确确认优先。
- 当前代码和测试比旧记忆更可信。
- 审计记录不能被记忆覆盖。
- 自动生成的图谱、摘要、导览不能直接当事实。
- 候选记忆不能当正式记忆用。
- 冲突时系统不能偷偷选一个，必须提示冲突或生成待确认项。

## 16. 角色权限规则

状态：已确认。

权限采用白名单规则。

总规则：

- 只规定能做的事。
- 没写允许，就是不允许。
- 能读不等于能写。
- 能写候选不等于能写正式记忆。
- 临时授权必须有期限、理由和记录。
- 权限只对未来生效，不改历史记录。

- 新增记忆。
- 编辑记忆。

- 删除记忆。

- 确认用户偏好记忆。
- 确认记忆结构调整。
- 确认跨项目记忆。
- 确认成熟模式。
- 授权或撤回知识库权限。
- 授权或撤回模型权限。
- 授权或撤回工具权限。

### 16.2 秘书

能做：

- 读取项目摘要。

- 汇总待确认项。
- 提出记忆更新建议。
- 提出记忆清理建议。

### 16.3 全局主管

能做：

- 读取全局记忆。
- 读取跨项目摘要。

### 16.4 全局咨询

### 16.5 项目主管

- 提出记忆过期提醒。
- 提出记忆缺来源提醒。

## 17. 状态流转规则

状态：已确认。

状态不要一开始做太多。

记忆层先按四类对象处理状态：

- 观察。
- 候选记忆。
- 正式记忆。
- 关系和图谱结论。

### 17.1 观察状态

观察是系统看到的痕迹，例如一次汇报、一次工具结果、一次会话摘要。

状态：

- `recorded`：已记录。
- `candidate_created`：已经从它生成了候选记忆。
- `ignored`：确认不需要进入记忆。
- `quarantined`：里面可能有敏感内容或不可信内容，先隔离。

允许流转：

- `recorded -> candidate_created`
- `recorded -> ignored`
- `recorded -> quarantined`
- `quarantined -> ignored`
- `quarantined -> candidate_created`

### 17.2 候选记忆状态

候选记忆是可能该长期保存、但还没确认的内容。

状态：

- `draft`：草稿。
- `needs_review`：待审查。
- `approved`：已批准，可以进入正式记忆。
- `rejected`：拒绝。
- `quarantined`：隔离。
- `superseded`：被更新的候选替代。

允许流转：

- `draft -> needs_review`
- `needs_review -> approved`
- `needs_review -> rejected`
- `needs_review -> quarantined`
- `quarantined -> needs_review`
- `approved -> superseded`

### 17.3 正式记忆状态

正式记忆是已经被确认、以后会被任务包召回的内容。

状态：

- `active`：生效。
- `conflicted`：有冲突，不能直接给子智能体用。
- `deprecated`：已废弃，保留历史。
- `frozen`：冻结，不能直接改。
- `archived`：归档，默认不召回。

允许流转：

- `active -> conflicted`
- `active -> deprecated`
- `active -> frozen`
- `active -> archived`
- `conflicted -> active`
- `conflicted -> deprecated`
- `frozen -> active`
- `frozen -> deprecated`
- `deprecated -> archived`

硬规则：

- 正式记忆不直接覆盖，修改就是新版本。
- `conflicted`、`deprecated`、`frozen`、`archived` 默认不进子智能体任务包。
- 废弃不是删除，只是不再用于未来召回。
- 冻结后不能直接改，只能先解冻或新建替代版本。

### 17.4 关系和图谱结论状态

关系和图谱结论包括：

- 这个原因导致那个结果。
- 这个文件影响那个模块。
- 这个实体和那个实体相关。
- 这个主题属于某个社区摘要。

状态：

- `candidate`：候选关系。
- `confirmed`：确认关系。
- `ambiguous`：不确定。
- `rejected`：拒绝。
- `stale`：过期。

硬规则：

- LLM 推断出来的因果关系默认是 `candidate` 或 `ambiguous`。
- `confirmed` 才能作为正式关系进入任务包。
- `ambiguous` 和 `stale` 只能作为提醒，不能当事实。

## 18. 存储和索引架构

状态：已确认。

记忆层采用双层正式存储和多种可重建索引。

核心原则：

- SQLite 负责结构化状态、权限、版本、关系和审计。
- Markdown 展示页负责人可读呈现。
- 向量库、图索引、代码索引、理解地图都是可重建索引。
- 可重建索引不是权威来源。

### 18.1 正式记忆受控存储

正式记忆使用工作台受控存储。

核心做法：

- SQLite 存结构化状态、权限、版本、关系、来源和审计引用。
- 正式记忆可以生成 Markdown 展示页。
- Markdown 展示页保留同一个 `memory_id`。

分工：

- SQLite 是系统查询、状态管理、权限判断、版本管理和关系管理入口。
- Markdown 展示页是用户和 agent 阅读正文的入口。
- Markdown 展示页不是普通知识库笔记。

原因：

- 只用 Markdown，状态、权限、版本、关系、冲突不好查。
- 只用 SQLite，人读和审查不方便。
- 双层更复杂，但更适合工作台。

规则：

- Markdown 是展示格式，不是权威身份。
- 知识库 vault 里的普通笔记不会因为是 Markdown 就成为正式记忆。
- 正式记忆展示页不能被 Obsidian CLI 或外部 Markdown 编辑器直接改成正式变更。
- 如果允许编辑正式记忆展示页，也必须通过工作台状态机、版本和审计。

### 18.2 审计记录

审计记录以 SQLite 为权威。

必须写审计的动作包括：

- 创建。
- 修改。
- 废弃。
- 冻结。
- 确认。
- 拒绝。
- 合并。
- 拆分。
- 上升为全局记忆。
- 下沉为项目记忆。

规则：

- 审计记录不能物理删除。
- Markdown 可以展示审计摘要，但不是审计权威。
- 记忆正文修改不能覆盖审计历史。

### 18.3 来源引用

记忆层只保存来源引用，不默认复制大段原文。

知识库权限的具体落地方式待知识库设计确认。

当前只确认原则：知识库材料和从它生成的索引、候选、记忆都不能绕过工作台权限。

来源引用保存：

- 来源路径。
- 文档 ID。
- 会话 ID。
- 审计 ID。
- 代码位置。
- 时间。
- 权限和敏感级别。

规则：

- 原始知识库文档仍属于知识库。
- 记忆层不能变成第二个知识库。
- 私密文档摘要必须单独走权限确认。

### 18.4 向量库

向量库只做检索缓存。

可以进入向量库的内容：

- 正式记忆。
- 候选记忆。
- 会话摘要。
- 来源片段摘要。
- 派生理解报告摘要。

规则：

- 向量命中不代表事实正确。
- 向量库可以重建。
- 向量库不能成为唯一数据源。
- 向量召回进入任务包前，必须经过状态、权限、冲突、过期检查。

### 18.5 图索引

图索引用来查关系，不负责确认事实。

图索引可以包含：

- 实体关系。
- 时间线。
- 影响范围。
- 相似模式。
- 代码关系。
- 派生理解图谱关系。

每条关系必须标明来源：

- 用户确认。
- 项目主管确认。
- 静态抽取。
- LLM 推断。
- 不确定。

规则：

- LLM 推断关系默认不能直接进入正式图。
- 图谱负责看关系，不负责替人确认。
- 图索引可以重建。

### 18.6 派生索引

以下都属于派生索引：

- 向量索引。
- 图索引。
- 代码索引。
- 理解地图。
- 社区摘要。
- 图谱报告。

规则：

- 派生索引可以删除后重建。
- 删除派生索引不能导致正式记忆丢失。
- 删除派生索引不能导致审计记录丢失。
- 派生索引不能绕过权限。
- 派生索引对知识库材料的权限继承方式，待知识库设计确认。

### 18.7 存储分工

| 内容 | 权威位置 |
| --- | --- |
| 正式记忆状态、权限、版本、关系 | SQLite |
| 正式记忆正文 | SQLite 受控内容 + 可生成 Markdown 展示页 |
| 审计记录 | SQLite |
| 来源引用 | SQLite |
| 人可读记忆页 | Markdown 展示页，不等同于知识库普通笔记 |
| 向量检索 | 向量库，可重建 |
| 图关系查询 | 图索引，可重建 |
| 代码图谱 | 派生索引，可重建 |
| 理解地图 | 派生索引，可重建 |
| 原始知识库文档 | 知识库，不复制进记忆 |

### 18.8 硬规则

- SQLite 里的状态和审计更权威。
- Markdown 或 Obsidian CLI 不能绕过状态机直接改正式记忆。
- 向量库、图谱、理解地图都不是权威来源。
- 任何索引都必须能从正式数据和授权来源重建。
- 私密来源不能因为建索引而绕过权限。

## 19. 召回和任务包生成规则

状态：已确认。

本节规定项目主管派发任务时，系统如何决定给子智能体看哪些记忆。

核心原则：

- 任务包只给最小必要记忆。
- 先过滤，再召回。
- 按任务意图选择记忆。
- 每条进入任务包的记忆必须说明为什么被选中。
- 被排除的记忆也要记录原因。

### 19.1 最小必要记忆

子智能体不读取完整项目记忆库。

任务包里只放：

- 当前任务目标必须知道的记忆。
- 当前任务相关的项目规则。
- 当前任务相关的最新状态。
- 当前任务相关的禁止事项。
- 当前任务相关的来源引用。
- 必须注意的冲突或过期提醒。

任务包提供的是够完成任务的上下文，不是完整档案。

### 19.2 进入任务包前的过滤

进入任务包前必须检查：

- 这条记忆是不是正式记忆。
- 状态是不是可用。
- 有没有冲突。
- 有没有过期。
- 子智能体有没有权限。
- 当前模型能不能处理。
- 是否来自已撤回来源。
- 是否包含私密内容。

规则：

- 不通过检查的内容不能进入任务包。
- 候选、观察、自动图谱、摘要、导览默认不能作为正式事实进入任务包。
- 如果确实要给，只能标成待审查材料或辅助线索。

### 19.3 按任务意图召回

不同任务召回不同内容。

实现任务：

- 当前代码状态。
- 项目规则。
- 相关决策。
- 影响范围。
- 验证要求。

审查任务：

- 任务目标。
- 验收标准。
- 改动证据。
- 相关记忆。
- 历史问题。

研究任务：

- 最终蓝图。
- 已确认设计。
- 相关来源。
- 未定问题。

总结任务：

- 工作流记录。
- 阶段汇报。
- 审查结果。
- 用户确认项。

排错任务：

- 最近变化。
- 失败记录。
- 相关代码。
- 相似历史问题。

重构任务：

- 设计约束。
- 影响范围。
- 代码结构。
- 测试要求。

### 19.4 入选理由

任务包里每条记忆都要带简短理由。

理由候选：

- 和当前目标相关。
- 是最新项目状态。
- 是明确禁止事项。
- 是验收标准。
- 是历史冲突提醒。
- 是相似问题经验。
- 是权限要求。

### 19.5 冲突记忆

如果两条记忆冲突：

- 不偷偷选其中一条。
- 不直接都塞进任务包。
- 生成冲突提醒。
- 交给项目主管或用户确认。
- 如果任务必须继续，只能放当前采用哪条作为临时依据的说明。

### 19.6 排除记录

系统不只记录放了什么，也要记录没放什么。

排除原因候选：

- 因权限排除。
- 因过期排除。
- 因冲突排除。
- 因候选未确认排除。
- 因内容太大排除。
- 因模型不能处理排除。

### 19.7 任务包生命周期

任务包是一次任务的上下文，不是长期记忆。

任务结束后：

- 子智能体汇报进入工作流账本。
- 项目主管总结后才可能生成记忆候选。
- 任务包本身可以被审计，但不自动变成记忆。

### 19.8 生成流程

流程：

1. 项目主管明确任务目标。
2. 系统判断任务类型。
3. 系统列出候选记忆。
4. 过滤权限、状态、冲突、过期、模型限制。
5. 按相关性和重要性排序。
6. 裁剪到任务需要的大小。
7. 给每条记忆写入选理由。
8. 记录被排除项。
9. 生成任务包。
10. 子智能体只读任务包。

### 19.9 硬规则

- 子智能体不能自己扫完整记忆库。
- 候选记忆不能伪装成正式记忆。
- 自动摘要和图谱只能作为辅助线索。
- 冲突内容默认不进任务包。
- 每条进入任务包的记忆都要有来源和入选理由。
- 任务包结束后不自动变成长期记忆。

## 20. 审计事件设计

状态：已确认。

审计记录谁改了什么、为什么改、依据是什么、改之前是什么、改之后是什么。

如果以后记忆错了，必须能查出它是怎么变成这样的。

### 20.1 必须审计的动作

只要影响记忆状态或未来召回，就必须审计。

必须审计：

- 创建观察。
- 创建候选记忆。
- 批准候选。
- 拒绝候选。
- 创建正式记忆。
- 编辑正式记忆。
- 废弃记忆。
- 冻结记忆。
- 解冻记忆。
- 归档记忆。
- 合并记忆。
- 拆分记忆。
- 上升为全局记忆。
- 下沉为项目记忆。
- 创建关系。
- 确认关系。
- 拒绝关系。
- 生成任务包。
- 记忆被排除出任务包。
- 处理冲突。
- 权限导致无法召回。
- 派生索引重建。

### 20.2 审计事件内容

每条审计至少记录：

- 谁触发的。
- 哪个角色触发的。
- 什么时候。
- 做了什么动作。
- 影响了哪个对象。
- 改之前是什么。
- 改之后是什么。
- 为什么这么做。
- 依据来源是什么。
- 关联哪个项目。
- 关联哪个任务或会话。
- 是否涉及权限。
- 是否涉及私密内容。
- 是否需要用户确认。
- 结果是成功、失败还是等待中。

### 20.3 审计记录不可普通编辑

规则：

- 审计记录不能物理删除。
- 审计记录不能被 Markdown 编辑覆盖。
- 如果审计记录写错，只能追加一条更正记录。
- 废弃记忆不删除审计。
- 删除记忆也不删除审计。

### 20.4 审计和记忆正文分开

记忆正文可以改版本。

审计记录只记录发生过的动作。

分工：

- 记忆页负责当前怎么看这件事。
- 审计负责过去到底发生了什么。

两者不能混在一起。

### 20.5 审计要支持的问题

审计必须能回答：

- 这条记忆是谁创建的。
- 为什么进入正式记忆。
- 它引用了哪些来源。
- 有没有用户确认。
- 什么时候被废弃。
- 为什么没有进入某次任务包。
- 哪个权限挡住了召回。
- 哪个索引是从哪些来源重建的。

### 20.6 审计对象

审计事件对象为 `MemoryAuditEvent`。

字段见 `5.30 MemoryAuditEvent`。

### 20.7 硬规则

- 没有审计的正式记忆变更无效。
- 审计记录不能物理删除。
- 审计更正只能追加，不能覆盖。
- 任务包生成也要审计。
- 记忆没被召回的原因也要审计。
- 派生索引重建要记录来源和时间。

## 21. UI 交互流程

状态：已确认。

记忆管理页面不只是列表和详情。

它必须让用户处理候选、冲突、版本、来源、权限、任务包预览和派生索引。

### 21.1 查看一条记忆

页面要显示：

- 当前结论。
- 所属范围：全局、项目、会话、用户偏好。
- 当前状态：生效、冲突、废弃、冻结、归档。
- 来源。

- 关联项目、会话、任务。
- 相关冲突。
- 是否能进入任务包。
- 最近一次审计记录。

目标：

- 用户一眼能知道这条记忆能不能信。

### 21.2 审查候选记忆

候选记忆页面要显示：

- 候选内容。
- 为什么系统认为它该被记住。
- 来源是什么。
- 谁生成的。
- 会影响哪个范围。
- 是否涉及私密内容。
- 是否和旧记忆冲突。

可操作：

- 采纳。
- 拒绝。
- 编辑后采纳。
- 隔离。
- 要求更多来源。

### 21.3 处理冲突

冲突页面要显示：

- 冲突的两条或多条内容。
- 各自来源。
- 各自更新时间。
- 谁确认过。
- 影响哪些任务或项目。
- 系统建议怎么处理。

可操作：

- 选择 A。

- 都废弃。

- 冲突没处理前，不能偷偷进入子智能体任务包。

### 21.4 版本对比

版本页面要显示：

- 旧版本。
- 新版本。
- 改了什么。

- 冻结当前版本。

规则：

### 21.5 来源查看

来源面板要显示：

- 来源类型。
- 来源标题。
- 来源位置。
- 来源时间。
- 权威等级。
- 敏感级别。
- 是否还可访问。
- 是否已撤权。

规则：

- 如果来源不可访问，要显示来源不可用，不能静默隐藏。

### 21.6 任务包预览

项目主管派任务前，要能预览：

- 将给子智能体哪些记忆。
- 为什么选这些。
- 哪些记忆被排除。
- 排除原因是什么。
- 有没有冲突或过期。
- 有没有权限阻断。
- 当前模型是否能处理。

可操作：

- 确认生成任务包。
- 移除某条记忆。
- 请求授权。
- 暂停任务等待确认。

### 21.7 派生索引视图

派生索引包括：

- 图谱。
- 理解地图。
- 社区摘要。
- 代码图谱。

界面必须明显标出：

- 这是派生索引。
- 不是正式记忆。
- 生成时间。
- 来源。
- 是否过期。
- 是否涉及私密内容。
- 是否可以重建。

可操作：

- 查看来源。
- 重新生成。
- 生成候选记忆。
- 标记错误。
- 删除索引。

### 21.8 最小 UI 入口

记忆页面至少包含这些入口：

- 正式记忆。
- 候选。
- 冲突。
- 来源。
- 版本。
- 审计。
- 任务包预览。
- 派生索引。

### 21.9 硬规则

- 正式记忆和候选记忆必须视觉区分。
- 正式记忆和派生索引必须视觉区分。
- 冲突、过期、冻结、废弃必须明显显示。

- 高风险操作必须展示影响范围。
- UI 上每个采纳、废弃、冻结、恢复动作都要写审计。

## 22. 维护任务和后台作业

状态：已确认。

记忆层不能只靠人手动整理。

系统要定期检查过期、冲突、缺来源、重复、私密内容和索引状态。

### 22.1 过期检查

系统要检查：

- 记忆引用的文件是否已经改了。
- 记忆引用的决策是否被新决策替代。
- 记忆引用的任务是否已经结束。
- 记忆引用的权限是否撤回。
- 代码索引是否落后当前代码。
- 理解地图是否落后当前项目。

结果：

- 生成过期提醒。
- 不自动改正式记忆。
- 必要时阻止进入任务包。

### 22.2 冲突检查

系统要检查：

- 新旧记忆是否矛盾。
- 项目记忆和全局记忆是否矛盾。
- 记忆和当前代码是否矛盾。
- 记忆和当前文档是否矛盾。
- 候选记忆和正式记忆是否矛盾。

结果：

- 生成冲突记录。
- 交给项目主管或用户处理。
- 冲突未处理前不进任务包。

### 22.3 缺来源检查

系统要检查：

- 正式记忆有没有来源。
- 来源是否还能访问。
- 来源是否只是自动摘要。
- 来源是否缺少具体位置。
- 来源是否和记忆内容对得上。

结果：

- 缺来源的正式记忆要标风险。
- 严重时转为冲突或冻结。
- 不能自动补编来源。

### 22.4 重复和实体漂移检查

系统要检查：

- 同一件事是否被记成多条。
- 同一实体是否有多个名字。
- 项目、工具、文档、模型是否被重复建档。
- 两条记忆是否应该合并。
- 某条全局记忆是否其实应该下沉到项目。

结果：

- 生成合并建议。
- 生成实体合并建议。
- 不能自动合并正式记忆。

### 22.5 私密和安全扫描

系统要检查：

- 记忆里是否有 token、key、cookie、密码。
- 私密文档内容是否被不该摘要。
- 派生索引是否包含私密内容。
- 任务包是否包含超出权限的内容。
- 外部工具输出是否含有指令注入。

结果：

- 高风险内容进入隔离。
- 阻止进入任务包。
- 提醒用户或项目主管处理。

### 22.6 派生索引维护

系统要维护：

- 向量索引。
- 图索引。
- 代码索引。
- 理解地图。
- 社区摘要。
- 图谱报告。

规则：

- 索引可以自动重建。
- 重建要记录来源和时间。
- 来源权限撤回后，相关索引要停止召回或重建。
- 索引失败不能影响正式记忆。

### 22.7 成熟模式检查

系统要检查：

- 哪些错误重复出现。
- 哪些流程多次成功。
- 哪些审查意见反复出现。
- 哪些项目经验可能上升为全局模式。

结果：

- 生成成熟模式候选。
- 不能自动变成全局记忆或技能。
- 必须用户确认。

### 22.8 维护任务审计

每次维护任务要记录：

- 什么时间运行。
- 检查了什么范围。
- 发现了什么。
- 自动做了什么。
- 哪些需要用户确认。
- 哪些因为权限没检查。

### 22.9 建议维护频率

- 任务开始前：轻量检查任务包相关记忆。
- 任务结束后：检查新候选和冲突。
- 每天或每周：项目级过期、重复、缺来源扫描。
- 阶段结束时：成熟模式和全局上升检查。
- 用户手动触发：严格维护扫描。

### 22.10 硬规则

- 维护任务不能自动改正式记忆。
- 维护任务可以生成候选、提醒、冲突、隔离。
- 自动修复只能作用于可重建索引。
- 正式记忆修改必须走状态机和审计。
- 维护任务不能绕过权限。

## 23. 验收场景和失败模式

状态：已确认。

记忆层不能只看有没有页面、数据库和召回。

它必须在容易出错的场景里不乱来。

### 23.1 旧记忆和当前代码冲突

场景：

- 记忆说某功能已经完成，但当前代码里没有。

正确表现：

- 系统提示冲突。
- 不把旧记忆直接放进子智能体任务包。
- 项目主管看到记忆和当前代码不一致。
- 处理后写审计。

失败表现：

- 子智能体直接按旧记忆执行。
- 系统不提示冲突。

### 23.2 用户最新确认覆盖旧记忆

场景：

- 旧记忆说走 A 方案，用户后来明确说走 B 方案。

正确表现：

- 系统按 B。
- A 被标记为过期或废弃候选。
- 后续任务包不再默认采用 A。
- 保留 A 的历史记录。

失败表现：

- 系统继续召回 A。
- 记忆覆盖用户最新确认。

### 23.3 候选记忆不能当正式记忆

场景：

- 子智能体汇报里提到一个可能长期有效的结论，但还没被项目主管确认。

正确表现：

- 进入候选。
- 不进入正式任务包。
- UI 显示待审查。
- 项目主管可采纳、拒绝或编辑。

失败表现：

- 直接变成项目记忆。
- 被下一个子智能体当事实使用。

### 23.4 派生图谱不能当事实

场景：

- 图谱或摘要说模块 X 影响模块 Y，但这只是 LLM 推断。

正确表现：

- 标记为辅助线索或候选关系。
- 不作为正式事实进入任务包。
- 需要来源或确认。

失败表现：

- 直接当成 confirmed 关系。
- 影响任务决策但没有来源。

### 23.5 私密来源不能绕过权限

场景：

- 某私密文档被项目 A 授权使用，后来权限撤回。

正确表现：

- 未来任务包不再召回这份文档。
- 相关派生索引停止召回或重建。
- 相关记忆标记来源权限已撤回。
- 审计保留历史发生过的授权和撤回。

失败表现：

- 仍然通过向量搜索召回私密摘要。
- 派生图谱继续泄露文档内容。

### 23.6 冲突记忆不能偷偷塞进任务包

场景：

- 两条记忆互相矛盾。

正确表现：

- 生成冲突提醒。
- 项目主管或用户处理。
- 任务必须继续时，只能显式说明临时依据。

失败表现：

- 系统偷偷选一条。
- 两条都塞给子智能体但不说明冲突。

### 23.7 Markdown 不能绕过状态机

场景：

- 有人直接改了 Markdown 记忆正文。

正确表现：

- 系统发现正文和数据库状态或版本不一致。
- 生成待处理提醒。
- 不把这次编辑当正式变更，除非走确认和审计。

失败表现：

- Markdown 一改，正式记忆无审计生效。

### 23.8 任务包要解释入选和排除

场景：

- 项目主管派任务。

正确表现：

- 每条入选记忆有理由。
- 被排除项有原因。
- 权限、冲突、过期、候选未确认都能解释。

失败表现：

- 只给一个黑盒上下文包。
- 出错后不知道为什么没召回某条记忆。

### 23.9 维护任务不能自动改正式记忆

场景：

- 后台扫描发现某条记忆可能过期。

正确表现：

- 生成过期提醒或候选修改。
- 不直接改正式记忆。
- 修改必须走状态机和审计。

失败表现：

- 后台任务自动重写正式记忆。

### 23.10 删除索引不影响正式记忆

场景：

- 删除向量库、代码索引、理解地图。

正确表现：

- 正式记忆仍在。
- 审计仍在。
- 索引可重建。
- 任务包暂时降级，但不丢事实。

失败表现：

- 删除索引导致记忆丢失。
- 审计不可查。

### 23.11 硬验收标准

记忆层至少要通过这些检查：

- 正式记忆有来源。
- 正式记忆变更有审计。
- 冲突不自动消失。
- 候选不冒充正式记忆。
- 派生索引不冒充事实。
- 子智能体只能读任务包。
- 权限撤回影响未来召回。
- 旧版本保留。
- 任务包能解释入选和排除原因。
- 后台维护不能自动改正式记忆。

## 24. 知识库和记忆层边界

状态：已确认根定义。

本节跳出现有对象设计，重新定义知识库和记忆层。

### 24.1 知识库定义

知识库是资料工作区。

它放的是人和 agent 可以阅读、整理、编辑的材料。

包括：

- 笔记。
- 项目资料。
- 研究记录。
- 设计文档。
- PDF、图片、附件。
- 双链。
- 标签。
- 属性。
- Canvas。
- Bases 表格视图。
- agent 整理出来的草稿。

关键点：

- 知识库可以被编辑。
- 知识库可以很自由。
- 知识库不自动改变 agent 的行为。
- 知识库里的话，不等于系统承诺。

一句话：

- 知识库是材料和思考空间。

### 24.2 记忆层定义

记忆层是系统行为依据。

它放的是已经被确认、会影响 agent 怎么做事的长期事实。

包括：

- 用户偏好。
- 全局产品方向。
- 项目长期规则。
- 已确认项目状态。
- 会话总结中被确认的长期事实。
- 成熟模式。
- 禁止事项。
- 会进入任务包的上下文。

关键点：

- 记忆必须有来源。
- 记忆必须有状态。
- 记忆必须有版本。
- 记忆必须有审计。
- 记忆会影响 agent 行为。

一句话：

- 记忆层是会改变系统行为的确认事实。

### 24.3 边界原则

边界不按文件格式分。

边界按行为后果分。

同一段 Markdown：

- 放在知识库里，是资料。
- 被确认进记忆层，会影响任务包和 agent 行为。
- 被做成索引，只是帮助搜索。
- 被放进审计，是记录发生过什么。

核心规则：

- 知识库负责存材料。
- 记忆层负责决定哪些材料变成系统依据。
- 索引负责帮用户和 agent 找材料。
- 审计负责记录发生过什么。

### 24.4 Obsidian-like 能力归属

工作台可以内置 Obsidian-compatible 知识工作区。

这些能力属于知识库核心：

- 本地 vault。
- Markdown 文件。
- 双链。
- 反向链接。
- Properties。
- Canvas。
- Bases。
- 全文搜索。
- 图谱。
- CLI 或自动化入口。
- 导入或挂载 Obsidian vault。

规则：

- Obsidian-like 能力不属于记忆层核心。
- 记忆层站在知识库之上。
- 记忆层从知识库中接收候选，但不自动采纳。
- 知识库编辑不能绕过记忆层状态机。

### 24.5 从知识库到记忆

流程：

1. 用户或 agent 在知识库中写材料。
2. 系统或项目主管发现其中可能有长期事实。
3. 生成 `MemoryCandidate`。
4. 用户或项目主管确认。
5. 写入正式记忆。
6. 后续任务包可以引用这条正式记忆。

例子：

- 知识库笔记写着：这个项目以后应该用插件化架构。
- 这只是资料。
- 用户确认后，才生成项目记忆：项目架构方向采用插件化架构。
- 这条项目记忆进入任务包后，才影响子智能体做事。

### 24.6 硬规则

- 知识库内容不自动变成记忆。
- Obsidian CLI 或其他自动化入口可以改知识库草稿，但不能直接改正式记忆。
- 知识库里的结论不会自动进入任务包。
- 从知识库生成的摘要先进入候选记忆。
- Canvas、Graph、Bases 是知识组织视图，不是正式记忆。
- 记忆详情可以反向链接知识库来源。
- 记忆生效必须走确认、状态机、版本和审计。

### 24.7 仍需研究

仍需单独研究：

- 是否直接嵌入 Obsidian。
- 是否只兼容 Obsidian vault。
- 是否启动或控制 Obsidian app。
- Obsidian CLI 如何接入工作台权限和审计。
- 插件生态是否允许接入。
- Dataview、Bases、Canvas 的具体兼容策略。
- 知识库文档级权限如何落到 vault 文件、附件和索引上。
