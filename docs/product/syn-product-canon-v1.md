本文只定义长期产品方向，不表示当前代码已经实现，也不授权真实执行、数据迁移、外部连接、提交、合并或发布。

## 1. 一句话定义

Syn 是只服务当前用户的个人长期人工智能工作平台。

它把个人事务、持续项目、知识、记忆、技能、智能体、工具和外部软件组织成一套能持续理解用户、推进工作、回到事实来源并不断积累能力的系统，让一个人逐步拥有接近一个可靠小团队的工作能力。

Syn 不是 Codex 外壳，也不是单纯聊天软件、项目管理器、知识软件或开发流程工具。

## 2. 产品首先服务谁

产品中心是用户本人，不是模型、智能体、流程或项目。

Syn 要长期帮助用户管理：

- 自己是谁、稳定偏好和长期目标；
- 最近做过什么、正在做什么、还有什么没有闭环；
- 个人事务、外部承诺、日程、资料和决定；
- 长期项目的目标、事实、方案、过程、风险和成果；
- 可以复用的知识、技能、工具和做事方法；
- 不同智能体和软件之间的协作关系。

用户不需要为了适应系统，先把生活和工作改造成一套复杂流程。系统应尽量从自然对话和真实事件中理解需要，只有在确实需要持续管理、授权或执行时，才建立正式对象。

## 3. 用户与智能体的基本关系

大原则是：**智能体管事，用户管决定。**

智能体可以在既有范围内整理、分析、搜索、提醒、提出方案、执行已批准工作、验证和汇报。以下事项仍由用户决定，或必须遵守用户已经明确批准的规则：

- 最终要做什么；
- 哪个结果算完成；
- 是否改变项目目标；
- 是否扩大权限；
- 是否发生有明显后果的外部动作；
- 是否把高影响内容变成长期规则、记忆或技能。

治理强度应和后果相称。低风险、可撤销的内部整理可以轻量自动进行；权限扩大、外部动作和难恢复变更需要清楚确认。内部实现可以严谨，但不应把复杂手续全部推给用户。

长期目标不是让用户逐次批准每个工具调用，而是让用户保留公司目的、资源配置、风险边界、权限根和高影响例外等最高层决定。反复出现、边界稳定的低风险判断可以由用户签署为可撤销政策，让 Syn 在政策、预算和验收范围内自行处理；政策本身的扩大、治理根变化和不可逆重大承诺仍由用户决定。

用户在 Syn 界面里明确编辑、纠正、确认或撤销内容，是正式的用户输入，不是“前端临时状态”。系统应把这项动作提交给真正拥有该对象的来源，保留必要的版本与审计，并让后续角色读到新结果。前端缓存不能自称事实来源，智能体也不能静默覆盖用户刚做的修改；出现并发或来源冲突时要让用户看见并处理。

## 4. 长期存在的人工智能组织

Syn 里存在稳定角色，也可以按任务创建临时智能体（Agent）。

### 4.1 顶层角色

- **秘书**：看住与用户有关的未闭环事项，负责收集、整理、提醒、日报、长期变化和交接建议。秘书不是项目执行裁判，也不替用户决定。
- **全局主管**：处理跨项目优先级、边界、冲突、风险和独立复核。它提供自己的判断，但意见本身不自动改变项目事实。

### 4.2 项目角色

- **项目主管**：常驻一个明确项目，理解项目长期上下文，与用户协商方案，组织执行、回收结果、验证并形成项目内事实。
- **稳定专业成员**：在真实工作反复需要时建立，拥有稳定身份、职责、记忆、知识范围和权限说明。
- **临时智能体**：为某个任务按需创建，获得最小必要上下文，完成后回交结果并明确退场；它可被搜索和审计，但不会自动变成常驻成员。

角色身份不等于模型、服务提供方、线程编号或某个正在运行的进程。角色可以更换当前使用的模型或底层智能体，身份、职责、记忆、知识范围和权限仍由 Syn 自己持有。模型变化不自动带来权限变化。

组织按真实负载和失败模式扩展，不预先摆满没有实际工作的职位。

重大、方向性或高不确定问题可以按需调用多个咨询角色，从不同模型或不同方法独立形成意见，再把共识、分歧和依据并排交给用户判断。咨询意见不会自动成为用户决定、项目事实或执行授权；日常小事也不默认启动多人会诊。咨询角色是否成为稳定成员，仍按真实复用频率和工作负载决定。

## 5. 自然对话是主要入口

用户应当可以直接说出需要，而不是先填写一堆表格。

通常流程是：

1. 用户与当前明确角色自然对话；
2. 角色读取当前范围内必要的事实、知识、记忆和技能；
3. 条件足够时直接回答或提出方案；
4. 缺少真正关键的信息时再询问；
5. 需要持续跟踪、多人协作或有后果的执行时，再建立任务、工作流、授权或交接；
6. 结果回到真正的事实来源。

普通聊天不会自动创建项目、任务、工作流、日程、承诺或批准。系统也不会通过猜项目、静默换角色或复用错误线程来扩大上下文和权限。

关闭并重新打开桌面应用、底层智能体进程变化或模型更换后，同一角色的工作脉络仍应可以恢复。

## 6. 个人范围、全局范围和项目范围

不是所有事情都必须变成项目。

- **个人范围**承载个人事实、偏好、资料、日程、承诺、收件、轻量事项和秘书工作。
- **全局范围**承载跨项目判断、全局状态和独立复核。
- **项目范围**承载复杂、持续、需要长期上下文、权限和执行治理的工作。

用户明确要求处理某个外部项目或其他目录时，可以把它明确纳入本次工作范围。系统应说明目标、路径、事实归属和允许动作，而不是永久禁止跨项目，也不是默认随意跨项目。

同一种正式对象只有一个事实所有者和一条受控写入面。秘书、主管、智能体、前端和连接器都通过这条写入面提交动作，不各自维护一份可反向覆盖的副本。用户明确跨项目工作时，写入仍回到目标项目或外部来源的所有者。

个人事项只有在用户明确需要长期项目化时才升级为项目。升级保留来源，不复制成两份互相竞争的事实。

## 7. 知识基础设施

知识库不是孤立页面，而是所有智能体共同依赖的基础设施层。

每个稳定角色、临时智能体、执行者和审查者，在会话开始、任务派发、显式交接或主动查询时，都应根据角色、作用域、当前对象和权限，快速获得当前工作需要的：

- 资料和文档；
- 决策及其是否仍然有效；
- 研究、设计、代码和历史成果；
- 来源引用和新鲜度；
- 可用技能、适用条件和使用说明。

用户通常不负责手工搬运这些上下文。系统负责检索、筛选、装配和引用，资料不足、过期、冲突或索引失效时必须如实说明。

所有智能体接入知识能力，不等于所有智能体默认读取全部资料。实际内容仍按个人、全局、项目、任务和权限过滤。检索到的材料可以帮助理解，但不会仅因为被检索到就自动成为正式事实、长期记忆、系统命令或权限。

完整边界见 [`knowledge-infrastructure-canon-v1.md`](knowledge-infrastructure-canon-v1.md)。

## 8. 记忆和个人模型

记忆是 Syn 的核心基础设施，不是附属搜索功能。

稳定角色需要在适用权限内知道：

- 用户是谁；
- 用户最近做了什么；
- 用户长期做过什么；
- 当前有哪些未完成事项；
- 用户明确确认过哪些偏好、目标和决定；
- 哪些内容只是系统观察或模型推断。

记忆必须区分用户明确事实、系统观察、模型推断、候选记忆和正式长期记忆。重要记忆要有来源、作用域、版本、时效、敏感性和纠正历史。

个人模型包含可纠正的“用户知识深度”：用户明确说明自己熟悉或不熟悉某个领域时，记录为有来源的个人事实；系统根据长期行为形成的熟悉度判断，只能作为带证据、置信度和时效的模型推断。它可以帮助调整解释深度、资料选择和沟通方式，但不能把一次对话固化成长期能力结论，用户可以随时纠正或否认。

系统可以按明确政策主动捕获低风险观察、整理候选和生成日报，但不能把每句话都当长期记忆，也不能把模型总结直接伪装成用户事实。用户可以查看、纠正、否认、冻结或废弃记忆。

记忆决定哪些长期内容会影响未来行为；知识负责提供可阅读和可引用的材料。两者协作但不合并。

## 9. 技能和能力积累

Syn 应从真实工作中逐渐发现：

- 哪些步骤经常重复；
- 哪些方法已经证明有效；
- 哪些提示、检查、工具组合值得复用；
- 哪些成熟做法可以变成技能候选或确定性脚本。

知识基础设施帮助智能体发现和理解技能，技能治理负责版本、适用范围、验证和启用权限。被发现不等于已获准使用；一次成功也不自动升级成永久规则。

第一版技能治理采用“先验证、再由用户或既有明确政策启用、可以停用和回滚”的方式。未来是否允许少数低风险技能按证据自动启用，留到对应政策任务包决定，不阻挡首版技能能力。

能用清楚规则表达、可以可靠测试的重复工作，优先沉淀为确定性工具或脚本；需要理解和判断的部分继续由智能体完成。

Syn 还要逐步具备受治理的自升级能力：从真实工作、失败、成本和外部版本变化中生成 Skill、Profile、插件、Provider 适配或代码候选，在隔离环境中验证，经独立复核、有限灰度、签名晋升和可恢复回滚后使用。候选生成不等于启用，执行者不能修改自己的权限根、审计、预算、验收器或发布信任链后再自行批准。

## 10. 完整工作闭环

Syn 要完成的不只是聊天，也不只是执行，而是整条闭环：

```text
事情出现
→ 当前范围的责任角色理解
→ 获取必要事实、知识、记忆和技能
→ 提出建议或方案
→ 用户决定或既有规则批准
→ 执行与验证
→ 结果回到原事实来源
→ 形成可追溯的知识、记忆或技能候选
→ 秘书继续看住尚未闭环的部分
```

没有新事件时，智能体和模型不持续空转。用户事件、定时事件、外部变化、项目变化或系统异常才触发对应工作。

## 11. 知识工作区

Syn 自己提供原生知识工作区，支持用户长期浏览、搜索、编辑和组织资料。Markdown 文档格式、双向链接、标签、属性、关系图、画布和附件等能力服务于真实知识工作。

知识工作区是知识基础设施的人类工作面，不是知识基础设施的全部。智能体不需要先打开这个页面，才能通过受控知识服务检索资料。

知识工作区可以展示和索引可回源的项目状态摘要，让用户与智能体快速看到目标、现状、下一步和未闭环事项。摘要必须由项目事实和可重建的项目摘要投影生成，不能在知识库中再手工维护一份互相竞争的“当前状态”；记忆层只补充长期决定、历史脉络和稳定背景。

Obsidian 可以作为交互参考和用户明确选择的互操作对象，但不是 Syn 核心能力的必需依赖。文件和外部系统继续保有自己的事实来源。

## 12. 外部智能体、模型、工具和软件

当前可以先真实接通 Codex，但产品不能绑定 Codex。

未来可以接入其他编程智能体、普通模型、本地模型、专业模型、浏览器、开发工具、知识软件、企业系统和其他外部服务。

Syn 统一管理的是角色、作用域、权限、上下文、调用、结果、回执和审计，不要求所有外部能力使用相同接口，也不把外部服务内部编号当作 Syn 自己的身份。

Syn 默认拥有自己的治理核心和 vendor-neutral Agent Runtime 合同，不把 DeepSeek Harness、Codex 或任何单一外部 Harness 当系统根。外部 Runtime 可以作为可替换适配器接入；替换、停用或销毁 Runtime 后，角色身份、正式事实、长期记忆、未完成运营动作和用户控制权必须仍由 Syn 恢复。

外部软件继续拥有自己的事实。Syn 通过适配器受控读取、索引、同步或操作，并把结果写回原来源，不把摘要复制成第二套真源。读取授权不自动包含写入授权，凭据不进入普通聊天、记忆或事件正文。

外部系统支持模型上下文协议（MCP）时，可以优先使用它作为标准接入方式；不支持时仍可使用其他受控适配器。接入协议负责传输能力，不拥有 Syn 的角色身份、知识真源、记忆、作用域或权限。

## 13. 长期业务版图

Syn 的长期能力需要服务至少五类实际工作：

- 游戏开发；
- 智能体开发；
- 企业系统；
- 个人工作；
- 股票市场。

这表示底座不能只按软件开发任务设计，但不表示现在立即连接企业生产、个人真实账号或实盘交易。每类真实外部能力仍按实际后果单独进入开发和验收。

## 14. 用户看到什么

用户日常主要看到：

- 当前在哪个范围、与哪个角色协作；
- 现在最需要知道、决定或继续的事情；
- 角色准备做什么，为什么需要确认；
- 工作进行到哪里，有什么阻塞；
- 最终做成了什么，结果在哪里；
- 本轮引用了哪些关键资料和技能；
- 哪些事情仍未完成。

事实归属、权限、事务、审计和上下文装配等复杂度由系统内部承担。专业用户仍可以进入知识、记忆、智能体、工作流、连接器和审计等工作面查看细节。

## 15. 明确反目标

Syn 不会被设计成：

- 某一家模型或编程智能体的外壳；
- 只有聊天、没有事实回写和工作闭环的应用；
- 强迫所有个人事务建立项目的系统；
- 自动猜项目、静默切换角色和权限的万能聊天框；
- 把每句话自动变成任务或长期记忆的系统；
- 用一个通用任务、知识或智能体对象吞掉所有业务差异的系统；
- 把所有外部数据复制进中央数据库的系统；
- 为展示而预建一整套没有真实工作的虚拟组织；
- 用复杂开发治理流程增加用户日常操作负担的产品；
- 因为模型更强就自动授予更多权限的系统。

## 16. 判断产品是否成功

长期成功不是“建了多少表、页面和角色”，而是：

- 用户遗漏更少；
- 常驻角色重启后仍真正了解用户和当前工作；
- 开始一项工作时更少手工搬运资料；
- 复杂工作能推进、验证、回源和闭环；
- 用户能看懂系统为什么这样建议或行动；
- 解释深度能根据用户可纠正的知识深度调整，而不是反复讲得过浅或过深；
- 重大问题需要时能获得彼此独立的多视角意见，并把最终决定留给用户；
- 记忆、知识和技能越用越有价值，同时保持可纠正；
- 外部服务可以替换，而角色身份和工作脉络不丢；
- 系统失败后可以恢复，不伪装成已经完成。
- 系统可以提出、验证、灰度和撤回自己的改进，同时不能自行降低权限、预算、审计和验收标准。
